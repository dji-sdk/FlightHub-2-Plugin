# 日志与链路追踪

排障时先确定身份再看错误：`pluginId`、宿主、接口名 / 流程名、业务 ID、幂等键、时间范围——这些要能拼出唯一的检索条件。

## 前端：诊断面板与 `ctx.logger`

本地调试页面的诊断面板按插件、宿主、阶段（`install` / `activate` / `runtime` / `view` / `dispose`）记录事件，含错误码、消息和资源快照。

插件里写日志用 `ctx.logger`（四个级别：debug / info / warn / error），可以带结构化字段：

```ts
ctx.logger.info('打开示例面板', {
  clickCount,
  hostId: ctx.host.id,
})
```

注意：

- 本地调试页面会把 `debug` 及以上级别写入诊断面板，并旁路到浏览器控制台；真实宿主是否输出控制台由平台配置决定。不要依赖 `console.log` 作为唯一证据。
- 结构化字段的值必须是可序列化数据。

推荐筛选顺序：先按 `pluginId` 过滤 → 按 `hostId` 区分宿主 → 按阶段顺序看 → 展开 `detail` 核对业务标识 → 卸载后确认 `resourceSnapshot` 全零。

## HTTP 链路：请求 ID 与幂等键

调用插件接口时可以带两个追踪头：

```http
X-Request-Id: local-debug-001
Idempotency-Key: issue-create-001
```

它们会注入到脚本侧：

- `ctx.requestId`：请求追踪 ID。
- `ctx.idempotencyKey`：幂等键，并参与 `ctx.stableId(scope)` 派生稳定 ID。

后端访问日志默认只输出 `pluginId`、接口名（`handler`）和结果类别。需要在脚本里关联追踪信息时，用日志显式带上：

```ts
// handlers/task/create.ts
export function create(input: RecordInput, ctx: HandlerCtx) {
  log.info("开始创建业务记录", {
    request_id: ctx.requestId,
    idempotency_key: ctx.idempotencyKey
  });
  return { accepted: true };
}
```

后端脚本日志由平台自动补充 `PluginID`、`ScriptKey`、`IdempotencyKey`。限额：每次调用最多 32 条日志，每条最多 8 个字段，message 和字段值各最多 512 字节；对象/数组不会原样记录。

## 流程编排追踪

流程实例的 ID 规律：

```text
workflowId = <流程名>-<业务ID>
step id    = 流程 JSON 里 steps[].id
```

排查流程问题时优先观察：

- 当前是否在等待人工信号（`awaitingSignal`）。
- 失败步骤的重试次数和最后错误：是可重试失败还是契约错误。
- 步骤终态 `steps.<id>.$state`：`succeeded / failed / skipped / timedOut / interrupted`。
- 日志出现 `step input unresolved`：通常是流程 JSON 的 `from` 路径拼错了。

先使用已部署环境的流程状态接口，按流程名与业务 ID 查询当前状态。完整执行历史和服务日志由部署方提供；需要深入排查时，带上插件版本、业务 ID、流程 ID、失败步骤和时间范围联系技术支持或部署方，不要求获取运行时源码或自行配置日志服务。

## 设备命令的 traceId

部分设备能力的受理结果会带 `traceId`。它只说明命令被平台接受，不代表设备已完成动作。要等权威遥测或任务状态回来后，才能记录最终结果（完成 / 失败 / 未知）。

本地调试页面生成的 `mock-trace-*` 值只能关联模拟调用，不能当作真实设备执行证据。

## 敏感信息

平台会按字段名自动遮蔽 `token`、`password`、`secret`、`authorization`、`cookie` 等值，但自由文本无法可靠脱敏。不要记录：

- Token、Cookie、密码、Authorization 头。
- 带签名的预览/下载 URL。
- 完整的 HTTP 请求/响应原文和连接配置。
- 会进入流程历史的凭据或大对象。

可以记录 `event_key`、`object_key`、`session_id`、`dock_sn` 这类业务标识。

## 一次排障应保留什么

- [ ] 环境、时间范围、插件版本。
- [ ] `pluginId`、宿主 ID。
- [ ] 接口名 / 流程名和业务 ID。
- [ ] `X-Request-Id`、幂等键或设备 `traceId`（注明来源）。
- [ ] HTTP 状态与业务 `code`。
- [ ] 流程 ID、失败步骤与重试次数。
- [ ] 诊断面板资源快照是否归零。
- [ ] 已删除所有凭据和敏感正文。
