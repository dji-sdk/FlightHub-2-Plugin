# 模拟数据与测试数据

模拟数据的目标是稳定重现契约和错误分支，不是制造"全绿"的假结果。创建向导选择「0=完整 Capability」生成的能力工程自带一个 `mock/` 目录，本地调试时后端运行时会读取它。

## 模拟数据目录结构

```text
mock/
├── fixtures/
│   └── default.json          # 数据初始内容：{ "entities": { ... } }
├── events/
│   └── example-created.json  # 事件样例，可手动投递给事件处理脚本
├── connections.json          # 外部连接的本地模拟值
└── providers/                # 本地模拟能力提供方的配置
```

## 初始测试数据：`mock/fixtures/default.json`

顶层固定是 `entities`，键是实体名，值是记录数组；字段和值以生成工程的测试数据与 `schema.sql` 为准。下面仅说明结构：

```json
{
  "entities": {
    "example_record": [
      { "id": "demo-001", "title": "机场入口发现占道物", "processed": false }
    ]
  }
}
```

约束：

- `entities` 的键与字段必须匹配 `schema.sql` 派生的实体声明（构建产物 `backend/<pluginId>/dist/plugin.json` 中的 `entities[]`）；不要在源清单手写 `entities`。不匹配的数据不能作为有效测试数据。
- 需要稳定断言时，在测试数据里明写 `id`；不写时运行时会生成随机 `id`。
- 本地快照会补 `tenant_id`、`created_at`、`updated_at` 字段；这些是模拟数据快照的存储形状，不是正式脚本字段契约。JS `store` 的平台时间字段为 `createdAt` / `updatedAt`，业务响应数据结构可以另行映射为 `created_at`。

前置条件：生成工程依赖已安装，含后端的 `dev` 已启动且未使用 `--frontend-only`；`FH2_LOCAL_ORIGIN` 已设为当前回环监听地址（默认 `http://127.0.0.1:5175`，以输出为准）。以下三个模拟数据辅助端点只受本地调试页面同源门禁约束，当前不检查插件令牌；不要把这一点推广到 `/plugin-api/plugin/invoke` 或任何真实环境接口。不要发往真实环境或暴露外网。

```bash
# 看当前数据快照
curl -sS "${FH2_LOCAL_ORIGIN:?}/plugin-api/mock/backend/state" \
  -H "Origin: ${FH2_LOCAL_ORIGIN:?}"

# 清除本轮写入并恢复初始测试数据；不是保证得到空表
curl -sS -X POST "${FH2_LOCAL_ORIGIN:?}/plugin-api/mock/backend/reset" \
  -H "Origin: ${FH2_LOCAL_ORIGIN:?}"
```

## 事件测试数据：`mock/events/*.json`

每个 JSON 文件是一条本地事件样例，核心字段是 `id`、`type`、`data`。`example.created` 是模板本地联调类型，不是真实平台消息：

```json
{
  "id": "example-created-001",
  "type": "example.created",
  "data": { "file_id": "photo-001", "workspace_id": "mock-project" }
}
```

具体字段以模板生成的样例为准。前置条件同上，且对应的事件订阅与测试数据文件已存在；在实际能力工程目录执行：

```bash
curl -sS -X POST "${FH2_LOCAL_ORIGIN:?}/plugin-api/mock/backend/event" \
  -H "Origin: ${FH2_LOCAL_ORIGIN:?}" \
  -H 'Content-Type: application/json' \
  --data-binary @mock/events/example-created.json
```

本地手动投递不是消息队列的"至少一次"、并发或重试实现。检查业务幂等时，既重复同一个 `id`，也使用新消息 `id` 配相同业务键，确认不会产生重复副作用，避免只命中本地缓存。真实媒体消息可能采用不同的顶层字段形状，不能把本地包装当作生产契约，见[已知限制](./30.backend-debugging.md#已知限制)。

## 连接与能力模拟数据

- `mock/connections.json`：为清单里声明的外部连接（`connections[]`）提供本地调试用的连接值。生产的真实连接值在部署配置里，不要把真实密码写进 `mock/` 目录。
- `mock/providers/`：生成工程支持的本地模拟能力提供方配置；只使用该模板已实现的配置形状，它不会启动真实流程、队列或设备服务。

## 测试数据设计规则

- 固定业务主键和时间；只有专门测试时间/随机性时才引入变化。
- 成功、业务冲突、契约错误、超时分别建不同的场景文件。
- 模拟数据返回的字段必须与真实接口一致，不要为了让界面通过而少校验。
- 能力空壳时明确返回 `skipped` 或报错，不能返回假的文件 ID、假轨迹。
- 测试用例名称写清"模拟数据"或"测试数据"，报告里不要写成"真机通过"。
- 测试数据不放真实 Token、密码、Cookie 或现场敏感数据。

## 验证清单

- [ ] `reset` 后恢复预期的测试数据业务字段；平台补充字段按当前模拟数据快照检查，不误认作空表。
- [ ] 同一事件 `id` 重复投递没有重复副作用。
- [ ] 核对未知实体/字段的报错，以及未命中事件的处理结果；本地模拟器可能宽松接受或跳过的场景，在部署环境验证正式拒绝行为。
- [ ] 插件卸载后计时器、订阅等资源释放。
