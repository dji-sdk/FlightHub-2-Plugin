# 前端本地调试

本地调试页面是插件开发的"验证器"：多宿主模式验证四个宿主（`cockpit` / `plan` / `message` / `project`）的装载协议，驾驶舱模式提供接近真实驾驶舱的布局。本文适用 Toolchain / SDK `1.0.0`，用于在本地把扩展点和界面调通。

## 启动

前置条件：生成工程依赖已安装。以下命令在实际插件或能力工程目录执行；从工作区根执行时加 `--root "<插件或能力工程目录>"`，目录以生成工程结构为准。

```bash
pnpm exec fh2-plugin dev          # 多宿主模式，默认端口 5175
pnpm exec fh2-plugin dev cockpit  # 驾驶舱模式，默认端口 5176
```

需要固定端口或停止监听时：

```bash
pnpm exec fh2-plugin dev --port 5180 --no-watch
```

## 三个调试面板

### 插件面板

"插件"抽屉显示插件 ID、版本、健康状态和配置。建议依次检查：

1. 插件卡是否出现，ID 是否与插件清单（`fh2-plugin.json`）一致。
2. 目标宿主是否 `Running`；部分宿主失败时显示 `Degraded`。
3. 禁用插件后贡献是否消失；重新启用后是否只出现一份。
4. 修改配置并"保存并重载"后，运行时是否重建（而不是旧实例继续工作）。

> 清单里写 `trusted` / `trustLevel` / `sandbox` 会被工具链直接拒绝。运行方式不是作者可声明的概念。

### 场景与模拟网络

多宿主模式提供模拟 WebSocket 和平台事件按钮；全栈工程还提供触发事件处理脚本的场景按钮；驾驶舱模式在顶栏 `DEV` 菜单里有同一组工具。

- "推送 WS"按钮：验证 `ctx.ws.onBizCode()` 能收到消息。
- "分发事件"按钮：验证 `ctx.events.on()` 能收到平台事件。
- 全栈工程的事件场景按钮会真正执行本地事件处理脚本。

这些按钮只改变本地调试页面的模拟状态，不会触发真实业务或真实设备。

### 诊断面板

可按插件、宿主、阶段筛选。阶段有 `install`、`activate`、`runtime`、`view`、`dispose`。重点看：

- `activate` 阶段是否成功：目标宿主已激活。
- `effectiveRuntime`：最终跑在 `isolated-realm` 还是 `isolated-iframe`（隔离环境，见[安全与隔离](../10.concepts/50.security-and-isolation.md)）。
- `resourceSnapshot`：卸载后各项资源计数是否全部为 0。

`ctx.logger` 的日志会进入诊断面板；开发模式下 `debug` 及以上级别同时输出到浏览器控制台。

## 调试一个扩展点

先核对"清单静态声明"，再核对"运行时贡献"。以项目侧边栏按钮为例。

清单声明（`fh2-plugin.json`）：

```json
{
  "id": "hello-project",
  "point": "project.sidebar-actions",
  "path": "/hello-project"
}
```

入口运行时提交实现（`plugin.ts`）：

```ts
await ctx.extensions.contribute('hello-project', {
  icon: 'hello-idle',
  label: '项目入口',
  disabled: false,
  render: () => helloProjectView.get(ctx),
})
```

按钮不出现时按这个顺序查：

1. `pnpm run generate` 后 `src/generated/plugin-types.ts` 是否更新。
2. `pnpm run validate` 是否通过。
3. 入口是否按 `ctx.host.id` 分支，只在目标宿主激活。
4. `contribute()` 的 ID 是否已在清单声明，扩展点是否属于当前宿主。
5. 宿主是否真的消费这个扩展点（11 个扩展点见[扩展点目录](../70.api-reference/10.frontend/30.extension-point-catalog.md)）。

## 调试插件界面与通信通道

插件入口持有跨开关、重挂仍有意义的业务状态；插件界面只持有临时呈现状态。两者之间通过通信通道（`state` + `methods`）交互。推荐的挂载写法：

```ts
// src/views/hello-project.ts
export default defineView({
  mount (ctx) {
    const client = helloProjectView.client(ctx.port)
    const app = createApp(ProjectView, {
      client,
      styleTarget: ctx.styleTarget,
      overlayElement: ctx.overlayElement,
    })
    app.mount(ctx.mountElement)
    return {
      dispose: () => {
        app.unmount()
        client.dispose()
      },
    }
  },
})
```

调试弹窗、下拉框时：第三方组件的挂载目标用 `ctx.overlayElement`，样式挂载目标用 `ctx.styleTarget`。内容"在 DOM 里但看不见"时，优先检查这两项和 ShadowRoot 内的样式、裁剪，而不是反复调 `render()`。

## 转到真实环境

本地调试页面验证通过后，用预览命令在获授权的真实司空里复验。当前只支持 HTTP 目标；地址须换成你已登录、可访问的完整项目页 URL，保留组织/项目路径、查询参数和 `#` 后的路由，不只填写 Origin。目标仅支持 HTTPS 时停止此路线，不擅自降级协议：

```bash
pnpm exec fh2-plugin preview --root "<前端插件或能力工程目录>" --fh2-url "http://fh2.example.test/project?org=demo#/team" --no-open
```

启用本次 PAC，在同一 Origin 登录并进入项目，手填终端打印的资源根，由宿主校验权限、勾选临时运行同意后确认重载。ready 只说明本地就绪；预览只替换前端，后端仍用目标环境已安装版本。逐步操作、截图和结束时的清理见[真实环境预览](./10.local-development.md#真实环境预览)。

## 验证清单

- [ ] 只有声明了对应扩展点的宿主出现贡献。
- [ ] 插件界面关闭、插件禁用、宿主卸载三条路径都能释放订阅和界面资源。
- [ ] 构建失败不会替换上一份可用产物；修复后能重新加载。
- [ ] 插件界面没有依赖宿主 DOM 或自行发起网络请求。
- [ ] 最终在真实宿主验证过权限、路由、网关和设备能力。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 插件卡不存在 | `dist/fh2-plugin.json` 不存在，或 `--plugins-dir` 指错。先 `validate` + `build` |
| 卡片在但按钮没有 | 宿主 ID、扩展点 ID 不匹配，或 `activate` 抛错。看诊断面板的 `activate` 阶段 |
| 插件界面空白 | 界面入口路径错、`handle()` 未注册或资源加载被阻止。看 `view` 阶段诊断和控制台 |
| 改代码后还是旧页面 | 构建失败，保留了旧产物。看终端最新构建输出，先修第一条报错 |
| 关闭后仍收到消息 | 订阅 / 计时器没走 `ctx` 提供的受跟踪 API。卸载后检查资源快照是否归零 |
| 本地调试页面正常、真实环境不行 | 模拟数据与真实权限、设备状态、网络不等价。转到真实环境预览复验 |
