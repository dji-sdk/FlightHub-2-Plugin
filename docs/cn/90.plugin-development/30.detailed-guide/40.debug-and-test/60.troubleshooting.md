# 常见问题排查

按"构建产物 → 安装 → 宿主激活 → 界面 → 网关 → 后端运行时 → 外部依赖"的顺序排查。不要先在业务代码里加重试掩盖根因。

## 安装与版本

先区分插件化开发者工具和生成的插件工程。开发者工具需要 Node.js `>=20.19`（推荐 22 LTS 及以上），根目录使用 Corepack 准备的 pnpm 10（默认 `10.15.0`）；插件工程沿用自己的包管理器配置。不要为通过安装而改写开发者工具的锁文件、依赖版本或批准全部安装脚本。

| 现象 | 原因与处理 |
| --- | --- |
| `ERR_PNPM_UNSUPPORTED_ENGINE` | 当前 pnpm 不在开发者工具支持范围；在根目录执行 `corepack enable`（或改用 `corepack pnpm`）后重新执行 |
| `ERR_PNPM_LOCKFILE_BREAKING_CHANGE` | 常见于旧全局 pnpm 抢先被 PATH 解析；使用 Corepack 或显式版本命令，不删除锁文件 |
| pnpm 11 提示 `allowBuilds`、安装脚本未运行 | `allowBuilds` 是 pnpm 运行时的安装脚本策略/审批配置，不是 FH2 模板字段。开发者工具不支持 pnpm 11；先切回固定 pnpm，别把提示当成模板缺字段或直接批准所有包 |
| `corepack: command not found` | 按[环境准备](../20.development/40.hands-on/10.environment-preparation.md)安装 Corepack；无全局写权限时可用版本化 `npx` 入口 |
| `fh2-plugin --version` 报未知命令 | 用 `fh2-plugin create --version`；根入口没有该参数 |
| 全局 CLI 与工程 CLI 版本不同 | 对比 `fh2-plugin create --version` 和工程内 `pnpm exec fh2-plugin create --version`，核对发行身份与本地依赖；保留其它安装，不盲目覆盖注册 |

在开发者工具根目录（含 `pnpm-lock.yaml`、`public-distribution.json`）自救，不先重装全部工具：

```bash
node --version
pnpm --version
corepack pnpm --version
corepack pnpm install --frozen-lockfile
corepack pnpm link:toolchain
fh2-plugin create --version
```

`corepack pnpm --version` 应为工具固定的 `10.15.0`。如果 Corepack 不可用，可用 `npx -y pnpm@10.15.0` 替换 `corepack pnpm` 执行同样步骤；所需网络和下载仍须符合本机策略。注册权限/冲突按环境准备处理，不改全局配置来覆盖未知程序。pnpm 11 的批准操作可能已修改工作区配置，先审查差异，保留他人改动，不自动删除。

## 前端

| 现象 | 原因与处理 |
| --- | --- |
| 本地调试页面没有插件卡 | `dist/fh2-plugin.json` 不存在，或 `--plugins-dir` 指错。先 `pnpm run validate && pnpm run build`，核对 `dev` 输出的产物目录 |
| 卡片一直 `Pending` | 插件没有在任何宿主成功激活。看诊断面板的 `activate` 阶段 |
| 状态 `Degraded` | 至少一个宿主成功、另一个失败。按 `hostId` 过滤诊断，别只看总状态 |
| 清单合法但按钮不显示 | 宿主 ID 分支、扩展点 ID 或宿主消费点不匹配。对照实际前端成员的 `src/generated/plugin-types.ts` |
| 插件界面空白 | 界面入口未生成、`handle()` 未注册、挂载目标错误。看 `view` 阶段诊断 |
| 弹窗/下拉跑到插件界面外面 | 组件库把浮层挂到了 `document.body`。把浮层目标设为 `ctx.overlayElement` |
| 改代码后还是旧页面 | 构建失败，dev 保留了上一份可用产物。先修终端里第一条报错 |
| 重挂后回调重复触发 | 计时器或订阅没释放。改用 `ctx.timers` 和 `dispose`；卸载后检查资源快照 |
| 插件界面里发请求失败 | 插件界面不持有 `ctx`，也不应自行发请求；改为通过通信通道让入口代码代取 |

在生成的 pnpm 工作区根执行已有自检脚本（以当前 `package.json` 为准）。能力模板有测试脚本，独立后端模板没有统一的 `test` 脚本，不能照抄执行不存在的脚本：

```bash
pnpm run generate
pnpm run validate
pnpm run test
pnpm run build
```

能力工程工作区通常没有根级 `tsc` 脚本。类型检查在实际插件目录运行其已有脚本；或从装有 TypeScript 的工作区执行 `pnpm exec tsc --noEmit -p "<插件目录>/tsconfig.json"`，不要假定所有模板都有同名脚本。

## 本地调试页面与真实环境预览

| 现象 | 原因与处理 |
| --- | --- |
| `5175` / `5176` 端口被占用 | 先确认占用者；换 `--port`，或仅停止自己启动的 dev 进程 |
| `--gateway-target` 启动失败 | 缺 `FH2_DEV_LOGIN_TOKEN` 环境变量，或目标地址不是合法源地址 |
| 行业工作区根 `dev` 返回参数错误 | 当前是含 `packages.json` 的工作区根；先核对 `package.json` 中已有的 `dev` / `dev:cockpit` 脚本再运行。旧工程缺少驾驶舱根脚本时，用 `fh2-plugin dev cockpit --root "<实际能力子目录>"`；成员目录的同名脚本只调试该插件 |
| 驾驶舱页仍有 project/message 宿主 | 这是正常路由拓扑，`cockpit` 不是单宿主开关；以「Host」面板实际状态判断卸载 |
| `preview` 拒绝 HTTPS 或旧证书参数 | 当前只支持 HTTP PAC；移除 `--local-protocol` / `--cert` / `--key` 和旧证书环境配置。不要降级目标协议或关闭 TLS 校验，HTTPS-only 目标联系部署方 |
| 预览页面没有调试面板 | 先启用当前 PAC、登录同一 HTTP Origin 并进入项目，再打开终端调试面板地址；目标构建须允许插件调试 |
| 本地来源校验失败 | 手填当前「插件来源URL」完整资源根；不要填入口 JS、单插件清单、PAC 或面板地址。看宿主清单/权限提示和代理日志 |
| ready 但本地代码没覆盖远端 | ready 只表示本地就绪。核对 ID、目标项目、面板校验、临时运行勾选及「确认并重载」后的实际加载结果 |
| 插件 ID 改后仍加载旧插件 | 停止并重启 preview，手填新会话来源并重新确认；旧会话不能继续复用 |
| 调试后目标环境打不开/临时插件还在 | 在面板点「停用并重载」，停止 preview 并关闭临时 PAC、恢复原代理；不只关闭浏览器页签 |

HTTP PAC、先登录、手填和宿主确认的完整步骤及截图位置见[真实环境预览](./10.local-development.md#真实环境预览)。

## Web IDE 与保存

先保留内存里未保存内容，再对照保存回执和磁盘；不要把「无待保存内容」视为所有预期文件都已保存。

| 现象 | 优先检查 |
| --- | --- |
| `serve --port 0` 被拒绝 | 不指定端口才会随机分配；显式端口须为 `1..65535`，打开本次终端地址 |
| 打开目录后进入启动中心 | 未识别到工程标志；当前启动中心用于创建新工程。已有工程先保留修改、停止 serve，再用正确 `--root` 重启；不在开发者工具根目录直接运行插件任务 |
| 检查器改了脚本但保存回执没有它 | 检查器脚本已纳入保存计划。若回执仍缺少该路径，先保留内容，核对 CLI/IDE 版本、保存范围与磁盘，不在未确认时关闭页面 |
| 顶部校验/打包或运行前保存报 404，新草稿未写入 | 通用「保存全部」仍有新建文件和 DAG 输入草稿的屏障限制。先用 DAG 保存按钮处理草稿/新文件并逐个核对，不带着漏项启动任务 |
| 新文件第一次保存后继续编辑 | 当前保存协调路径第一次成功后转为已存在文件，第二次正常走写入，不再按新建处理。若实际仍报 `FH2_IDE_ALREADY_EXISTS`，保留内容、核对 CLI/随包 IDE 版本及磁盘，不盲目覆盖 |
| 回执同时有已保存、失败和未执行 | 前序失败会停止后续写入；`FH2_IDE_SAVE_SKIPPED` 属于 `pending` 未执行，不是一次写入失败。已保存文件不回滚，逐项处理未保存内容 |
| 保存时出现 `FH2_FILE_CONFLICT` | 磁盘被外部修改；先比较内存与磁盘并处理冲突，再重试该范围 |
| 构建任务成功但产物标记 `stale` | 构建期间源码又变化；保存当前内容并重新构建，不交付旧快照 |

独立文件可以已保存，而关联文件仍未执行；这不是多文件事务。详见[Web IDE 保存边界](./12.web-ide.md#保存边界)。

## MCP 与知识

| 现象 | 优先检查 |
| --- | --- |
| GUI 客户端找不到 `fh2-plugin` | GUI 的 PATH 可能不同；用实际 Node 和开发者工具 `bin/fh2-plugin.mjs` 的绝对路径配置，不绕过 bin 直跑 `dist/cli.js` |
| MCP 提示忽略未知参数 | 调用按已定义字段继续执行，warning 只回显键名不回显值。不要把 `--check` 当成 `check`，更不能认为有 warning 就没有写盘 |
| 想只读检查类型却生成了文件 | `generate` 的只读字段是布尔 `check: true`；仅传未知 `"--check": true` 会按默认生成。先停后续写操作并审查差异 |
| `FH2_MCP_PATH_ESCAPE` | 工具路径越出 `--root` 或符号链接指向边界外；选正确根后重启。根限制不是账号权限或构建沙箱 |
| 知识包 import 成功但画布仍用快照 | import 只安装缓存，不改项目锁。用 `knowledge use <id> --root <工程目录>` 显式固定，再看 `knowledge status` 和「检查依据」 |
| `knowledge status` 无阻断但 checker 不可用 | 退出码不证明权威校验器存在；当前 `checkerAvailable` 为 `false`，本地快速预检不能作为可部署结论 |

配置、允许的只读工具和任务终态检查见[知识与 MCP](./16.mcp-and-knowledge.md)。

## 插件接口

| HTTP / 业务码 | 常见原因 | 处理 |
| --- | --- | --- |
| `400 / 40001` | JSON 非法，或请求体顶层多了未知字段 | 请求体只能有 `pluginId`、`handler`、`input` |
| `400 / 40006` | 插件 / 接口寻址失败、参数校验不过、缺幂等上下文 | 核对点分接口名和 `Idempotency-Key` |
| `200 / 20001` | `NOT_FOUND` / `DUPLICATE` / `CONFLICT` 等业务结果 | 展示业务反馈，不重试 |
| `503 / 50301` | 沙箱超时、下游暂时不可用 | 同一幂等键退避重试，并查服务端日志 |
| `401 / 40101` | 已部署网关的凭据缺失、失效或未获授权 | 按部署方提供的授权方式处理，不使用本地模拟器 Token |

接口名由文件路径派生：

```text
handlers/illegal-road/start-session.ts + export function startSession → illegal-road.start-session
```

接口名由文件路径加命名导出派生（`handlers/<域>/<动作>.ts` + `export function <动作>` → `<域>.<动作>`）；流程和事件脚本才在清单 `scripts[]`/`events[]` 里声明各自的 `entry`。

上表描述已部署网关数字码；当前本地网关也返回数字分类，但 HTTP 状态、多余字段校验可能不同，不能据此判断目标环境错误映射已通过。消息包装、排序与分页的差异见[已知限制](./30.backend-debugging.md#已知限制)。

## 流程编排

| 现象 | 优先检查 |
| --- | --- |
| 后端已装载但没有流程执行 | 确认目标插件版本、流程名与触发声明；请部署方确认运行时和事件投递就绪，本地 dev 不执行流程 |
| 发信号返回 40901 | 流程当前没在等这个信号。先查等待状态再发 |
| 发信号返回 40002 | 信号名写错。对照流程 JSON 的 `await.signal` |
| 同一业务 ID 无法重跑 | 流程 ID 按 `<流程名>-<业务ID>` 幂等，重复启动返回"已存在"。换新的测试业务 ID，不要删共享实例 |
| 流程停在某个步骤很久 | 看该步骤是 `wait_signal`（等人工）还是在轮询外部任务 |
| 流程失败但事件已终止 | 主步骤失败后收尾步骤仍会执行，两边都要看 |

画布编辑、保存、在源码清单登记和交付是不同步骤。没有「一键部署」或「运行真实流程」按钮；操作及检查依据见[工作流编辑器](./14.workflow-editor.md)。

## 数据与事件

| 现象 | 排查 |
| --- | --- |
| reset 后数据又出现 | 前端轮询或事件正在重写。先停用插件再 reset |
| 事件处理脚本没触发 | 核对事件 `type`、`match` 条件和投递的测试数据 |
| 重复事件产生重复记录 | 唯一键 / 幂等没覆盖，或测试时误换了事件 ID |
| `UNKNOWN_ENTITY` / 字段错误 | 用同一份事实核对三处：源根 `schema.sql` 的 `plugin_db_<实体>` 与列、本次 `dist/plugin.json` 由 Toolchain 投影出的 `entities`、目标库是否已按本次 `dist/schema.sql` 建表或升级。修正 `schema.sql` 后重新 `validate` / `build`，再由部署侧执行对应 SQL；不要手写源 `entities`、改 `dist/plugin.json`，或拿旧部署表掩盖漂移 |
| 媒体条目在但链接为空 | 能力未配置或链接获取降级，不代表文件丢失 |

HTTP 状态码 + code：
requestId/idempotencyKey：
workflowId/step：
