# 能力版本发布

业务能力随行业包 zip 交付。前后端插件可以独立修改版本，本次发布将需要交付的成员打入同一包，通过平台上传并确认安装。插件开发工具本身的版本和兼容矩阵见[发版说明](../../99.release-notes.md)。

## 发布前检查

1. 完成[质量门禁](./10.quality-gates.md)，使用本次源码生成上传包。
2. 核对前端调用的 `pluginId` 是后端插件的 ID，以及接口、事件和幂等约定；前后端 ID 和版本不要求相同。
3. 在测试环境验证所用扩展点、宿主能力、后端接口和流程。设备动作以最终任务或设备状态验收，不能只看接口受理结果。
4. 请部署方确认后端契约范围、连接配置、业务表准备及本次升级的数据兼容性。

## 发布流程

```text
质量检查 → 工作区 pack → 上传行业包 zip → 核对解析结果 → 确认安装 → 验证生效版本与业务功能
```

打包步骤见[行业包构建与打包](./20.industry-package.md)，平台操作及异常时的回滚见[安装、升级与回滚](./50.installation-and-upgrade.md)。

## 发布记录

保留实际上传的制品与验证结果，便于排查版本问题：

| 项 | 记录内容 |
| --- | --- |
| 交付包 | 包 ID、zip 文件名和摘要、所含能力 |
| 插件成员 | 各前后端插件 ID、版本，及后端资产摘要 |
| 兼容要求 | 前端运行协议要求、后端 `contractsRange`、本次接口或事件变更 |
| 数据与配置 | 迁移内容、数据兼容检查结果、部署配置是否就绪；不记录秘密值 |
| 安装与验收 | 目标环境、安装时间、结果、生效版本和业务验证结果 |
| 回滚 | 是否执行、恢复结果和原因；业务数据处理另行记录 |

同一版本的制品内容应保持不变，源码或资源变化后更新版本再打包。回滚恢复平台保存的整体生效态快照，不保证发布记录中的任意历史组合都能恢复。
