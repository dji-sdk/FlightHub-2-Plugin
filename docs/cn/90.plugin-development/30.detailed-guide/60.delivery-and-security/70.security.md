# 安全基线

插件入口、界面和后端脚本的运行边界不同。这一页区分平台强制限制与作者必须遵守的纪律；安装审核和代码审核仍是安全前提，不能只依赖沙箱、签名或构建成功。

## 信任与隔离

- 前端清单不能声明 `trusted`、`trustLevel`、`sandbox` 字段——出现即被拒绝。运行方式不是作者可声明的概念。
- 插件入口代码运行在隔离环境（iframe 沙箱或隔离域）：没有 localStorage、不能用 eval、不能直接 `fetch` / `new WebSocket`。一切宿主交互都走 `ctx`。
- 界面：挂在宿主 ShadowRoot 里（只有 DOM / CSS 隔离，不是 JS 安全边界）。界面不持有 `ctx`，数据经通信通道由入口代取——这是设计约定，不是运行时强制。
- 界面拿不到 `ctx`（上下文对象），它与入口之间只有通信通道（状态 + 方法）。

隔离模型的完整说明见[安全与隔离](../10.concepts/50.security-and-isolation.md)。

## 最小权限

- 前端：清单 `permissions` 只声明实际使用的能力；`ctx.capabilities.get()` 返回 `undefined` 时必须写降级逻辑。
- 后端 HTTP / 事件入口按插件包 `allowlist` 注入；流程脚本的非空 `scripts[].allowlist` 覆盖包级列表，空或未写时回落包级，不是合并。需要隔离不同接口的权限时拆成不同插件包。
- 后端脚本没申报的能力对象**根本不存在**（访问会报 `xxx is not defined`），平台不会报"未授权"。
- HTTP、事件和流程脚本三路共用按有效 `allowlist` 注入的方法，包括流程启动、通知、媒体、轨迹和视频。方法存在不证明提供方可用；只读判定不获得这些有副作用的能力，见[能力注入](../20.development/20.backend/40.context-and-allowlist.md)。
- 飞行动作只能走平台的受控步骤（如 `dispatch_mission`），脚本里拿不到设备 SDK、Token 或下游客户端。

## 网络与输入

前端插件入口的业务 HTTP 使用 `ctx.apiCall()`；平台会阻止入口的原生网络请求。界面在宿主页面执行，不安装同一网络护栏，但作者仍应经通信通道让入口代取数据，不能把 ShadowRoot 当成网络或 JavaScript 安全沙箱。

`ctx.apiCall()` 的请求约束：

- 业务路径（`endpoint`）以单个 `/` 开头，不自行加 `/plugin-api` 前缀或 `x-plugin-token`；禁止 `//`、反斜杠、片段和路径穿越。
- 也可用绝对 HTTP(S) URL 走受管出网，但目标必须命中宿主网关白名单；URL 不得带用户名、密码或片段，请求体只能是 JSON，不能自定义 Header。声明 `platform:http` 不等于白名单已放行，见[HTTP 调用](../20.development/10.frontend/70.http-websocket-events.md)。
- GET 不允许带请求体。
- 相对业务路径的请求体（`body`）支持 JSON 或文件：Blob 单个 ≤ 10MB；多部分表单最多 8 个文件、单文件 ≤ 10MB、总量 ≤ 20MB。绝对 URL 不支持文件请求体。
- 幂等键长度 1-256 字符，不能含换行等控制字符。

后端 `connector.fetch` 只接受绝对 URL，不自动跟随重定向，响应体超限直接失败。直连白名单只是防误配，生产出网策略由网关强制执行。

## 数据与秘密

- 不要把 Token、密码、STS 凭证、签名 URL、请求/响应原文写进日志、异常、返回值或流程黑板。
- 后端配置里的秘密只存在部署配置；`secret: true` 只让日志不打印值，不提供加密。
- 日志：平台按字段名遮蔽敏感值，但自由文本脱敏不可靠——敏感信息只写标识（如 `object_key`、`session_id`），不写正文。
- 当前本地预览只支持 HTTP PAC，不需要证书或私钥。调试面板地址不代登录或确认；本次资源根须手填、校验并同意后再加载，用完禁用来源并恢复代理设置，见[真实环境预览](../40.debug-and-test/10.local-development.md#真实环境预览)。

## 存储边界

- 前端 KV 存储每个命名空间配额 256 KiB；Blob 单项和总量上限 50 MiB、最多 200 项、TTL 24 小时；Object URL 由引擎台账统一回收。
- 后端数据存储（`store`）禁止裸 SQL、表连接和跨实体事务；"一个实体一张表、一个唯一键"是设计约束。
- 后端存储通过当前插件声明的逻辑实体调用，实体来源为 `schema.sql`，不能把任意物理表名当作接口。多插件的数据隔离和目标环境存储策略由部署方确认；本地内存模拟器不能证明这些生产边界，见[存储参考](../70.api-reference/20.backend/50.data-store-api.md)。

## 审计清单

1. 清单里没有信任字段、凭据或环境地址。
2. 声明的权限与实际调用一致。
3. 所有写副作用有稳定幂等键；超时后先查状态再决定重试。
4. 日志只记录 ID、键名、错误分类和摘要。
5. 插件资产有摘要校验，发布记录使用不可变版本。
6. 错误响应不回显请求体、SQL、连接串或下游原文。
