# 类型与契约目录

这一页说清两件事：清单和契约文件由谁校验、什么时候校验，以及跨端能传什么值。

前后端各有一份**源清单**（`fh2-plugin.json`，你手写，工具链校验）。后端装载时还会读**运行时清单**（构建产物 `plugin.json`，宿主严格解析，未知字段直接拒装）。结构定义只管"字段对不对"，版本号格式、字段与代码是否一致这类语义规则由工具链和宿主另外检查。

## 契约与校验时机

| 契约 | 形式 | 谁校验 | 何时 |
| --- | --- | --- | --- |
| 前端清单 `fh2-plugin.json` | JSON 结构定义 + 语义校验 | `fh2-plugin validate` / `build` | 本地校验、构建、安装 |
| 前端运行时契约 | SDK 内置 JSON | SDK / 引擎 | 构建、安装、激活 |
| 扩展点、能力、平台事件目录 | SDK 固定常量表，不可扩展 | 工具链 + 宿主 | 生成类型、校验、运行时 |
| 后端源清单 `fh2-plugin.json` | 结构定义 + 语义校验 | `fh2-plugin validate` / `build` | 本地校验、构建、安装 |
| 后端运行时 `plugin.json` | 严格解析，未知字段拒装 | 后端宿主装载器 | 包装载 |
| 流程 JSON 与 trigger | 严格解析 + 静态检查 | 宿主装载器 / 发布门禁 | 包装载、发布 |
| 脚本 I/O | 清单 `scripts[].io` 声明 | 装载期 + 运行时 | 装载、流程校验、调用 |
| 响应格式 `{code, message, data}` | 统一信封 | 后端 HTTP 层 | 每次请求 |

## 前端结构定义获取

> 文中 `fh2-plugin-sdk` 是文档里的模块名，实际导入路径以生成工程为准，见[环境准备](../../20.development/40.hands-on/10.environment-preparation.md)。

```ts
import { MANIFEST_SCHEMA_ID, manifestSchema, runtimeContract } from 'fh2-plugin-sdk'
```

或直接引用包内文件：

```text
fh2-plugin-sdk/schema/manifest.schema.json
fh2-plugin-sdk/runtime-contract.json
```

JSON 结构定义只管结构。更严的规则由工具链补充校验：严格三段语义化版本号、源清单禁止构建字段、配置默认值合法性、扩展点字段与代码声明一致性等。日常用 `fh2-plugin validate` 即可覆盖。

## 共享值域

跨越边界（插件与宿主之间、入口与界面之间）只能传可克隆的值——DOM、Vue 对象、函数都过不去：

```ts
type JsonValue = null | boolean | number | string | JsonValue[] | {[key: string]: JsonValue}
```

`PluginValue` 在 JSON 值之外还允许 `undefined / bigint / Date / RegExp / Error / ArrayBuffer / Blob / File / Map / Set`。跨宿主服务的方法参数、界面状态、日志详情都按 `PluginValue` 校验，循环结构同样会被拒绝。

后端有两套类型词表，别混用：

| 层 | 类型词 |
| --- | --- |
| 脚本 I/O（`scripts[].io`、流程输入） | `string / number / bool / object / array` |
| 数据实体字段（`entities[]`） | `string / number / boolean / datetime / json` |

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端包本地装不上，没有结构定义文件可查 | 后端源清单和运行时清单的结构定义已随 developer-runtime 提供；若仍失败，对照[后端清单](../20.backend/10.plugin-manifest.md)逐字段检查 |
| 前端结构校验通过但整体校验失败 | 结构校验之外还有语义校验；以 `fh2-plugin validate` 的诊断为准 |
| 脚本 I/O 写了 `boolean` 类型 | 脚本 I/O 层用 `bool`；`boolean` 只用于数据实体声明 |
