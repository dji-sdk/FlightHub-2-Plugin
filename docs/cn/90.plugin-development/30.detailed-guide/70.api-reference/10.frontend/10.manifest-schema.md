# 前端插件清单结构

`fh2-plugin.json` 放在插件工程根目录，是前端插件的声明文件：写清插件是谁、入口在哪、要用哪些能力、在哪些位置放什么。宿主实际安装的是构建产物 `dist/fh2-plugin.json`，你只编辑源文件。

## 顶层字段

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | :---: | --- |
| `id` | 字符串（`string`） | ✅ | `^(official\|exp)_[a-z0-9]+([_-][a-z0-9]+)*$`，如 `exp_capture` |
| `name` | 字符串（`string`） | ✅ | 非空 |
| `version` | 字符串（`string`） | ✅ | 严格三段语义化版本号，不能有首尾空白 |
| `description` | 字符串（`string`） |  | 展示说明 |
| `author` | 字符串（`string`） |  | 展示信息 |
| `entry` | 字符串（`string`） | ✅ | `./` 开头，指向入口代码（如 `./plugin.js`） |
| `permissions` | 字符串数组（`string[]`） |  | 能力 ID 列表，去重；值必须来自[能力目录](./40.capability-catalog.md) |
| `extensions` | 数组 | ✅ | 可为空；`id` 插件内唯一，`point` 必须在[扩展点目录](./30.extension-point-catalog.md)中 |
| `views` | 对象 |  | 键是界面 ID（`viewId`，`^[a-zA-Z0-9][a-zA-Z0-9-]*$`），值见下文 |
| `contributes.icons` | 数组 |  | `{id, src}`；`id` 插件内唯一，`src` 以 `./` 开头 |
| `config` | 对象 |  | 配置项声明，见下文 |

严格解析的规则：

- 根对象拒绝未知字段，多写一个就报错。
- 源文件出现 `manifestVersion`、`engines`、`buildInfo` 会被拒绝——这三个由 `fh2-plugin build` 写入构建产物。
- 源文件出现 `trusted`、`trustLevel`、`sandbox` 会被拒绝——运行方式不是作者可声明的概念。

## 子结构

```ts
// extensions[] 的一项：只能写该扩展点允许的静态字段
interface ExtensionDeclaration {
  readonly id: string
  readonly point: string
  readonly [staticField: string]: unknown
}

// views 的值
interface ViewResource {
  readonly entry: string              // 界面构建产物路径
  readonly styles?: readonly string[]
}

interface IconResource {
  readonly id: string
  readonly src: string
}
```

扩展声明只写该扩展点允许的静态字段，例如按钮的 `anchor`、项目入口的 `path` / `position`、计划表单的 `planType`；没有静态字段的扩展点只写 `id` 和 `point`。`label`、`icon`、`visible` 等是运行时状态，不是清单静态字段，与回调方法一起用 `ctx.extensions.contribute()` 提交，后续状态由贡献句柄的 `update()` 更新。图标资源仍在 `contributes.icons` 中声明，贡献的 `icon` 状态引用资源 ID。`layer`、`zIndex`、`slot`、`priority`、`order` 等布局字段一律拒绝。各扩展点的静态字段清单见[扩展点目录](./30.extension-point-catalog.md)。

配置项只支持三种类型，且必须有 `default` 与 `label`：

```ts
type ConfigFieldSchema =
  | { type: 'boolean'; default: boolean; label: string }
  | { type: 'number'; default: number; label: string; min?: number; max?: number }
  | { type: 'string'; default: string; label: string; enum?: readonly string[] }
```

`number.default` 必须有限且落在 `min/max` 内；`string.enum` 非空并包含 `default`。安装时填入的非法值会被丢弃并回退默认值。

## 最小示例

`fh2-plugin.json`：

```json
{
  "id": "exp_minimal",
  "name": "最小插件",
  "version": "0.1.0",
  "entry": "./plugin.js",
  "permissions": ["platform:storage"],
  "extensions": [
    {"id": "open-panel", "point": "cockpit.ui.toolbar-actions"},
    {"id": "panel", "point": "cockpit.ui.left-panel"}
  ],
  "views": {
    "panel": {"entry": "./views/panel.js"}
  }
}
```

## 校验与构建

- 校验：`fh2-plugin validate`，覆盖 JSON 结构定义、语义规则、扩展点字段与源码一致性。
- 构建：`fh2-plugin build` 产出 `dist/fh2-plugin.json`，写入 `manifestVersion`、`engines`、`buildInfo`，并把逻辑路径替换为构建后的资源路径。命令详见[工具链命令行参考](./70.toolchain-cli.md)。
- SDK 提供清单 JSON 结构定义文件并导出 `manifestSchema`。文件位置使用开发者工具生成的配置，详见[类型与契约目录](../30.shared/10.schema-catalog.md)；不要把 `$schema` 写进清单。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 校验报未知字段 | 清单是严格解析的；删掉拼错或多余的键（`handlers`、`triggers`、`trusted` 等都不是合法字段） |
| 校验报扩展声明含状态/方法 | 这些字段移到运行时 `contribute()`，清单里只留静态字段 |
| 安装报清单不合法（`MANIFEST_INVALID`） | 用的是手改过的产物或缺构建字段；用 `fh2-plugin build` 重新产出 |
| `version` 校验失败 | 必须是三段数字的语义化版本号，如 `0.1.0` |
