# 前端 SDK API

`fh2-plugin-sdk` 是插件开发 SDK，提供 `definePlugin`、上下文 `ctx`、界面定义和扩展点、能力、事件目录。

> 本页模块名用于说明 SDK 的 API 与子入口，不是公共 npm 安装坐标。实际依赖与导入路径保留开发者工具生成的配置，获取与安装见[环境准备](../../20.development/40.hands-on/10.environment-preparation.md)。

## 包入口

| 入口 | 内容 |
| --- | --- |
| `fh2-plugin-sdk` | `definePlugin`、`defineView`、`definePluginView`、`createViewState`、上下文类型、错误码、清单契约、`manifestSchema`（界面相关的成员也从这个根入口导入即可） |
| `fh2-plugin-sdk/view` | 同上中界面相关成员的子路径导出（可选，二选一） |
| `fh2-plugin-sdk/catalog` | 宿主、扩展点、能力、平台事件目录 |
| `fh2-plugin-sdk/schema/manifest.schema.json` | 清单 JSON 结构定义 |

SDK 只提供插件作者 API。宿主创建、安装和资源管理由平台负责，不通过 SDK 导入宿主实现。

## 入口定义

```ts
// plugin.ts
import { definePlugin } from 'fh2-plugin-sdk'

export default definePlugin({
  async activate(ctx) {
    // 贡献扩展、申请能力、订阅事件都从这里开始
    return {
      dispose({ reason }) {
        // 业务收尾：停止自己的业务逻辑
      },
    }
  },
})
```

规则：

- 插件入口构建产物的默认导出必须是 `definePlugin()` 的结果，一个插件只有一个入口。
- `activate` 返回值里的 `dispose` 只做业务收尾；扩展、界面、定时器、订阅、Blob URL、跨宿主通信服务由平台统一回收，不必重复清理。
- 同一入口可在 `cockpit | plan | message | project` 四个宿主分别激活，用 `ctx.host.id` 分流。
- `dispose` 的 `reason` 取值：`host-unmount | plugin-disabled | plugin-uninstalled | config-changed | activation-failed | runtime-terminated`。

## 上下文成员（`ctx`）

`ctx` 是平台传给 `activate` 的上下文对象，插件的一切宿主交互都通过它。

| 成员 | 说明 |
| --- | --- |
| `plugin` | `{id, name, version}` 当前插件身份 |
| `host` | `{id, instanceId}` 当前宿主 |
| `locale` | 语言（宿主创建时的快照） |
| `config` | 配置项求值结果（只读） |
| `permissions` | 实际授权的能力 ID 列表 |
| `lifecycle` | `{signal, disposed}`；停用时 `signal` 发出中止信号 |
| `timers` | `setTimeout/clearTimeout/setInterval/clearInterval`，停用时统一回收 |
| `extensions.contribute(id, impl)` | 贡献一个清单已声明的扩展，返回句柄（见[扩展点目录](./30.extension-point-catalog.md)） |
| `capabilities.get(id)` | 取能力调用方；未授权或宿主未提供时返回 `undefined`（见[能力目录](./40.capability-catalog.md)） |
| `services.provide / connect` | 同插件跨宿主通信（见[跨宿主通信服务](./60.plugin-service.md)） |
| `storage.local / session` | 键值存储 `get/set/remove/keys`，值必须是可序列化 JSON |
| `blobs` | 二进制存取 `get/put/remove/url` |
| `events.on(name, handler)` | 订阅平台事件（见[平台事件目录](./50.platform-event-catalog.md)） |
| `ws.onBizCode(bizCode, handler)` | 只读订阅宿主 WebSocket 业务消息 |
| `logger` | `debug/info/warn/error(message, detail?)` |
| `apiCall(endpoint, options?)` | 插件入口的受管 HTTP 出口；相对路径访问平台内部接口，绝对 HTTP(S) URL 经网关出网 |
| `views.get(viewId, initialState?)` | 取得界面句柄；实际显示还需扩展点或弹窗等宿主出口挂载 |
| `views.handle(viewId, provider)` | 接管一个界面（配合 `definePluginView`） |

## HTTP 调用选项（`apiCall`）

```ts
const res = await ctx.apiCall('/plugin/invoke', {
  method: 'POST',                             // 默认 GET
  body: {pluginId: 'exp_demo', handler: 'demo.status', input: {}},
  timeoutMs: 10000,
  idempotencyKey: 'capture-001',              // 1-256 字符，不含换行
})
```

| 限制 | 值 |
| --- | --- |
| 相对路径 `endpoint` | 单个 `/` 开头，不能自带 `/plugin-api` 前缀、`//`、反斜杠、fragment 或路径穿越 |
| 绝对 URL `endpoint` | 仅 HTTP(S)，不能带 userinfo/fragment；必须命中宿主网关出网白名单 |
| 相对路径 `body` | JSON 值，或 Blob（≤10MB），或受控多部分表单（≤8 个文件、单文件 ≤10MB、总 ≤20MB） |
| 绝对 URL `body` | 仅 JSON 值；不开放自定义 Header |
| GET 请求 | 不能带请求体 |
| 返回值 | JSON 原始响应，**不**自动提取 `data` |
| 失败 | **不返回失败信封**：网关业务码非零时直接抛 `PluginError`（`code` 为 `PLUGIN_GATEWAY_ERROR`，网关业务码在 `detail.gatewayCode`），用 `isPluginError` 判断后读取 |
| `idempotencyKey` | 1–256 字符、非空、无 CR/LF；平台映射为 `Idempotency-Key` 请求头，实际去重语义以后端契约为准 |

## 界面

```ts
import { defineView } from 'fh2-plugin-sdk'

export default defineView({
  mount(viewCtx) {
    // viewCtx: {viewId, mountElement, styleTarget, overlayElement, port, locale, direction, theme}
    viewCtx.mountElement.textContent = 'hello'
    return { dispose() {} }
  },
})
```

- 界面构建产物的默认导出必须是 `defineView()` 的结果。
- 界面**拿不到** `ctx`（`PluginContext`）和能力；与入口之间只有一条通信通道（状态 + 方法）。

```ts
import { definePluginView, createViewState } from 'fh2-plugin-sdk'

const panel = definePluginView<{
  state: {count: number}
  methods: {increment(delta: number): number}
}>('panel')

// 入口侧：接管界面。对象形态（state 是 createViewState 之类的状态源）：
const state = createViewState({count: 0})
await panel.handle(ctx, {
  state,
  methods: {
    increment: delta => {
      state.update(v => ({count: v.count + delta}))
      return state.get().count
    },
  },
})

// 界面侧：contract.client(port) 得到 { state, <各方法平铺>, dispose }，
// 方法直接调用：await client.increment(1)
```

> 提示：`panel.handle(ctx, provider)` 内部委托给 `ctx.views.handle`；推荐使用契约对象，让类型检查约束状态、方法和初始状态。

- 契约**未声明 `initialState`** 时，使用上例的 `handle(ctx, {state, methods})` 会话对象，`get(ctx)` 返回初始状态为 `null` 的界面句柄。
- 契约**声明了 `initialState`** 时，必须使用 `handle(ctx, (initialState, call) => ({state, methods}))` 工厂，并通过 `get(ctx, initialState)` 传入初始状态；工厂创建的完整初始状态必须包含相同字段和值，不能把上例的会话对象直接传入。
- `createViewState().update(updater)` 返回 `void`；上例 `increment` 声明返回 `number`，因此更新后显式返回 `state.get().count`。

约束：方法最多 1 个参数；参数、返回值、状态必须满足 `PluginValue`（可跨边界克隆的值）；`initialState` 必须是 JSON 值且为状态的部分形状。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| Entry 里裸 `fetch` / `XMLHttpRequest` / WebSocket 被拦截 | 改用 `ctx.apiCall()` / `ctx.ws`。Guard 错误不是 `PLUGIN_NETWORK_BLOCKED`；后者表示 `apiCall` 参数校验失败 |
| `ctx.apiCall` 返回的不是业务数据 | 它返回完整信封，业务数据在 `data` 字段里 |
| `ctx.apiCall` 报 `PLUGIN_GATEWAY_ERROR` | 网关业务码非零会以异常抛出；`isPluginError` 判断后读 `error.detail.gatewayCode` |
| 界面里拿 `ctx` 是 `undefined` | 界面设计上就没有上下文；需要数据就走插件入口↔界面通道 |
| 定时器在插件停用后还跑 | 用 `ctx.timers` 而不是全局 `setTimeout`，平台会统一回收 |
