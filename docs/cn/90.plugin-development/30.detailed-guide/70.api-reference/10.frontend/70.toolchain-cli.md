# 工具链命令行参考（`fh2-plugin`）

`fh2-plugin` 是插件工程的命令行工具，覆盖创建、校验、类型生成、构建、打包和调试。本文人工说明适用插件开发工具 `1.0.0`；命令是否可用还取决于开发者工具所含资源和目标环境。插件开发工具的获取、安装和 CLI 注册步骤见[环境准备](../../20.development/40.hands-on/10.environment-preparation.md)，不要把逻辑包名当作公共 npm 下载坐标。

在已注册 CLI 的终端执行 `fh2-plugin create --version` 检查版本，执行 `fh2-plugin <命令> --help` 查看该命令的当前参数。根命令不支持 `fh2-plugin --version`。SDK 包版本、前端运行协议版本和后端 `contractsVersion` 是不同维度，不能用 CLI 版本替代。

## 工程目录与模板

开发者工具根目录不是待运行的插件工程。多数工程命令的 `--root` 相对执行命令时的当前目录；不传时使用当前目录。再按该工程根解析清单和配置路径。显式 `--manifest` 会改变部分命令的发现路径，不是行业工作区成员选择的通用替代。

**后端校验不要传 `--manifest` 或 `--config`**：在后端目录执行 `fh2-plugin validate`，
或执行 `fh2-plugin validate --root <后端目录>`。显式 `--manifest` 使用前端清单规则，
会把合法后端清单误报为缺少 `id`、`entry` 等前端字段；不要为修这个报错改后端身份。

| 根目录标志 | 含义与操作范围 |
| --- | --- |
| `packages.json` | 行业能力工作区；支持聚合校验、类型生成、构建和打包。直接 CLI `dev` 不支持此根 |
| `capabilities.json` | 单个能力工程；可运行 `dev`，并用 `--frontend` / `--backend` 选择成员 |
| `fh2-plugin.json` | 单个前端或后端插件；按源清单识别侧别，不按文件名猜侧别 |

`create` 只接受以下模板，不再使用旧全栈单插件模板或旧宿主专用模板名：

- `capability-fullstack`：默认能力工作区。外层有 `packages.json`，同名能力子目录内有 `capabilities.json`、两个前端成员、一个 TypeScript 后端成员和 `mock/`。
- `frontend-basic`：单前端插件，包含面板及现场问题/对话框示例；不是另一个能力工作区。
- `backend-basic`：独立 TypeScript 后端插件，不生成前端界面。

非交互创建单插件时明确传 `--plugin-id`；ID 使用 `exp_` 或 `official_` 前缀的小写短名。创建后是否安装依赖由交互选择或 `--install` / `--no-install` 决定，不要假定已安装；不存在 `fh2-plugin install` 命令。

## 交互创建与自动化创建

日常创建工程，在开发者工具目录之外的工程父目录执行：

```bash
fh2-plugin create
```

向导依次询问工程类型、目录、名称、包管理器和是否安装。前端或后端单插件还会询问插件 ID。
完整工作区的目录名同时用作能力 ID（例如 `exp_hello`），成员 ID 自动添加
`_frontend`、`_issues`、`_backend` 后缀。在开发者工具目录内创建时，默认放入 `examples/`，
并默认不安装；**仅从开发者工具取得依赖，不代表当前目录在开发者工具目录内**。
输入 `Ctrl+C` 可取消；非空目录会拒绝覆盖。

使用源码 bin 或该源码注册的 CLI 时会自动定位开发者工具。从其他 CLI 创建时才需要
`--platform-root <源码根>`。没有终端问答的 CI/脚本应显式填写参数，例如：

```bash
fh2-plugin create exp_hello --template capability-fullstack --platform-root "$FH2_TOOLS" --package-manager pnpm --install
```

只有需要目录名与能力 ID 不同，或需要自定义成员 ID 时，再加 `--capability-id`、
`--frontend-plugin-id`、`--issues-plugin-id`、`--backend-plugin-id`；完整选项见
`fh2-plugin create --help`。不加 `--install` 的非交互命令只生成文件，后续须在工程根安装依赖。

## 命令副作用

| 命令 | 输入与输出边界 |
| --- | --- |
| `create` | 在工程父目录创建新工程；可按选择安装依赖。开发者工具接入使用 `--platform-root "$FH2_TOOLS"`，沿用生成的本地依赖配置 |
| `validate` | 读取源码清单与可发现的源码，输出诊断，不生成发布包 |
| `generate` / `types` | `generate` 按工程生成前端 `src/generated/plugin-types.ts` 或后端 `types/`；`types` 只面向后端。`--check` 检查缺失/过期，不写类型文件 |
| `build` | 校验并生成构建所需类型，写入 `dist/`；`--watch` 才持续重建，不启动宿主或网关 |
| `pack` | 默认先构建，再写交付目录和未签名 zip；不上传、不部署、不签名 |
| `dev` / `preview` | 构建并启动服务，默认监听源码；`--no-watch` 只关闭重建监听，不等于命令立即退出 |
| `serve` | 启动本地 Web IDE；编辑和任务经本地 API 执行，详见[Web IDE](../../40.debug-and-test/12.web-ide.md) |
| `knowledge` / `mcp` | 分别管理后端知识包、接入本地 AI 工具；详见[知识与 MCP](../../40.debug-and-test/16.mcp-and-knowledge.md) |

不要编辑生成类型或 `dist/` 来修源码问题。前端类型文件是 `src/generated/plugin-types.ts`。`generate --out` 相对选定清单所在目录；能力根自定义 `--out` 时须用 `--manifest` 明确选择一个前端成员。

能力根的 `build --frontend <id>` 只构建选定前端并跳过后端，`--backend <id>` 反之。行业根不接受这类成员筛选或自定义 `--config`；需要局部构建时改用能力根。`pack --no-build` 只适用于能力根，且要求可复用的最新独立默认配置构建报告；行业根始终重新构建。

## 打包上下文

发布教程使用[工作区行业包打包](../../60.delivery-and-security/20.industry-package.md)。CLI 保留单插件与旧聚合上下文，用于检查或兼容已有工程：

| 选定工程根 | `fh2-plugin pack` 的输出 |
| --- | --- |
| 行业工作区（`packages.json`） | 默认写 `release/`，生成包含能力成员的上传包 |
| 能力工程（`capabilities.json`） | 默认写 `release/`，生成含 `packages.json` 与能力目录的上传包 |
| 独立前端 / 后端插件（`fh2-plugin.json`） | 默认写 `release/`，生成独立插件 zip；无法直接上传平台，需要先将源码纳入能力工作区 |
| 旧 `plugins/*` 聚合根 | 默认写 `dist/`，保留旧聚合行为；新工程使用能力 / 行业结构 |

独立插件根没有 `pack` 脚本时，可用工程已安装的 CLI 执行 `pnpm exec fh2-plugin pack`；这只生成插件级交付物。`--out-dir` 相对选定工程根。标准 zip 输出中的 `UPLOAD_READY <zipPath>` 只证明已生成产物，不代表平台接受该结构，也不证明已上传、安装或审批。

## 退出码

退出码分别解释，不能把进程启动或任务受理视为交付成功：

| 命令组 | 退出码 |
| --- | --- |
| `validate`、`generate` | `0` 检查通过或类型已更新；`1` 校验失败或类型缺失/过期；`2` 参数或路径错误；`3` 内部错误 |
| `types` | `0` 类型已更新或最新；`1` 清单缺失、类型过期或未捕获异常；`2` 参数错误 |
| `build`、`pack`、`dev`、`preview`、`serve` | `0` 正常完成/退出；`1` 构建、服务或工程发现失败；`2` 参数错误；`3` 内部错误；SIGINT 中断可返回 `130` |
| `knowledge` | `0` 操作成功；`1` 知识校验或锁解析失败；`2` 子命令/参数错误。`status --json` 有阻断项也返回 `1` |
| `mcp` | `0` 正常退出；`1` 服务/知识初始化失败；`2` 参数或收纳根错误 |

其他入口按其实际帮助和错误输出处理；不要假定所有命令都支持同一组短参数或参数转发形式。

## 推荐的 CI 检查

在已安装依赖的插件或能力工程根执行：

```bash
fh2-plugin generate --check
fh2-plugin validate --format json
fh2-plugin build
```

`validate --format json` 的输出结构随工程上下文不同，读取 `ok` 和诊断，并保留成员结果及 warning；不要把前端单插件的形状套到行业工作区。`generate --check` 非零时先在开发环境重新生成并审查类型改动。构建会执行校验和类型生成，但成功不证明目标宿主或后端兼容、设备动作通过或插件获准发布。

## 本地调试（`dev`）

例如从含 `packages.json` 的工作区根，选择含 `capabilities.json` 的同名子目录。将示例 ID 换成工程实际 ID：

```bash
fh2-plugin dev --root ./exp_demo_capability
fh2-plugin dev cockpit --root ./exp_demo_capability
```

错误目录示例：在上述行业工作区根直接执行 `fh2-plugin dev` 会返回参数错误。改用 `--root <能力子目录>`，或运行生成工程已有的 `pnpm run dev`，该脚本已选择能力子目录。工作区根没有 `dev:cockpit` 脚本。

- 普通模式默认端口 `5175`，驾驶舱模式默认 `5176`，打开终端完整地址。驾驶舱模式仍挂载 `project+message+cockpit`，不是单宿主。
- 能力工程包含后端且未选择仅前端时，同时启动本地 HTTP 模拟器；独立后端 `dev` 只启动调试网关，没有前端页面。
- 前端重建成功刷新页面；能力内后端重建成功只重载本地后端。重建失败先看终端，已有页面可能仍显示上一份产物。
- `--gateway-target <origin>` 需要经环境变量注入 `FH2_DEV_LOGIN_TOKEN`，只代理固定 HTTP 网关；本地 WebSocket 和平台事件不会因此变成真实订阅。

用 `Ctrl+C` 停止服务和监听；详细操作见[本地开发](../../40.debug-and-test/10.local-development.md)。

## 连接真实司空（`preview`）

在已安装依赖的前端插件或能力工程根执行，将地址换成获授权的 HTTP 项目页：

```bash
fh2-plugin preview --fh2-url "http://fh2.example.test/project" --no-open
```

当前只支持 HTTP 目标，通过本机同源受限代理和 PAC 接入；不支持 HTTPS，也不支持 `--local-protocol`、`--cert`、`--key`。不要安装证书、关闭 TLS 校验或擅自把 HTTPS 环境改成 HTTP。

完整顺序是：启用本次 PAC，先登录同一 HTTP Origin 并进入项目，打开终端调试面板地址，在面板手填本次资源根 URL，校验清单和权限，勾选临时运行同意，再点「确认并重载」。链接只打开调试面板，不代登录、不预填来源、不代确认。逐步说明见[真实环境预览](../../40.debug-and-test/10.local-development.md#真实环境预览)。

只替换本地前端资源，后端使用目标环境已安装版本。同 ID 远端插件用 `overlay` 资源覆盖；远端未安装的插件经面板确认后临时运行（`temporary`），不是正式安装。代理 ready 不代表宿主加载成功。结束时停用预览并关闭 PAC。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `validate`/`generate` 报 `FH2_SDK_VERSION_MISMATCH` | SDK 与工具链版本不一致；使用同一开发者工具提供的配套版本 |
| 构建产物装不上 | 不要手改 `dist/`；用 `fh2-plugin build` 产出并整体发布 |
| `preview` 打不开 | 确认是获授权的 HTTP 私有化目标、当前 PAC 已启用，且已登录目标项目；不要按证书路线排查 |
| 本地后端没起来 | 确认后端工程包含当前源清单 `fh2-plugin.json`，并在后端插件目录运行 `fh2-plugin dev`；不要按已移除的旧全栈单插件目录约定排查 |

安装、保存和预览问题集中见[常见问题排查](../../40.debug-and-test/60.troubleshooting.md)。
