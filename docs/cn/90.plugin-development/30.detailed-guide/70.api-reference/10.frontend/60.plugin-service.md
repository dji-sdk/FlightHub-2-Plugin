# 跨宿主通信服务 API

跨宿主通信服务让**同一个插件**在不同宿主实例之间共享状态和方法（比如驾驶舱和计划页各有一个实例，共享一份数据）。它不是跨插件 RPC：服务按 `(插件 ID, serviceId)` 隔离，别的插件连不上。

## 定义契约

> `fh2-plugin-sdk` 是插件开发 SDK 的文档逻辑模块名；实际导入路径保留生成工程的配置，见[环境准备](../../20.development/40.hands-on/10.environment-preparation.md)。

```ts
import { definePluginService } from 'fh2-plugin-sdk'

const records = definePluginService<{
  get: (input: {id: string}) => {id: string; status: string}   // 方法
  refresh: () => void
}, {
  changed: {id: string}                                         // 事件
}>('records')
```

约束：

- 方法只能有 0 或 1 个参数；参数、返回值、事件数据都必须是 `PluginValue`（可跨边界克隆的值）。
- 方法名不能叫 `dispose` 或 `on`；方法名与事件名不能重叠。
- `serviceId` 为空会抛 `TypeError`。

## 服务提供方

```ts
// 在某一个宿主实例里提供实现
const registration = await ctx.services.provide(records, {
  get: async ({id}) => ({id, status: 'ready'}),
  refresh: () => {},
  changed: (emit, options) => {
    if (options?.immediate) emit({id: 'current'})
    const off = subscribe(id => emit({id}))   // 返回 {dispose} 取消订阅
    return {dispose: off}
  },
})

await registration.dispose()   // 撤销提供方，现有调用方的挂起调用会失败
```

同一插件、同一 `serviceId` 只能有一个提供方；重复 `provide` 返回 `SERVICE_UNAVAILABLE`。提供方可以晚于调用方出现（晚绑定）。

## 调用方

```ts
// 另一个宿主实例里连接
const client = await ctx.services.connect(records)

const item = await client.get({id: 'r-1'})          // 方法全部返回 Promise
const sub = await client.on('changed', payload => { // 订阅服务事件
  ctx.logger.info('记录变化', payload)
})

await sub.dispose()
await client.dispose()
```

调用方方法全部是异步的；提供方离开后调用返回 `SERVICE_UNAVAILABLE`，新的提供方注册后逻辑订阅会自动重新绑定。

## 限制

- 参数、返回值、事件在跨宿主传输前都会校验并克隆；不满足 `PluginValue` 返回 `PLUGIN_VALUE_INVALID`。
- 不要传 DOM、Vue 实例、函数、能力/宿主句柄或循环结构。`PluginValue` 允许 `Blob`、`Error`、`Date`、`Map` 等结构化克隆值，但大对象会跨宿主复制，通常更适合 Blob 存储或后端资源 ID。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `connect` 后调用返回 `SERVICE_UNAVAILABLE` | 没有任何宿主实例 `provide`，或提供方已释放；等提供方出现或降级 |
| 想让插件 A 调用插件 B 的服务 | 不支持；跨宿主通信服务只在同一个插件的不同宿主实例之间有效 |
| 方法参数带函数或 Vue 对象报错 | 跨边界只能传 `PluginValue`；改成传数据 |
| 两个实例都想 provide | 只允许一个权威提供方；把实现收敛到一个实例 |
