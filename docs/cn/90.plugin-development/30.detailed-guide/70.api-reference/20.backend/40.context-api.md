# 后端脚本上下文（`ctx`）

后端四类脚本（HTTP 接口处理函数、事件消费、流程脚本、只读判定脚本）的入口函数第二个参数都是 `ctx`。它是本次调用的事实信息，不需要申报权限，也没有任何能力方法——能力是按 `allowlist` 注入的**全局对象**（见[能力目录](./80.host-capability-catalog.md)）。

每种入口的 `ctx` 字段以工具链生成的 `types/` 类型声明为准（`fh2-plugin types` 产物：`HandlerCtx`、`EventCtx` 等，按调用形态分"世界"）。

## 字段

| 字段 | 说明 |
| --- | --- |
| `ctx.now` | UTC RFC3339 字符串；HTTP 是本次调用时间，事件是每次处理尝试的时间。流程 / 只读判定从步骤入参 `now` 取得，显式接入 `run.now` 才有确定性时间 |
| `ctx.idempotencyKey` | HTTP 取 `Idempotency-Key` / 业务键；事件取消息 `event_id`，不是投递标识；流程 / 只读判定取步骤入参 `idempotencyKey`。缺失时为空串 |
| `ctx.requestId` | HTTP 请求追踪 ID；事件、流程和经流程执行的只读判定为空串，不用于生成业务 ID |
| `ctx.pluginVersion` | 当前插件包版本 |
| `ctx.scriptId` | 当前脚本标识 |
| `ctx.stableId(scope)` | 由幂等键派生的稳定 ID，见下文 |

各路径下 `scriptId` 与 `requestId` 的取值：

| 字段 | HTTP 接口处理函数 | 事件处理函数 | 流程脚本 | 只读判定脚本 |
| --- | --- | --- | --- | --- |
| `scriptId` | `handler:<pluginId>:<名>` | `event:<pluginId>:<type>#<序号>` | 清单 `scripts[].name`；未写时由文件名 / 入口派生 | `evaluator:<pluginId>:<名>` |
| `requestId` | HTTP 请求追踪 ID | 空串 | 空串 | 经流程执行时为空串 |

`scriptId` 用于定位脚本，不是业务去重键。事件重新处理时 `ctx.now` 可以变化；需要保持原业务时间，应校验并使用消息中的业务时间字段，而不是把当前处理时间当作事件发生时间。

## 稳定 ID（`stableId(scope)`）

```
stableId(scope) = sha256(idempotencyKey + "\0" + scope) 的前 32 个十六进制字符
```

- 相同幂等键 + 相同 scope 得到相同 ID；仍须配合存储唯一键、原子去重和副作用控制，稳定 ID 本身不保证整段业务幂等。
- ⚠️ 幂等键为空时抛 `INVALID_ARGUMENT`（契约错）——平台不会随机兜底。HTTP 入口要用它，调用方必须带 `Idempotency-Key` 头。

## 示例

```ts
// handlers/example/create.ts
export function create (input: RecordInput, ctx: HandlerCtx) {
  const recordKey = requireText(input, 'record_key')
  return {
    id: ctx.stableId('record:' + recordKey),
    accepted_at: ctx.now,
  }
}
```

## 注意

- 不要用运行时时间、随机数或进程状态生成去重 ID。HTTP 不自动重试；事件和流程重新执行整段脚本时，已发生的副作用仍需防重。
- 流程每一步的幂等键是 `<流程ID>:<步骤ID>`。在流程步骤的 `inputs` 里接入下面的引用，脚本直接读 `ctx.idempotencyKey`。`now`、`idempotencyKey`、`script` 是平台种子/寻址键，不要写进 `scripts[].io.inputs`：

```json
{ "idempotencyKey": {"from": "run.idempotencyKey"} }
```

时间同理：在步骤 `inputs.now` 接入 `{"from":"run.now"}` 后，脚本从 `ctx.now` 读取，不需要在 `io.inputs` 声明 `now`。只接幂等键不会自动填充时间；未接线时对应 `ctx` 字段为空，不能生成随机值或当前时间来伪造确定性。整步重跑见[重试边界](./60.workflow-dsl.md#重试边界)。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `stableId()` 抛 `INVALID_ARGUMENT` | 幂等键为空；HTTP 调用方补 `Idempotency-Key` 头 |
| 再次处理时 `ctx.now` 变了 | HTTP / 事件是每次处理时间，属于正常差异；流程检查是否显式接入 `run.now` |
| 同一请求写了两条记录 | 幂等没做；用 `stableId` 做唯一键 + `store.createIfAbsent` |
