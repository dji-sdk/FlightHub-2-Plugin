# 流程触发器参考

每个流程 JSON 必须自带 `trigger` 段，声明「这个流程怎么被启动」。五轴 `api / schedule / stream / bizNotify / job` 至少启用一轴，同一流程可以同时启用多轴。

## 总表

| 轴 | 启动方式 | 关键字段 |
| --- | --- | --- |
| `api` | 调用 `POST /flows/{name}/start` | `seed?` |
| `schedule` | 平台定时调度 | `intervalSec` 必填、`paused?` |
| `stream` | 消费统一事件流，命中即启动 | `match` 必填、`seed` 必填 |
| `bizNotify` | 消费任务系统通知 | `subscriber` 必填、`seed` 必填、`params?` |
| `job` | 只能被本插件代码 `flow.start()` 启动 | `seed?` |

## HTTP 触发（`api`）

```json
{ "trigger": {"api": {"seed": ["eventId"]}} }
```

- `seed` 列出启动请求会写入 `trigger.*` 的键。
- 声明了 `api` 才允许 HTTP 启动；否则流程存在但调用返回 `403 / 40301`。

## 定时触发（`schedule`）

```json
{ "trigger": {"schedule": {"intervalSec": 300, "paused": false}} }
```

- `intervalSec > 0` 必填；`paused` 默认 `false`。
- 平台按声明维护定时调度（调度 ID 固定为 `flow-schedule-<流程名>`）：手工暂停会被下一轮对账恢复，要停就改声明并重新发布。
- 调度触发会提供 `run.intervalSec`。

## 事件流触发（`stream`）

```json
{
  "trigger": {
    "stream": {
      "match": {"event_type": "traffic.accident", "status": "pending"},
      "seed": ["eventId", "eventType", "payload", "lat", "lng"]
    }
  }
}
```

- `match` 必填非空；键只能是 `event_id / event_type / tenant_id / source / status / priority / occurred_at / flight_mission_id / result_code / notify_on / payload`，全部按字符串等值 AND。
- `seed` 用小驼峰命名法写：`eventId, eventType, tenantId, source, status, priority, occurredAt, flightMissionId, resultCode, notifyOn, payload, lat, lng`。
- 空字符串值不写入 seed；`lat/lng` 从 `payload.poi` 提取，任一为 0 或非法则两者都不写入。
- `eventId` 是业务幂等键（流程 ID = `<流程名>-<bizId>`，重复启动返回 `{already: true}`）。

## 业务通知触发（`bizNotify`）

```json
{
  "trigger": {
    "bizNotify": {
      "subscriber": "patrol_demo",
      "seed": ["taskUuid", "projectUuid", "dockSn", "waylineUuid"],
      "params": {
        "recheck_delay_sec": {"as": "recheckDelaySec", "type": "number", "max": 3600}
      }
    }
  }
}
```

- `subscriber` 必填，对应任务通知 `biz_ext` 顶层的 key；按它匹配是否归本流程处理。
- `seed` 值域：`eventId, eventKind, occurredAt, taskUuid, projectUuid, taskName, taskType, dockSn, droneSn, waylineUuid, taskStatus`。
- `params` 只投影白名单键，可改名；类型 `number/string/bool`，number 可设 `max` 钳值。
- 用任务 UUID 做幂等键（每次通知自带的事件 ID 会变，不要用它）。

## 作业触发（`job`）

```json
{ "trigger": {"job": {"seed": ["event_id", "file_id"]}} }
```

- 只能被**本插件**的 HTTP 接口处理函数或事件脚本经 `flow.start(flowName, bizId, seed)` 启动；HTTP 启动端点不会因此放行。
- `seed` 名不能为空、带首尾空白、重复或叫 `script`；运行时会校验实际传入的 seed 覆盖声明的键。
- 重复启动同一业务 ID 返回 `{already: true}`，不是错误。

## 幂等与投递

| 项 | 行为 |
| --- | --- |
| 流程 ID | 固定 `<流程名>-<bizId>`；同一业务 ID 即使流程已结束也不能重跑（重复启动返回 already） |
| 事件流启动失败 | 不确认消息，等待重新投递 |
| 业务通知启动失败 | 退避后重新入队；永久坏消息确认并告警 |

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动返回 `40301` | 流程没声明 `api` 触发器；补声明并重新发布，或改用其他轴 |
| 定时触发到点没跑 | 声明被 `paused`，或 `intervalSec` 非法；注意手工暂停会被平台对账恢复 |
| 事件流命中但流程没起 | `match` 键名不在允许列表、或值类型不是字符串等值 |
| `flow.start` 报流程不存在 | 作业流程必须与调用脚本在同一个插件包内 |
