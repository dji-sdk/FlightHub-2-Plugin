# 后端能力目录

后端脚本没有 require、没有裸网络和文件系统。平台按清单 `allowlist` 把能力注入为**全局对象**：申报了才能用；没申报的对象根本不存在（报 `xxx is not defined`，而不是「未授权」）。

## 能力名全集（19 个）

`egress:fetch`、`config:get`、`event:write`、`geo.segment:read`、`integration:write`、`integration.gis:read`、`media:read`、`media:write`、`flow:start`、`track:read`、`video:process`、`data:read`、`data:write`、`cache:read`、`cache:write`、`notify:publish`、`wayline:generate`、`screenshot:signurl`、`screenshot:issueupload`

- 写进 `allowlist` 的名字必须真实存在；申报了授不出的名字，**整个插件进程起不来**。
- `log` 无需申报，永远可用。
- 只读判定脚本永远没有能力（注入面恒空）。

## 全局对象总表

「可用路线」：HTTP = HTTP 接口处理函数；事件 = 事件消费脚本；流程 = 流程脚本（`run_script`）。

三路（HTTP、事件、流程脚本）共用按有效 `allowlist` 注入的方法。`evaluators` 是第四种脚本入口，但注入面恒空，只能使用 `log`，不在下表中。流程脚本的非空 `scripts[].allowlist` 覆盖包级列表；为空或未写时回落到包级。**注入不代表部署的能力提供方可用**，方法存在仍可能在调用点报未装配或返回 `skipped`，具体按方法签名处理。

| 全局对象 | 方法 | 所需权限 | 可用路线 |
| --- | --- | --- | --- |
| `log` | `info / warn / error(message, fields?)` | 无需申报 | 三路都有 |
| `platform` | `getConfig()`（返回含 connectorId 的配置深拷贝）、`insertEvent(ev)`、`resolveSegment(lat, lng)` | `config:get` / `event:write` / `geo.segment:read` | 三路 |
| `connector` | `invoke(id, payload)`、`fetch({method, url, headers, body, timeoutSec})` → `{status, headers, body}` | `integration:write`、`integration.gis:read`（同走 `invoke`）、`egress:fetch` | 三路 |
| `store` | `query / count / insert / createIfAbsent / update / delete` | `data:read`（query/count）、`data:write`（写入四方法） | 三路 |
| `cache` | `get/set/del/exists/expire/incr/setnx/ttl/mget/getdel/unlock/expireAt/hset/hget/hgetAll/hdel/rpush/lrange/llen/lpop/sadd/smembers/sismember/srem/scard/zadd/zrange/zrangeByScore/zscore/zrem/zcard/zremByScore` | `cache:read`、`cache:write` | 三路 |
| `media` | `get(fileId, workspace?)`、`list(ownerType, ownerId)`（读）；`attach / ensureFolder / move / rename`（写） | `media:read` / `media:write` | 三路 |
| `flow` | `start(flowName, bizId, seed)` → `{already}`；只能启动**本插件**的作业流程 | `flow:start` | 三路按权限白名单 |
| `notify` | `publish({channel, to, bizCode, subCode, data})` → `{delivered, skipped, skipReason, failReason}` | `notify:publish` | 三路按权限白名单 |
| `wayline` | `generate({name, projectId, globalSpeed, waypointSpeed, waypoints[]})` → `{waylineUuid, objectKey, name, waypointCount}` | `wayline:generate` | 三路按权限白名单 |
| `screenshot` | `signUrl(objectKey)`；`issueUpload({routeId, waypointId})` → STS 三件套 | `screenshot:signurl` / `screenshot:issueupload` | 三路按权限白名单 |
| `objectTrack` | `inspect(ref, window)`、`getTrack(q)` | `track:read` | 三路按权限白名单 |
| `video` | `probe / extractFrames / createClip` | `video:process` | 三路按权限白名单 |

重耗时的视频处理建议交给流程作业，这是超时与重试设计建议，不是路线硬隔离；流程脚本获得 `flow.start` 后的递归和重试副作用仍需评审。

## 关键签名

```ts
// 受管出网（egress:fetch）
connector.fetch({
  method?: string,        // 空按 GET
  url: string,            // 绝对 URL
  headers?: Record<string, string>,
  body?: string | object,
  timeoutSec?: number,
}): {status: number; headers: Record<string, string>; body: string}

// 轨迹（track:read，三路按权限白名单注入）
objectTrack.inspect({fileId, objectKey}, {rawStartMs, rawEndMs})
  : {firstFrameNo, lastFrameNo, fps, durationMs, startWallClockMs}
objectTrack.getTrack({fileId, objectKey, objectId, fromMs, toMs, fps})
  : {samples: Array<{frameNo, offsetMs, x, y, w, h}>, durationMs}

// 视频（video:process，三路按权限白名单注入）
video.probe({fileId, objectKey}): {durationMs, width, height, fps, keyframeIntervalMs}
video.extractFrames(ref, atMs[], owner): Array<{atMs, fileId, skipped, skipReason}>
video.createClip(ref, startMs, endMs, owner): {fileId, actualStartMs, actualEndMs, durationMs, …}

// 媒体
media.get(fileId, workspace?): {fileId, fileName, fileType, subFileType, shotAtMs, previewUrl, originalUrl, urlExpiresInSec}
media.ensureFolder(ownerType, ownerId, displayName, parentId?, workspace?)
  : {folderId, parentId, created, skipped, skipReason}
media.move(fileId, folderId, workspace?): {moved, skipped, skipReason}
media.rename(fileId, name, workspace?): {renamed, skipped, skipReason}

// 通知
notify.publish({
  channel: 'project'|'organization'|'user_web'|'user_app'|'device'|'server',
  to: string | string[], bizCode: string, subCode: string, data: object,
}): {delivered, skipped, skipReason, failReason}
```

注意点：

- 轨迹坐标是 `[0,1]` 归一化值；FPS 必须来自 `video.probe`，不要假设 30。
- 媒体 URL 自带短期凭据，**不能**写进日志、数据库或流程历史。
- Media 逐方法可用性不同：`list` 当前不可用，`attach` 是空壳；`get`、`ensureFolder`、`move`、`rename` 在媒体能力配置后接真，写侧还依赖部署配置和 `workspace`。`rename.name` 只给显示名，不带扩展名。
- `notify.publish` 的 `delivered` 只表示下游服务收下，不表示前端已显示；未配置通知渠道时 `skipped=true`。通知不是权威通道，不要据此回滚业务。
- `cache` 的 key 是所有插件共享的空间，平台**不**加插件前缀；`store` 的物理表名同样全局统一为 `plugin_db_<entity>`，跨插件同名实体在装载 / 合并时拒绝。不要把两者理解成运行时自动按插件加前缀。

## 返回与错误

- `store` 方法返回 `{ok:true,data}` 或 `{ok:false,error:{code,message}}`，需检查 `ok`，见[数据存储 API](./50.data-store-api.md)。
- `cache` 的具体返回与错误通道请逐方法查工程生成的 `types/`，不从全局对象名称推断统一信封或统一抛错行为。
- `flow.start` 返回 `{already}`，错误以异常传递；`already=true` 不是失败。`connector.fetch` 返回 `{status,headers,body}`；`connector.invoke` 返回 boolean，不能读它们的 `.ok/.data`。
- 媒体、轨迹、视频和截图方法分别返回其签名声明的对象、数组或字符串；错误与 `skipped` 按各方法处理。`notify.publish` 返回 `{delivered,skipped,skipReason,failReason}`，不能把 `delivered=false` 一律等同于抛错。

HTTP 接口处理函数、事件入口和流程脚本**必须返回对象**，无业务输出通常返回 `{}`。事件入口顶层返回 `{ok:false,error:{code,message}}` 会按 `error.code` 分类消息处置；HTTP 接口处理函数和流程脚本**不自动提升返回的失败信封**，操作失败需要让调用失败时必须显式 `throw result.error`。

## 硬隔离

飞行与裸设备操作（下发任务、返航等）**从不**注入脚本——即使权限白名单写了也不会有对应对象。这类操作只能用流程受控步 `dispatch_mission`、`return_home` 等，见[流程编排语言](./60.workflow-dsl.md)。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `store is not defined` | `allowlist` 没申报 `data:read`/`data:write`；缺申报的对象不会注入，也不会报「未授权」 |
| 进程起不来，报能力名问题 | `allowlist` 里写了拼错或不存在的权限名 |
| 想在 HTTP 接口处理函数里处理视频 | 三路都按 `track:read` / `video:process` 注入；重活建议用作业流程，并另行确认部署的能力提供方可用 |
| 想直接下发飞行任务 | 脚本做不到（硬隔离）；改用流程受控步 |
| `connector.invoke` 不生效 | 确认申报的权限：`integration:write` 与 `integration.gis:read` 走同一个函数但语义不同 |
