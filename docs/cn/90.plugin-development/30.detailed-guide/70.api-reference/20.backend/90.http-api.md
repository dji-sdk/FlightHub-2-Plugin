# 后端 HTTP API

本页列出已部署后端服务的流程启动、信号投递、状态查询和 HTTP 接口处理函数调用接口。直接访问该服务时，使用接入配置提供的地址与有效访问凭据，按 `Authorization: Bearer <token>` 鉴权。

该服务凭据与前端插件网关的插件 Token 不同。插件前端通过 `ctx.apiCall()` 调用，由平台处理鉴权；`build` / `pack` 不启动这里的服务，本地 `dev` 的 HTTP 模拟器也不执行完整流程。

## 响应格式（信封）

```json
{"code": 0, "message": "success", "data": {}}
```

- 成功判据：HTTP 2xx **且** `code === 0`。
- 失败响应没有 `data` 键。
- `code: 20001` 是业务结果（如查无记录）：HTTP 200 但**不是**成功。

## 路由

| 方法与路径 | 请求体 | 成功数据 | 说明 |
| --- | --- | --- | --- |
| `POST /flows/{flowName}/start` | `{bizId?, correlationId?, trigger?}` | `{workflowId, already}` | 仅声明了 `trigger.api` 的流程；幂等 ID 优先级 `bizId > trigger.incidentId > correlationId` |
| `POST /flows/{flowName}/incidents/{bizId}/start` | `{bizId?, correlationId?, trigger?}` | `{workflowId, already}` | 同上的按业务 ID 寻址形式（`bizId` 放在路径里，与上一条等价） |
| `POST /workflows/{id}/signals/{signal}` | `{by?, payload?}` | `{}` | 按完整流程实例 ID 投递信号 |
| `GET /workflows/{id}/status` | 无 | `StatusView` | 按完整 ID 查询 |
| `POST /flows/{flowName}/incidents/{bizId}/signals/{signal}` | `{by?, payload?}` | `{}` | 服务端拼 `<flowName>-<bizId>` |
| `GET /flows/{flowName}/incidents/{bizId}/status` | 无 | `StatusView` | 同上 |
| `POST /plugin/invoke` | `{pluginId, handler, input}` | HTTP 接口处理函数返回对象 | 调插件 HTTP 接口，见[HTTP 接口](./20.handler-api.md) |

`StatusView` 表示**编排进度**，不是业务状态：

```ts
interface StatusView {
  flow: string           // 流程名
  currentStep: string    // 当前步骤
  executed: string[]     // 已执行的步骤
  skipped: string[]      // 被跳过的步骤
  awaitingSignal: string // 正在等待的信号（无则空）
}
```

## 示例

```http
POST /flows/accident-response/incidents/INC-1/start
Authorization: Bearer <token>
Content-Type: application/json

{"bizId": "INC-1", "correlationId": "trace-1", "trigger": {"projectUuid": "p-1"}}
```

```http
POST /flows/accident-response/incidents/INC-1/signals/route_selected
Authorization: Bearer <token>
Idempotency-Key: action-001
Content-Type: application/json

{"by": "user-1", "payload": {"waylineUuid": "w-1", "dockSn": "d-1", "projectUuid": "p-1"}}
```

- 重复启动同一业务 ID 返回 `code: 0`、`already: true`。
- 路径中的 signal 名覆盖 body 同名字段；调用方不提供幂等键时，服务端按「信号名 + payload 摘要」生成，同内容会被视为同一次投递。
- 信号投递结果未知（`50401`）时：用相同 `Idempotency-Key` 重试，或先查 `awaitingSignal`。

## 业务码总表

| HTTP | 业务码 | 含义 | 调用方动作 |
| ---: | ---: | --- | --- |
| 200 | `0` | 成功 | 读 `data` |
| 200 | `20001` | 插件业务结果（如 `NOT_FOUND`） | 不是成功；按业务处理，不要盲目重试 |
| 400 | `40001` | JSON / 参数或业务 ID 非法 | 修改请求 |
| 400 | `40002`–`40005` | 信号校验失败（未声明的信号、缺信号数据键、类型错、多余键） | 按流程 `await` 声明修正 |
| 400 | `40006` | 插件契约错 | 改参数或修脚本，不要重试 |
| 401 | `40101` | 未授权（token 缺失或错误） | 重新取得凭据；不要把 token 写进日志 |
| 403 | `40301` | 流程存在但未声明 `api` 触发器 | 改用允许的触发方式 |
| 404 | `40401` | 流程不存在 | 核对流程名 |
| 404 | `40402` | 流程实例不存在 | 核对完整实例 ID |
| 405 | `40501` | HTTP 方法错误 | 按响应 `Allow` 头改方法 |
| 409 | `40901`–`40903` | 信号校验失败（当前未等待、信号越界、重复信号） | 查询 `awaitingSignal` 后再投递 |
| 500 | `50001` | 工作流引擎调用失败 | 按幂等性决定是否重试 |
| 503 | `50301` | 插件暂不可用（可重试错误 / 超时） | 带稳定幂等键退避重试 |
| 504 | `50401` | 信号投递超时 | 结果未知；用相同幂等键重试或先查状态 |

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 返回 200 但拿不到数据 | `code` 是 `20001` 业务结果；先看 `message`，再查业务状态 |
| 启动返回 `already: true` | 同一业务 ID 已启动过（含已结束的流程）；这是幂等行为不是错误 |
| 信号投递后流程没反应 | 用 `GET .../status` 看 `awaitingSignal`；对照流程 `await` 声明的信号名和信号数据键 |
| `50401` 后要不要重投 | 结果未知；用相同幂等键重试是安全的，先查状态更稳 |
