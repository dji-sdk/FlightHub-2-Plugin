# 能力可用性矩阵

这一页是前后端共同的可用性入口：前端按驾驶舱/计划/项目/消息宿主列出扩展点与能力，后端按 HTTP、事件回调和流程脚本列出全局对象与注入权限。两套运行环境、权限与调用方式不能混用，先看[功能总览](./00.index.md)选择路线，再查这里的矩阵；登记提供或按权限注入都不承诺目标部署环境运行可用。

前端使用规则（详见[宿主、扩展点与能力](../10.concepts/30.host-and-capability-model.md)）：

- 扩展点写进清单 `extensions`，不是权限。
- 能力先在清单 `permissions` 声明，再用 `await ctx.capabilities.get(id)` 获取，**每次判空**。
- 4 个基础能力（HTTP/事件/WebSocket/存储）不经过 `get()`，直接用 `ctx.apiCall`、`ctx.events`、`ctx.ws`、`ctx.storage`/`ctx.blobs`。
- 能力和句柄绑定当前插件实例，不能跨宿主保存；不再使用的资源尽早释放。地图就绪、项目/设备权限、同源上传等运行条件由宿主决定，不是插件可切换的配置。
- 当前目录不支持 `platform:paas-event`、`message:alert-popups` 这两个能力权限；`message.alert-popups`（点号）仍是合法扩展点，写在 `extensions`，不要混写到 `permissions`。

后端使用规则（详见[ctx 与能力注入](../20.development/20.backend/40.context-and-allowlist.md)）：

- 能力按有效 `allowlist` 注入全局对象方法，不走前端 `ctx.capabilities.get()`，后端 `ctx` 只提供调用事实。
- HTTP/事件用包级 `allowlist`；流程脚本非空 `scripts[].allowlist` 覆盖包级，为空或未写则回落包级。注入后仍需按具体方法处理未装配、返回状态与错误。
- 飞行控制只能走流程平台受控步；资源租约 `lease:*` 仍在规划中，暂不可申报或调用。

## 后端能力：19 个权限名

后端插件的能力是 allowlist 注入的全局对象，与前端 `capabilities.get()` 是两套体系。HTTP、事件和流程适配器三路按有效 allowlist 注入，下面的标记只说明注入范围，不承诺部署的能力提供方可用：

| 全局对象 | 权限 | HTTP/事件回调 | 流程脚本 |
| --- | --- | --- | --- |
| `log` | 无需申报 | ✅ | ✅ |
| `platform`（getConfig / insertEvent / resolveSegment） | `config:get` / `event:write` / `geo.segment:read` | ✅ | ✅ |
| `connector`（invoke / fetch） | `integration:write` / `integration.gis:read` / `egress:fetch` | ✅ | ✅ |
| `store` | `data:read` / `data:write` | ✅ | ✅ |

- 资源租约（`lease:*`）在规划中，暂不可用，申报会被装载拒绝（见 [资源租约](./60.backend-capabilities/70.resource-lease.md)）。
- 下发任务、返航等飞行操作不面向脚本，只能走流程受控步。
- 重耗时处理建议放在作业流程里，不能把该建议当作 HTTP/事件禁止注入或流程递归隔离保证。
- 各能力详表见[后端能力总览](./60.backend-capabilities/10.overview.md)。

## 上线前自查清单

1. **安装期**：清单里的权限、扩展点静态字段通过校验。
2. **激活期**：每次 `capabilities.get()` 都处理了 `undefined`；扩展点在目标宿主真实存在。
3. **运行期**：对状态可空、设备不可用、控制权缺失都写了降级分支。
4. **命令后**：用遥测/飞行任务/后端查询确认终态，不只断言 Promise 返回。
5. **销毁期**：主动释放高频订阅和句柄，离开宿主后无残留回调。
