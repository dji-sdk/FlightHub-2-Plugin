# 能力地图

插件能力分两套运行环境：前端在页面宿主里扩展界面和调用宿主能力；后端在服务端 Worker 里提供接口、处理事件、编排流程并调用平台服务。先选运行侧，再读对应专题；完整可用性表只维护在[能力可用性矩阵](./70.capability-availability.md)。

## 前端能力

| 分组 | 适用场景 |
| --- | --- |
| [平台通用能力](./10.frontend/10.platform/00.index.md) | HTTP、事件、WebSocket、存储，以及地图、弹窗、设备、航线等跨宿主功能 |
| [项目宿主](./10.frontend/20.project/00.index.md) | 项目侧边栏入口、插件路由、工作区与项目上下文 |
| [消息宿主](./10.frontend/30.message/00.index.md) | 告警卡片、导航与通知 |
| [计划库宿主](./10.frontend/40.plan/00.index.md) | 计划表单上下文、扩展、校验与提交 |
| [驾驶舱](./10.frontend/50.cockpit/00.index.md) | 工具栏与面板、直播、遥测、相机、飞控与任务交互 |

前端使用规则：

1. 只声明[扩展点目录](../70.api-reference/10.frontend/30.extension-point-catalog.md)中的 ID。静态字段写 `extensions`，运行时状态和回调用 `ctx.extensions.contribute()` 提交。
2. 按需声明 `permissions`，每次 `get()` 后处理 `undefined`。四个基础能力直接用 `ctx.apiCall`、`ctx.events`、`ctx.ws`、`ctx.storage` / `ctx.blobs`；界面通过契约方法向入口取数据。
3. 能力客户端、订阅和句柄绑定当前插件实例，不跨宿主保存或传递；宿主卸载会统一回收资源。
4. 多宿主插件用 `ctx.host.id` 区分场景，缺能力时隐藏或降级。以目标环境真实页面验证，不把本地模拟当作可用性承诺。

## 后端能力

| 专题 | 适用场景 |
| --- | --- |
| [后端能力总览](./60.backend-capabilities/10.overview.md) | 全局对象、权限声明与 HTTP/事件/流程三条代码路线 |
| [配置、受管出网与集成连接](./60.backend-capabilities/20.config-egress-integration.md) | 读取连接配置、受管出网、调用平台连接器 |
| [事件与流程](./60.backend-capabilities/30.event-flow.md) | 订阅媒体事件、写事件模型、更新状态与启动作业 |
| [飞行任务与违停巡逻](./60.backend-capabilities/40.flight-task-patrol.md) | 通过流程平台受控步完成下发任务、返航等操作 |
| [数据存储](./60.backend-capabilities/50.data-store.md) | `store` 与 `cache` 的使用边界和选型 |
| [媒体与前端通知](./60.backend-capabilities/60.media-notification.md) | 媒体读写与向前端投递通知 |
| [资源租约（规划中）](./60.backend-capabilities/70.resource-lease.md) | 暂不可用，不能申报 `lease:*` 或调用提案 API |
| [作业、目标轨迹与视频处理](./60.backend-capabilities/80.job-trajectory-video.md) | 作业流程与轨迹、视频处理能力的组合 |

后端按需申报有效 `allowlist`，未申报的能力方法不会注入，申报平台授不出的权限会被装载拒绝。流程脚本非空 `scripts[].allowlist` 覆盖包级，否则回落包级；后端 `ctx` 只提供本次调用事实，不提供能力方法。重耗时处理建议放在作业流程中，但这不构成路线隔离；调用需处理幂等、超时、重试副作用与具体返回形态。

## 怎么选

- 只改页面和交互：从前端能力开始。
- 只提供接口、事件或流程：从后端能力开始。
- 两者都要：先确认前端调用哪个后端插件 ID，再看[前后端协作](../20.development/30.fullstack/00.index.md)。

完整权限、扩展点和能力数量以[能力可用性矩阵](./70.capability-availability.md)为准，本页不重复维护第二份表。
