# 项目侧边栏入口

`project.sidebar-actions` 让插件在项目页左侧导航加一个入口：点击后进入插件自己的页面，还可以同时占据右侧主工作区。这是扩展点，在清单 `extensions` 里声明（不需要额外权限），运行时用 `ctx.extensions.contribute()` 提交具体内容。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## 字段清单

字段分两层：**静态配置写清单**，**运行时状态和回调在代码里提交**。把运行时字段写进清单会被校验拒绝。

| 字段 | 层 | 说明 |
| --- | --- | --- |
| `path` | 清单，必填 | 项目路由中的插件路径，如 `/incident-center` |
| `position` | 清单，可选 | 插到第 N 个原生项之前；缺省或越界时追加到尾部 |
| `icon` | 代码，必填 | 图标 ID，需在清单 `contributes.icons` 中声明 |
| `label` | 代码，必填 | 展开态标题与收起态 tooltip |
| `disabled` | 代码，默认 `false` | 禁止点击 |
| `showBadge` | 代码，默认 `false` | 右上角红色呼吸点 |
| `render()` | 代码，必填 | 返回左侧插件路由页的界面 |
| `renderWorkspace()` | 代码，可选 | 路由激活时同时挂到右侧主工作区的界面，见 [工作区](./40.workspace.md) |

`path` 和 `position` 装后不可改；运行期只能用 `contribution.update({ icon/label/disabled/showBadge })` 更新。`render`、`renderWorkspace` 也不能通过 update 替换。

`position` 说明：它匹配的是当前原生菜单项的位置，插件之间保持声明顺序。不要把某个数字长期当成固定业务菜单名。

## 可照抄示例

`fh2-plugin.json`：

```json
{
  "id": "exp_incident_center",
  "name": "事件中心",
  "version": "1.0.0",
  "entry": "./plugin.js",
  "permissions": ["project:context"],
  "extensions": [
    {
      "id": "incident-entry",
      "point": "project.sidebar-actions",
      "path": "/incident-center",
      "position": 1
    }
  ],
  "views": {
    "incident-panel": { "entry": "./views/incident-panel.js" },
    "incident-map": { "entry": "./views/incident-map.js" }
  },
  "contributes": {
    "icons": [
      { "id": "incident", "src": "./static/icons/incident.svg" }
    ]
  }
}
```

```ts
// plugin.ts
import {
  createViewState,
  definePlugin,
  definePluginView,
} from 'fh2-plugin-sdk'

interface IncidentState {
  readonly unread: number
  readonly selectedId: string | null
}
interface IncidentViewContract {
  state: IncidentState
  methods: { select(input: { id: string }): void }
}

const panelView = definePluginView<IncidentViewContract>('incident-panel')
const mapView = definePluginView<IncidentViewContract>('incident-map')

export default definePlugin({
  async activate (ctx) {
    if (ctx.host.id !== 'project') return
    const state = createViewState<IncidentState>({ unread: 3, selectedId: null })
    const session = {
      state,
      methods: {
        select: ({ id }: { id: string }) => {
          state.update(current => ({ ...current, selectedId: id }))
        },
      },
    }
    await panelView.handle(ctx, session)
    await mapView.handle(ctx, session)

    const contribution = await ctx.extensions.contribute('incident-entry', {
      icon: 'incident',
      label: '事件中心',
      disabled: false,
      showBadge: true,
      render: () => panelView.get(ctx),
      // 可省略；它不是单独的扩展点。
      renderWorkspace: () => mapView.get(ctx),
    })

    async function markAllRead () {
      state.update(current => ({ ...current, unread: 0 }))
      await contribution.update({ showBadge: false })
    }
    ctx.logger.debug('全部已读动作就绪', { callable: typeof markAllRead === 'function' })
  },
})
```

## 注意事项

- 点击 `disabled` 的入口不会导航；当前路径等于 `path` 或以 `path + '/'` 开头时入口显示为激活态。
- `render()` 返回的界面挂在左侧插件路由页里，离开路由或扩展消失时销毁。
- 宿主卸载时插件运行时会回收扩展句柄；不再需要入口时可提前 `dispose()`。
- 使用专属 `path`：以 `/` 开头、不与原生路径（如 `/team`、`/plan`）和其他插件冲突。当前没有统一的 path 冲突仲裁。
- `position` 用非负整数或省略；负数匹配不到插入位置，入口不会显示。
- 图标解析失败时显示空占位。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 入口不显示 | `position` 为负数、图标未声明，或宿主未成功挂载 |
| 入口重复出现 | 用同一扩展 ID 重复 `contribute`；先 `dispose()` 旧句柄 |
| 想改 `path` | `path` 是静态配置，改清单后重新构建安装 |
| 右侧工作区没出现 | `renderWorkspace` 只随插件路由激活；且依赖宿主注入工作区桥接，缺失时静默降级，左侧页面不受影响 |
