# 计划库表单上下文

`plan:form-context` 让插件读取当前计划表单的快照：处于哪种模式（新建/复制/编辑）、什么计划类型、用户填了什么。它是**只读**的——插件不能通过它修改表单。清单声明 `plan:form-context` 权限，代码里 `await ctx.capabilities.get('plan:form-context')` 获取并判空。只在计划宿主可用。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## 方法清单

| 方法 | 说明 |
| --- | --- |
| `getState()` | 返回当前快照 |
| `onStateChanged(handler)` | 订阅变化；返回可释放句柄 |

状态是判别联合：

```ts
type PlanFormContextState =
  | {
      available: false
      revision: number
    }
  | {
      available: true
      revision: number
      projectId: string
      mode: 'create' | 'copy' | 'edit'
        | 'airport-test' | 'workflow-create' | 'workflow-edit'
      planType: 'normal' | 'atob' | 'manual'
      isMultiWayline: boolean
      formInstanceId?: string
      draft: Record<string, PluginValue>
      sourceBizExt?: Record<string, PluginValue>
    }
```

字段说明：

- `draft` 来自当前表单数据：时间字段已转成 Unix 秒，函数和 `undefined` 被剔除，并做了跨环境安全的深拷贝。
- 快照内容变化时 `revision` 递增；相同内容不会重复通知。
- `formInstanceId` 标识一次表单生命周期：表单重建后会产生新值，插件应据此重置"用户是否手动改过开关"这类局部状态。
- `sourceBizExt` 只在 copy 模式提供，是被复制任务的原始 `biz_ext`，仅用于初始化插件界面，**不会**自动进入新任务的提交体。edit 模式中原始 `biz_ext` 在 `draft.biz_ext`，宿主提交时会原样保留。
- 表单卸载或草稿构建失败时进入 `available: false`，不要把它误判成"用户关闭了功能"。

## 集成片段

先按[第一个前端插件](../../../20.development/40.hands-on/20.first-frontend-plugin.md)建立可运行工程，再按[计划表单扩展](./20.form-extensions.md)接入计划宿主。下面不是完整的 `fh2-plugin.json`，不可整份替换：将 `permissions` 去重合并到现有清单，保留现有计划宿主扩展、界面声明/注册和入口。权限不会触发激活；清单若只有 `extensions: []`，`activate()` 不会执行。

合并到 `fh2-plugin.json` 的字段：

```json
{
  "permissions": ["plan:form-context"]
}
```

下面的 `definePlugin` 只示范入口逻辑组织，不是可直接替换完整工程的入口；保留生成工程的 SDK 导入路径，将快照同步逻辑合入已有计划宿主的 `activate` 和业务收尾，保留表单扩展贡献与界面注册。

```ts
// plugin.ts
import { definePlugin } from 'fh2-plugin-sdk'
import type { PlanFormContextState } from 'fh2-plugin-sdk'

const BIZ_KEY = 'quality-inspection'

export default definePlugin({
  async activate (ctx) {
    if (ctx.host.id !== 'plan') return
    const formContext = await ctx.capabilities.get('plan:form-context')
    if (!formContext) {
      ctx.logger.warn('plan:form-context 不可用')
      return
    }

    let formInstanceId = ''
    let enabled = false
    function apply (next: PlanFormContextState) {
      if (!next.available) {
        enabled = false
        return
      }
      if (next.formInstanceId && next.formInstanceId !== formInstanceId) {
        formInstanceId = next.formInstanceId
        enabled = Boolean(next.sourceBizExt && BIZ_KEY in next.sourceBizExt)
      }
      ctx.logger.debug('计划表单快照', {
        revision: next.revision,
        mode: next.mode,
        planType: next.planType,
        isMultiWayline: next.isMultiWayline,
        enabled,
      })
    }

    apply(await formContext.getState())
    const subscription = await formContext.onStateChanged(apply)
    return {
      async dispose () {
        await subscription.dispose()
      },
    }
  },
})
```

## 注意事项

- 用户填表时快照会高频变化：回调里只做纯状态同步，网络请求留到显式操作或提交阶段。
- 上下文不提供写接口；插件界面自己维护扩展状态，改不了原生表单字段。
- 其他宿主即使声明权限，`get()` 也是 `undefined`。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 拿到的时间不是预期格式 | 时间字段是 Unix 秒，不是字符串或 Dayjs 对象 |
| `available` 变成 `false` | 表单卸载或草稿构建失败；订阅释放后不再更新 |
| 复制计划时开关状态没带过来 | `sourceBizExt` 只用于恢复界面初始状态，提交时要靠你的 `onSubmit` 重新写入 |
| 表单重建后状态错乱 | 监听 `formInstanceId` 变化，重置插件局部状态 |
