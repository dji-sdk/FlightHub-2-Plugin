# 上下文与遥测

这一页讲两个只读状态能力：`cockpit:context`（当前页面上下文）和 `cockpit:telemetry`（设备遥测快照）。做任何驾驶舱业务，第一步通常就是读它们做门控——比如"没有项目 ID 就不启用按钮""没有飞行控制权就禁用操作"。

两个能力都在清单里声明同名权限，用 `ctx.capabilities.get()` 获取，`undefined` 表示当前拿不到（未授权或宿主未提供），要判空。

## cockpit:context：我在哪个页面、哪些东西就绪了

### 契约字段

```ts
interface CockpitContextState {
  organizationId: string | null
  projectId: string | null
  droneSn: string | null
  gatewaySn: string | null
  alertExecutionId: string | null
  liveReady: boolean
  flightId?: string | null
}

getState(): CockpitContextState
onStateChanged(handler: (state: CockpitContextState) => void): Disposable
```

### 字段从哪来

- `organizationId/projectId` 来自路由参数；`droneSn/gatewaySn/alertExecutionId` 来自路由 query 的 `droneSn/gatewaySn/alertId`。
- 路由里缺的值会表现为空字符串——**把 `null` 和空字符串都当"缺失"处理**。
- `flightId` 来自驾驶舱 SDK 的飞行任务状态，不来自路由；未起飞时可能是 `null`。
- `liveReady` 表示"至少一路直播已出首帧"。判定规则：
  - `first-frame` 事件把流加进就绪集合；`stopped` 和换通道把流移出；
  - 插件激活前就已经在播的流会被回填为 ready，不会错过。

### 示例：直播和设备就绪才启用按钮

```ts
const cockpitContext = await ctx.capabilities.get('cockpit:context')
if (!cockpitContext) return

let current = await cockpitContext.getState()
const sub = await cockpitContext.onStateChanged((next) => {
  current = next
  const usable = Boolean(next.projectId && next.droneSn && next.gatewaySn && next.liveReady)
  void toolbar.update({ disabled: !usable })
})

// 用完可以主动释放；宿主卸载时插件运行时也会回收
await sub.dispose()
```

### 注意

- 上下文本身只读，不下发任何命令。
- 只切换告警（`alertId`）时宿主不重建，只是状态更新；组织、项目、飞机或网关变化会重建整个宿主，旧订阅不再回调。
- 上下文缺字段不会阻止宿主建立，业务入口要不要启用由你自己决定。

## cockpit:telemetry：设备现在的状态

### 契约总形状

```ts
interface TelemetryState {
  device: CockpitDeviceState
  drone: CockpitDroneState
  dock: CockpitDockState
  payload: CockpitPayloadState
  control: CockpitControlState
}

onStateChanged(handler: (event: {
  source: 'device' | 'drone' | 'dock' | 'payload.camera' |
    'payload.gimbal' | 'payload.laser' | 'control'
  state: TelemetryState
}) => void): Disposable
```

`onStateChanged` 每次都给**完整快照**，`source` 只是标出这次是哪个域变了。不要把它当作增量变更数据使用，事实要从 `event.state` 里读。

### 字段一览

| 分组 | 字段 |
| --- | --- |
| `device.roster` | `droneSn/gatewaySn/dockSn/baseStationSn/rcSn`（可 null）、`gatewayType: base_station\|dock\|rc\|unknown`、`isNetworked`；整个 roster 可为 null |
| `drone.pose` | `source: drc\|ws`、经纬高、`elevation`、`attitude_head`、`horizontal_speed`、`vertical_speed`、`home_distance`，均可 null；整个 pose 可为 null |
| `drone.mode` | `{ source, mode_code }`，可 null |
| `drone.link` | `drcReady`、`timeDiffDeviceAndWeb` |
| `drone.timestamp` | 飞机侧 Unix 毫秒，只来自云端物模型；无数据为 null |
| `dock.status` | 机场模式、舱盖、推杆、飞机在舱、急停、告警状态（可 null） |
| `dock.position` | 机场经纬高（可 null） |
| `dock.environment` | 雨量、风速、温度、湿度（可 null） |
| `payload.camera` | `camera_index`、`camera_mode`、`photo_state`、`recording_state`、`record_time`、`zoom_factor`、`remain_photo_num`、`remain_record_duration`、`lens: wide\|zoom\|null`；可 null |
| `payload.gimbal` | `pitch/yaw/roll`（可 null）、`locked` |
| `payload.laser` | 激光点的经纬高和距离（可 null） |
| `control.flight` | `hasControl`、`ownerUserId` |
| `control.payload` | `hasControl`、`ownerUserId` |

状态变化来源（`source`）共 7 类：device、drone、dock、payload.camera、payload.gimbal、payload.laser、control。任何一类变化都会推一次全量快照。

### 示例

```ts
const telemetry = await ctx.capabilities.get('cockpit:telemetry')
if (!telemetry) return

const off = await telemetry.onStateChanged(({ source, state }) => {
  if (source === 'control') {
    void action.update({ disabled: !state.control.flight.hasControl })
  }
  if (source === 'payload.laser') {
    const laser = state.payload.laser
    if (laser?.longitude != null && laser.latitude != null && laser.altitude != null) {
      ctx.logger.debug('激光目标更新', laser)
    }
  }
})
```

### 注意：遥测只给事实，不做判断

它不会替你回答这些问题，需要你自己结合业务判断：

- `hasControl` 是否足够执行某个操作（飞行和载荷控制权要分别看）。
- 数字 `mode_code` 的业务含义。
- 激光点是否够新、是否对应当前画面目标。
- 飞机是否在空中、机场是否可派遣。

两个容易踩的坑：

- **`0` 是有效值**，不是空值。坐标、高度、角度、模式码都可能是 0，判断缺失要用 `null`/`undefined`，不要用 falsy 判断。
- 申请控制权的 Promise 返回**不等于**已经持权——要等 `source === 'control'` 且对应 `hasControl` 变成期望值。相机、云台、飞行命令同理。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `liveReady` 一直是 false | 没有任一路直播出首帧；`started` 不算数，`first-frame` 才算 |
| 状态里字段"消失了" | 不会删字段——子状态缺失时是 `null`，按缺失处理 |
| 收到回调但值没变 | 正常：7 路源任一变化都推全量快照，自己比对关心的字段 |
| 控制权申请成功但操作被拒 | Promise 只代表 SDK 调用返回；等 `control.*.hasControl` 到位再发命令 |
