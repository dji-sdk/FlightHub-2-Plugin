# 飞控、云台与任务

这一页覆盖四个"操作类"能力：`cockpit:flight-control`（飞行控制）、`cockpit:gimbal`（云台）、`cockpit:flight-task`（飞行任务）、`cockpit:hotkeys`（快捷键）。

先记住一条总原则：**命令被接受 ≠ 动作已完成**。飞行安全相关的每个命令，都要靠订阅状态（遥测/飞行任务/平台事件）来确认终态。

## cockpit:flight-control：控制权与飞行命令

### 方法

```ts
acquireControl(type?: 'flight' | 'payload' | 'all'): Promise<void>   // 缺省 all
releaseControl(): Promise<void>
flyTo(points: readonly GeoPoint[], options?: { maxSpeed?: number }): Promise<void>
emergencyStop(): Promise<void>
returnHome(): Promise<void>
returnHomeCancel(): Promise<void>
```

### 每个 resolve 的含义

| 方法 | resolve 代表 | 之后还要确认什么 |
| --- | --- | --- |
| `acquireControl` | SDK 调用返回 | 订阅遥测，等 `control.flight/payload.hasControl` 为 true |
| `releaseControl` | SDK 调用返回 | 等对应 `hasControl=false` |
| `flyTo` | 后端接口受理（走的是后端飞行任务接口，不是 SDK） | 用 `cockpit:flight-task` 或业务任务状态确认执行和终态 |
| `emergencyStop` | SDK 报告急停已触发/受理 | `cockpit.emergency-stop` 事件也只到这一步，设备最终停止要看状态 |
| `returnHome` / `returnHomeCancel` | SDK 调用返回 | 继续观察任务与飞行状态 |

### flyTo 的细节

- 起点（飞机当前位置）由宿主从实时遥测读取，你不能传入过期起点；飞机实时位置不可用时抛错。
- `maxSpeed` 缺省 14（m/s）。
- 当前实现没有对项目/网关缺失做本地预检，空值会直接进请求由后端拒绝——**先用 `cockpit:context` 做好门控**。
- 宿主卸载会取消在途的 flyTo 请求；但已被后端/设备接受的动作不会被自动回滚。

### 示例

```ts
const flight = await ctx.capabilities.get('cockpit:flight-control')
const telemetry = await ctx.capabilities.get('cockpit:telemetry')
if (!flight || !telemetry) return

await flight.acquireControl('flight')
// 轮询等待真正持权（伪代码 waitUntil）
const controlReady = await waitUntil(async () => (await telemetry.getState()).control.flight.hasControl)
if (!controlReady) throw new Error('未取得飞行控制权')

await flight.flyTo([{ lng: 113.9, lat: 22.5, height: 80 }], { maxSpeed: 10 })
// 这里只是请求被受理；继续用 cockpit:flight-task 判断运行和终态
```

## cockpit:gimbal：云台

### 方法

```ts
reset(mode?: 'all' | 'yaw' | 'down'): Promise<void>   // 缺省 down
lookAt(
  point: VideoPoint | GeoPoint,
  options?: { videoType?: 'normal' | 'wide' | 'zoom' | 'ir' | 'thermal'; locked?: boolean },
): Promise<void>
```

`lookAt` 按传入坐标类型走两条不同的真实链路：

| 传入 | 走哪条路 | 说明 |
| --- | --- | --- |
| `VideoPoint {x,y}` | 驾驶舱 SDK 的云台方法 | `videoType`、`locked` 由 SDK 处理 |
| `GeoPoint {lng,lat,height}` | 后端"相机注视"接口 | `locked` 缺省 true；`videoType` 被忽略；需要当前相机索引（缺失时抛 `CAPABILITY_NOT_AVAILABLE`） |

命令 Promise 不等待云台姿态到位。需要确认时订阅 `cockpit:telemetry` 的 `payload.gimbal`。

### 示例

```ts
const gimbal = await ctx.capabilities.get('cockpit:gimbal')
const telemetry = await ctx.capabilities.get('cockpit:telemetry')
if (!gimbal || !telemetry) return

if (!(await telemetry.getState()).control.payload.hasControl) return
await gimbal.lookAt({ x: 0.5, y: 0.45 }, { videoType: 'zoom', locked: true })
```

注意：没有 `rotate()` 方法，只有 `reset` 和 `lookAt`。

## cockpit:flight-task：任务状态与即时航线

### 状态

```ts
interface FlightTaskState {
  kind: 'wayline' | 'in-flight-wayline' | null
  flightId: string | null
  wayline: { taskId, status, progressPercent, waylineUuid, taskType,
             completedWaypointCount, totalWaypointCount } | null
  inFlightWayline: { taskId, status, progressPercent, taskName } | null
}
```

- `status` 取值：`pending / running / paused / completed / cancelled / failed / unknown`。
- 普通航线任务和即时航线是**两个独立快照**，互不覆盖；`kind` 只表示当前活动形态（即时航线优先）。
- 无任务或状态未知时对应快照为 `null`。
- 订阅变化：`onStateChanged(handler): Disposable`。

### 即时航线命令

```ts
startInFlightWayline({
  waylineUuid: string
  rthAltitude: number
  taskName: string
  waylineDuration: number
  waylineLength: number
  finishAction: 'goHome'
}): Promise<{ taskId: string }>

cancelInFlightWayline({ taskId: string; afterCancel: 'hover' }): Promise<void>
```

要点：

- `startInFlightWayline` resolve 只表示**任务记录已创建并拿到 taskId**，必须继续订阅状态确认执行。
- 同一前端会话同一时间只允许一个保留中的即时航线；重复 start 会失败并释放占用。
- `cancelInFlightWayline` 的真实语义是"取消当前设备的即时航线"：它不校验传入 `taskId` 的归属，也读取 `afterCancel`；取消命令之后宿主还会追加调用返航取消（结束取消航线后可能进入的机库返航段），两步都成功才 resolve。
- 两个命令都不代表飞机已达最终状态——WS 上报 cancelled/悬停要另外确认。

### 示例

```ts
const tasks = await ctx.capabilities.get('cockpit:flight-task')
if (!tasks) return
const { taskId } = await tasks.startInFlightWayline({
  waylineUuid, rthAltitude: 100, taskName: '沿路网返航',
  waylineDuration: 90, waylineLength: 800, finishAction: 'goHome',
})
const off = await tasks.onStateChanged((state) => {
  if (state.inFlightWayline?.taskId === taskId) renderStatus(state.inFlightWayline.status)
})
```

## cockpit:hotkeys：快捷键

```ts
register({
  key: string
  modifiers?: readonly ('ctrl' | 'alt' | 'meta' | 'shift')[]
  allowInInput?: boolean
  enabled?: boolean
  onTrigger: () => void | Promise<void>
}): Promise<{
  update({ enabled?: boolean }): Promise<void>
  dispose(): Promise<void>
}>
```

快捷键由驾驶舱 SDK 统一仲裁（冲突时宿主决定行为），**不要自己在 document 上挂键盘监听**。

```ts
const hotkeys = await ctx.capabilities.get('cockpit:hotkeys')
if (!hotkeys) return
const captureKey = await hotkeys.register({
  key: 'k', modifiers: ['shift'], allowInInput: false, enabled: true,
  onTrigger: () => captureOnce(),
})
await captureKey.update({ enabled: false })   // 运行时开关
await captureKey.dispose()                     // 用完释放（幂等）
```

注意：回调抛错会显示 3 秒错误通知；宿主卸载时插件运行时会释放你剩余的注册。

## 飞行流程四原则

1. **先状态门控，再发命令**——但门控快照可能立即过期，命令被拒仍要处理。
2. **命令接受不等于最终成功**——控制权看遥测，任务看飞行任务状态，急停事件也不代表设备已停。
3. **超时是未知结果**——先刷新权威状态，再决定要不要重试，不要盲目重发有副作用的命令。
4. **销毁不是飞行补偿**——插件卸载只回收你的订阅和请求，不会替你停止已启动的飞行或返航。

录像不同：录像还是这个插件开的时候，插件被禁用、卸载或改配置，宿主会先尝试停掉这段录像再卸载；只是切走页面不会停。自己调 `stop()` 结束最可控，别依赖卸载来收尾。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `acquireControl` 返回了但操作仍被拒 | 还没真正持权；等遥测的 `hasControl` |
| `flyTo` 报"飞机实时位置不可用" | 遥测里没有有效的飞机位置；等 `drone.pose` 有值再试 |
| `lookAt` 传 GeoPoint 抛 `CAPABILITY_NOT_AVAILABLE` | 当前相机索引缺失；等 `payload.camera.camera_index` 有值 |
| `startInFlightWayline` 成功但飞机没动 | 任务记录创建成功，下发是异步的；订阅状态确认 |
| 想旋转云台 | 没有 `rotate`；用 `reset` / `lookAt` 组合业务 |
