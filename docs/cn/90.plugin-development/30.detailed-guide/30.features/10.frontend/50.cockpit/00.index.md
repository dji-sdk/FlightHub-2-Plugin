# 驾驶舱插件能力总览

驾驶舱是插件能力最丰富的宿主：8 个界面扩展点、12 个 `cockpit:*` 能力、2 个平台事件。这一页是总索引——先弄清"能做什么、怎么拿"，具体字段和示例再看各专题页。

## 8 个扩展点

扩展点是宿主在页面上预留的 UI 位置。插件在清单里声明"我要在这个位置放东西"，宿主负责挂载。

| 扩展点 ID | 界面位置 | 可否 reveal |
| --- | --- | --- |
| `cockpit.ui.toolbar-actions` | 底部工具栏按钮（两个 anchor 位置可选） | 否 |
| `cockpit.ui.menubar` | 菜单栏按钮 | 否 |
| `cockpit.ui.live-overlay` | 直播画面覆盖层（按直播流和层级分组） | 否 |
| `cockpit.ui.left-bottom-panels` | 左下角信息面板栈 | 否 |
| `cockpit.ui.left-panel` | 可切换的左侧面板 | 是 |
| `cockpit.ui.sublive-tab` | 子直播页签 | 是 |
| `cockpit.ui.flight-actions` | 飞控操作区按钮（两个 anchor 位置可选） | 否 |
| `cockpit.ui.live-context-menu` | 直播画面右键菜单 | 否 |

字段全貌和示例见 [驾驶舱扩展点](./10.extension-points.md)。

## 12 个驾驶舱能力

能力是宿主提供给插件调用的功能，权限名与能力 ID 同名。驾驶舱宿主提供以下 12 个能力：

| 能力 ID | 一句话 |
| --- | --- |
| `cockpit:context` | 当前路由上下文：组织、项目、设备 SN、直播是否就绪 |
| `cockpit:telemetry` | 设备、飞机、机场、载荷、控制权的遥测快照 |
| `cockpit:camera` | 相机模式、变焦、拍照、录像、截帧 |
| `cockpit:detection` | AI 检测帧流，以及帧坐标与地面坐标的互投 |
| `cockpit:ai-config` | AI 识别模型与目标类型配置 |
| `cockpit:smart-track` | 智能跟踪（SPZ）的启动与停止 |
| `cockpit:scene-geometry` | 画面坐标与地理坐标的双向投影 |
| `cockpit:live-pointer` | 直播画面指针租约（谁能在画面上响应鼠标） |
| `cockpit:flight-control` | 控制权申请、flyTo、急停、返航 |
| `cockpit:gimbal` | 云台复位与注视 |
| `cockpit:hotkeys` | 注册快捷键 |
| `cockpit:flight-task` | 飞行任务状态与即时航线 |

各能力详见 [上下文与遥测](./20.context-and-telemetry.md)、[相机、检测与 AI](./30.camera-detection-and-ai.md)、[场景几何与直播指针](./40.geometry-and-live-pointer.md)、[飞控、云台与任务](./50.flight-gimbal-and-task.md)。

## 2 个平台事件

平台事件目录是封闭的，当前只有两个，且只有驾驶舱宿主会派发：

| 事件 | 含义 |
| --- | --- |
| `cockpit.live.lifecycle` | 直播生命周期：建联、首帧、停止、换通道 |
| `cockpit.emergency-stop` | 急停被触发或受理 |

详见 [驾驶舱平台事件](./60.live-lifecycle-events.md)。

## 怎么获取能力

统一三步：清单声明权限 → 代码获取 → 判空后使用。

`fh2-plugin.json`：

```json
{ "permissions": ["cockpit:camera", "cockpit:telemetry"] }
```

```ts
// plugin.ts
const camera = await ctx.capabilities.get('cockpit:camera')
if (!camera) {
  ctx.logger.warn('当前宿主未提供 cockpit:camera')
  return
}
const state = await camera.getState()
if (state.availability.status !== 'available') {
  ctx.logger.warn(state.availability.reason ?? '相机暂不可用')
  return
}
```

注意：

- `get()` 返回 `undefined` 是正常情况（未授权、宿主未提供、宿主不匹配都会这样），每次都要判空，不要用非空断言。
- 插件运行时已停止后再取能力会抛 `HOST_RUNTIME_DISPOSED`。
- 4 个基础能力不走 `capabilities.get()`：HTTP 用 `ctx.apiCall`、事件用 `ctx.events`、WebSocket 用 `ctx.ws`、存储用 `ctx.storage` / `ctx.blobs`（权限照常在清单声明）。

## 状态与命令不是一回事

能力方法的 Promise 有三种含义，写业务前先分清：

| 类型 | 例子 | Promise resolve 代表 |
| --- | --- | --- |
| 等到权威状态 | `camera.ensureMode()`、`smartTrack.start()` | 已观察到设备/状态的终态 |
| 命令被接受 | `flightControl.flyTo()`、`emergencyStop()` | 请求已发出并被受理，**不等于动作已完成** |
| 资源已创建 | `livePointer.acquire()`、`camera.acquireRecording()` | 句柄已生效，之后仍可能被宿主或他人撤销 |

所以飞行和任务类业务必须继续订阅 `cockpit:telemetry`、`cockpit:flight-task` 或平台事件来确认最终状态。命令超时意味着"结果未知"，不要直接重发有副作用的命令。

## 坐标与时间约定

- `GeoPoint` 是 `{ lng, lat, height }`。
- `VideoPoint` 和检测框用有效视频画幅内的归一化坐标（0~1），不含黑边。
- `DetectionFrame.capturedAt` 来自 AI SEI 时间，不是浏览器时钟。
- `TelemetryState.drone.timestamp` 是飞机侧 Unix 毫秒时间戳，无上报时为 `null`。
- 直播事件的 `timestamp` 是宿主桥接事件时的 `Date.now()`。

## 宿主什么时候创建和销毁

- 进入项目详情路由的 `#/cockpit` 页面且驾驶舱 SDK 就绪后，宿主才建立，插件才激活。
- 切换告警（`alertId`）只更新 `cockpit:context`；组织、项目、飞机或网关变化会重建整个宿主。
- 离开页面时宿主按顺序回收：停事件桥接 → 撤销扩展和界面 → 释放几何快照等资源 → 卸载。

插件运行时会统一回收插件注册的订阅、定时器和句柄，但逐帧检测、录像句柄、几何快照、指针租约、快捷键这类资源，建议用完尽早显式 `dispose()`。
