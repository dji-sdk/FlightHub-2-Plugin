# 驾驶舱扩展点

驾驶舱有 8 个扩展点，全部支持多个插件同时贡献。这一页按「是什么 → 字段 → 示例 → 注意」逐个讲，看完你就能选对位置、写对清单。

## 先记住三条通用规则

**1. 静态字段写清单，运行时字段写代码。** `anchor`、`stream`、`overlayLevel` 这类安装时就定死的配置写在 `fh2-plugin.json` 的 extension 条目里；`label`、`visible`、`onTrigger` 这类运行时会变的状态和回调，用 `ctx.extensions.contribute(extensionId, implementation)` 提交。把运行时字段写进清单会被校验拒绝。

**2. 多个插件的显示顺序**按 Engine 生成的 PluginPlan 列表顺序；同一插件的多个扩展再按清单里 extension 的声明顺序排列，不由激活先后或 CSS 决定。

**3. 扩展点没有对应权限。** `point` 不是 permission，不需要也不存在同名授权。但回调里如果调能力（比如点击按钮后读遥测），那个能力仍要单独声明权限并判空。

扩展、界面、图标的局部 ID 都要匹配 `^[a-zA-Z0-9][a-zA-Z0-9-]*$`。

按钮类扩展点的 `onTrigger` 都会收到同一个 `ActionContext`：

```ts
interface ActionContext {
  openView(view: ViewHandle, options?: { placement?: 'left' | 'right' | 'top' | 'bottom' }): Promise<ViewPresentation>
  notify(message: string, level?: 'info' | 'warning' | 'error'): Promise<void>
}
```

## 总表

| 扩展点 ID | 静态字段 | 状态字段（默认值） | 方法 | 界面位置 |
| --- | --- | --- | --- | --- |
| `cockpit.ui.toolbar-actions` | `anchor?` | `icon`、`label`、`active=false`、`disabled=false` | `onTrigger(ActionContext)` | 底部工具栏 |
| `cockpit.ui.menubar` | 无 | `icon`、`label`、`active=false`、`disabled=false` | `onTrigger(ActionContext)` | 菜单栏 |
| `cockpit.ui.live-overlay` | `stream?`、`overlayLevel` | `visible=false`、`interactive=false`、`width=320`、`height=36`、`placement`、偏移字段 | `render()` | 直播覆盖层 |
| `cockpit.ui.left-bottom-panels` | 无 | `visible=false`、`interactive=true`、`width=240` | `render()` | 左下信息栏 |
| `cockpit.ui.left-panel` | 无 | `visible=false`、`label`、`icon?`、`width?` | `render()` | 左侧面板（可 reveal） |
| `cockpit.ui.sublive-tab` | 无 | `visible=false`、`label`、`icon?`、`width?` | `render()` | 子直播页签（可主动展开） |
| `cockpit.ui.flight-actions` | `anchor?` | `visible=true`、`icon`、`label`、`active=false`、`disabled=false` | `onTrigger()` | 飞控操作区 |
| `cockpit.ui.live-context-menu` | 无 | `visible=true`、`icon`、`label`、`disabled=false` | `onTrigger(ctx)` | 直播右键菜单 |

## 底部工具栏：cockpit.ui.toolbar-actions

清单里可选 `anchor`：`footer-toolbar`（默认）或 `footer-toolbar:before-ai`（插到 AI 按钮前面）。

`fh2-plugin.json`：

```json
{ "id": "capture-entry", "point": "cockpit.ui.toolbar-actions", "anchor": "footer-toolbar:before-ai" }
```

```ts
// plugin.ts
await ctx.extensions.contribute('capture-entry', {
  icon: 'capture', label: '抓拍', active: false, disabled: false,
  async onTrigger({ openView }) {
    const shown = await openView(ctx.views.get('capture-settings'), { placement: 'top' })
    await shown.closed
  },
})
```

注意：

- `icon` 的值是图标 ID，按插件清单 `contributes.icons` 声明解析；ID 未声明时不报错，但图标渲染为空（原始 ID 会被透传给驾驶舱 SDK，找不到对应资源）。
- `disabled` 只表达插件自己的状态，宿主/SDK 仍可能叠加自己的禁用逻辑。
- 同一按钮重复触发 `openView` 会先关闭旧的弹层；外部关闭、界面自关闭、插件卸载都会让 `shown.closed` 完成。
- `onTrigger` 里抛错会显示 3 秒错误通知。

## 菜单栏：cockpit.ui.menubar

字段与工具栏相同（`icon/label/active/disabled/onTrigger`），没有 `anchor`、`badge` 或 `visible` 字段；不要依赖未声明的字段。

```ts
const records = await ctx.extensions.contribute('records-menu', {
  icon: 'records', label: '抓拍记录', active: false, disabled: false,
  async onTrigger({ openView }) {
    await openView(ctx.views.get('records-summary'), { placement: 'bottom' })
  },
})
await records.update({ active: true })   // 运行时改状态
```

## 直播覆盖层：cockpit.ui.live-overlay

在直播画面上叠一层自己的界面（标注、状态卡等）。两个静态字段决定它挂在哪一路直播、哪一层：

`fh2-plugin.json`：

```json
{
  "id": "annotation-canvas",
  "point": "cockpit.ui.live-overlay",
  "stream": "DronePayload",
  "overlayLevel": "top"
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `stream?` | `DronePayload`（默认）、`DronePayloadSide`、`Fpv`、`Dock`、`Assistant`、`LensType` | 挂到哪路直播流 |
| `overlayLevel` | `normal` 或 `top`（必填） | `top` 层级为 3000，可盖住操作区，但仍低于弹窗和右键菜单 |

运行时布局字段：

- `placement`：`fill / top / bottom / top-left / top-right / bottom-left / bottom-right / custom`。`fill` 铺满有效视频区域（自动避开黑边）。
- `width`/`height`：非 `fill` 默认 320×36。数字按 px，字符串只接受受控的 CSS 长度表达式，必须大于 0。
- `custom` 必须且只能选 `top/bottom` 之一加 `left/right` 之一，且不能用 `offsetX/offsetY`；非 `custom` 不能用四边偏移字段。
- `interactive=false` 时该层不响应鼠标；`true` 只对本层生效，不代表独占全屏指针（独占要用 `cockpit:live-pointer`）。

```ts
const overlay = await ctx.extensions.contribute('annotation-canvas', {
  visible: false, interactive: true, width: '100%', height: '100%', placement: 'fill',
  render: () => ctx.views.get('annotation-canvas'),
})
await overlay.update({ visible: true })
```

注意：宿主按 `stream + overlayLevel` 分组挂载；直播首帧、相机切换、窗口缩放都会刷新有效画幅。隐藏或销毁时先卸载界面再移除容器；某个插件挂载失败不影响其他插件。

## 左下面板：cockpit.ui.left-bottom-panels

进入原生左下信息栏的纵向面板栈（和 AI/VLM 面板一起排版），不是"任意左下角绝对定位"。

```ts
const panel = await ctx.extensions.contribute('capture-workbench', {
  visible: false, interactive: true, width: 280,
  render: () => ctx.views.get('capture-workbench'),
})
await panel.update({ visible: true })
```

⚠️ 这个区域受载荷控制权门控：没有载荷控制权时可能被收起。需要在无控制权时仍然展示的内容（比如任务状态卡），改用 `cockpit.ui.live-overlay`。宿主不会替你根据业务状态设置 `visible`。

## 左侧面板：cockpit.ui.left-panel

一个可切换的侧栏界面，支持 `handle.reveal(input?)` 主动展开。`width`（有限正数）会作为初始宽度和拖拽下限传给宿主；省略就用宿主默认值。

将下面两条追加到现有清单的 `extensions`（不要整份替换清单）。前提：`records-panel` 已在 `views` 声明，界面入口已实现，并在入口注册其状态/方法（见[界面与状态](../../../20.development/10.frontend/40.view-and-state.md)）；图标 `records` 已声明或使用现有图标 ID。

```json
[
  { "id": "records-panel", "point": "cockpit.ui.left-panel" },
  { "id": "open-records", "point": "cockpit.ui.toolbar-actions" }
]
```

在现有 `activate(ctx)` 内注册两份贡献；激活完成后，用户点击工具栏按钮才请求展示面板：

```ts
const panel = await ctx.extensions.contribute('records-panel', {
  visible: false, label: '抓拍记录', icon: 'records', width: 280,
  render: () => ctx.views.get('records-panel'),
})
await ctx.extensions.contribute('open-records', {
  icon: 'records', label: '打开抓拍记录', active: false, disabled: false,
  async onTrigger() {
    await panel.reveal({ source: 'toolbar-click' })
  },
})
```

不要在 `activate()` 内紧接 `contribute()` 就 `await reveal()`：贡献在激活完成后才提交，提前 reveal 会报 `EXTENSION_NOT_FOUND` 并使该插件激活回滚。

注意：非法 `width` 不会报错，只是不传给宿主；每个条目的界面生命周期是串行的，重新挂载前先卸载旧实例。

## 子直播页签：cockpit.ui.sublive-tab

契约和 `reveal()` 行为与左侧面板相同，只是位置在子直播区。`width` 虽然契约里接受，但当前实现会忽略它，页签布局由宿主决定。

将下面两条追加到现有清单的 `extensions`。前提：保留 `evidence-preview` 的 `views` 声明、界面入口及入口侧状态/方法注册，图标 `evidence` 已声明或使用现有图标 ID。

```json
[
  { "id": "evidence-preview", "point": "cockpit.ui.sublive-tab" },
  { "id": "open-evidence-preview", "point": "cockpit.ui.toolbar-actions" }
]
```

在现有 `activate(ctx)` 内注册贡献，把 reveal 留在激活完成后的工具栏回调中：

```ts
const preview = await ctx.extensions.contribute('evidence-preview', {
  visible: false, label: '证据预览', icon: 'evidence',
  render: () => ctx.views.get('evidence-preview'),
})
await ctx.extensions.contribute('open-evidence-preview', {
  icon: 'evidence', label: '打开证据预览', active: false, disabled: false,
  async onTrigger() {
    await preview.reveal()
  },
})
```

注意：界面卸载不会自动停掉你的业务订阅——订阅是插件入口代码持有的，自己管理好。

## 飞控操作区：cockpit.ui.flight-actions

飞控操作区的按钮。`anchor` 可选 `flight-actions`（默认）或 `flight-actions:after-return-home`（插到原生返航按钮后面）。

`fh2-plugin.json`：

```json
{ "id": "route-return", "point": "cockpit.ui.flight-actions", "anchor": "flight-actions:after-return-home" }
```

```ts
await ctx.extensions.contribute('route-return', {
  visible: true, icon: 'return-route', label: '沿路网返航', active: false, disabled: false,
  onTrigger: () => openReturnRoutePanel(),
})
```

注意：

- 它只提供按钮，不提供挂面板的位置；需要面板就组合 live-overlay、left-bottom-panels 或 `platform:dialog`。
- `onTrigger()` 无参数。
- `visible=false` 时宿主注销这个按钮；`disabled` 和业务可见性由你根据遥测/任务状态维护，但原生飞行安全门控仍可能拒绝后续的飞行命令。

## 直播右键菜单：cockpit.ui.live-context-menu

在直播画面右键菜单里加一项。回调参数由宿主换算：

```ts
await ctx.extensions.contribute('approach-target', {
  visible: true, icon: 'approach', label: '抵近目标', disabled: false,
  async onTrigger({ relativePos, videoPoint, stream }) {
    // videoPoint 是有效画幅内的归一化坐标，宿主已换算
    ctx.logger.info('选择直播目标', { videoPoint, stream })
  },
})
```

注意：点击点不在有效画幅内（比如点在黑边上）时，宿主显示 3 秒警告，不会调用你的回调；`disabled=true` 交给 SDK 置灰。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 校验报"清单中出现未知字段" | 把 `label`/`visible`/`onTrigger` 等运行时字段写进了清单，移到 `contribute()` 里 |
| 两个插件顺序和激活顺序不一致 | 顺序由装载顺序和清单声明顺序决定，属于正常行为 |
| 按钮点了没反应 | 检查 `disabled`、宿主侧门控，以及 `onTrigger` 是否抛错（抛错只有 3 秒通知） |
| 覆盖层挡不住/盖多了 | 检查 `overlayLevel` 与 `placement`；`fill` 才会避开黑边 |
| 离开驾驶舱后定时器还在跑 | 在插件入口里管理订阅和定时器；插件运行时会兜底回收，但业务上应尽早清理 |

完整字段定义见[前端扩展点目录](../../../70.api-reference/10.frontend/30.extension-point-catalog.md)。
