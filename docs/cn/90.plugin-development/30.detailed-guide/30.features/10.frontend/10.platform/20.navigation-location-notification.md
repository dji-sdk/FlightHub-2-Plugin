# 导航、位置与通知

这三个能力负责"页面跳转、感知当前路由、弹顶部提示"。它们虽然以 `platform:` 开头，但由**具体宿主**提供，可用范围各不相同：

| 能力 | 权限名 | 方法 | 可用宿主 |
| --- | --- | --- | --- |
| `platform:navigation` | `platform:navigation` | `open`、`back` | 驾驶舱、项目、消息（计划不可用） |
| `platform:location` | `platform:location` | `getState`、`onStateChanged` | 驾驶舱、项目（计划、消息不可用） |
| `platform:notification` | `platform:notification` | `show` | 驾驶舱、项目、消息（计划不可用） |

获取方式统一是 `await ctx.capabilities.get('平台:能力名')` 并判空。三个能力各自独立声明权限，用几个声明几个。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## `platform:navigation`：页面跳转

```ts
const navigation = await ctx.capabilities.get('platform:navigation')
if (navigation) {
  await navigation.open('/plan', { target: 'self' })
  await navigation.back()
}
```

| 方法 | 说明 |
| --- | --- |
| `open(url, { target: 'self' \| 'blank' })` | `self` 当前页跳转，`blank` 新窗口 |
| `back()` | 后退；各宿主实现不同（项目走宿主路由后退，消息走浏览器历史） |

行为与限制：

- URL 由宿主统一校验：空 URL 和 `javascript:`、`data:`、`vbscript:` 协议会被拒绝。
- `target: 'blank'` 可能被浏览器弹窗策略拦截，应在明确的用户点击动作里调用，并处理失败。
- 导航后当前宿主可能立即卸载，调用之后的内存状态不要当作持久状态。

## `platform:location`：感知当前路由

```ts
const location = await ctx.capabilities.get('platform:location')
if (location) {
  const state = await location.getState() // { pathname, search, hash }
  const subscription = await location.onStateChanged((next) => {
    ctx.logger.info('路由变化', next)
  })
}
```

- 状态字段：`pathname` 是路由路径；`search` 含开头 `?`（无则空字符串）；`hash` 含开头 `#`（无则空字符串）。
- 订阅基于路由切换钩子，**不会自动补发当前状态**——先 `getState()` 再订阅。
- 订阅返回可释放句柄，用 `await subscription.dispose()` 释放。

## `platform:notification`：顶部消息提示

```ts
const notification = await ctx.capabilities.get('platform:notification')
if (notification) {
  const toast = await notification.show({
    key: 'route-changed',
    message: '已切换到新页面',
    intent: 'info',
    durationMs: 2500,
  })
  // 不需要提前关闭时，可让宿主到期自动回收。
  await toast.dispose()
}
```

| 字段/方法 | 说明 |
| --- | --- |
| `show({ key, message, intent, durationMs? })` | `intent` 取 `info` / `success` / `warning` / `error` |
| 返回句柄 | 调 `dispose()` 提前关闭；不调用则按宿主默认时长消失 |

注意：`key` 的替换行为各宿主不一致（项目宿主可更新同 key 消息，其他宿主当前不消费 `key`）。不要依赖"同 key 覆盖"实现业务逻辑。

## 集成片段

先按[第一个前端插件](../../../20.development/40.hands-on/20.first-frontend-plugin.md)建立可运行工程。下面不是完整的 `fh2-plugin.json`，不可整份替换：将 `permissions` 去重合并到现有清单，保留现有宿主扩展、界面声明/注册和入口。权限不会触发激活；清单若只有 `extensions: []`，`activate()` 不会执行。

合并到 `fh2-plugin.json` 的字段：

```json
{
  "permissions": [
    "platform:navigation",
    "platform:location",
    "platform:notification"
  ]
}
```

下面的 `definePlugin` 只示范入口逻辑组织，不是可直接替换完整工程的入口；保留生成工程的 SDK 导入路径，将能力逻辑合入已有 `activate` 和业务收尾，保留原有扩展贡献与界面注册。`openPlanFromUserAction` 需接到现有已声明扩展的用户操作回调。

```ts
// plugin.ts
import { definePlugin } from 'fh2-plugin-sdk'

export default definePlugin({
  async activate (ctx) {
    const [navigation, location, notification] = await Promise.all([
      ctx.capabilities.get('platform:navigation'),
      ctx.capabilities.get('platform:location'),
      ctx.capabilities.get('platform:notification'),
    ])

    if (!navigation) ctx.logger.warn('当前宿主不支持导航')
    if (!location) ctx.logger.warn('当前宿主不提供路由状态')
    if (!notification) ctx.logger.warn('当前宿主不提供原生提示')

    const reportRoute = async (pathname: string) => {
      return notification?.show({
        key: 'route-changed',
        message: `当前页面：${pathname}`,
        intent: 'info',
        durationMs: 2500,
      })
    }

    let currentToast = location
      ? await reportRoute((await location.getState()).pathname)
      : undefined
    const routeSubscription = location
      ? await location.onStateChanged(async (state) => {
          await currentToast?.dispose()
          currentToast = await reportRoute(state.pathname)
        })
      : undefined

    async function openPlanFromUserAction () {
      if (!navigation) throw new Error('当前宿主不支持导航')
      await navigation.open('/plan', { target: 'self' })
    }
    ctx.logger.debug('计划跳转动作已就绪', {
      callable: typeof openPlanFromUserAction === 'function',
    })

    return {
      async dispose () {
        await routeSubscription?.dispose()
        await currentToast?.dispose()
      },
    }
  },
})
```

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 计划页里三个能力都是 `undefined` | 计划宿主没有提供这三个能力，相关功能入口应隐藏 |
| 新窗口没打开 | 浏览器拦截了非用户手势触发的 `blank`；改成点击事件里调用并处理失败 |
| 订阅后没收到首次状态 | `onStateChanged` 不自动补发；先 `getState()` 再订阅 |
| 同 `key` 的提示没有互相覆盖 | `key` 的去重行为各宿主不一致，不要依赖 |
| 想跳转任意网址 | 协议校验不等于业务白名单；不要拼接用户输入生成外链 |
