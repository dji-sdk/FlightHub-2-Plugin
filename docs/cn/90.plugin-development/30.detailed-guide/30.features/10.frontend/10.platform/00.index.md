# 平台通用能力总览

平台能力由平台统一提供，多数在四个宿主都能用，比如弹窗、地图、剪贴板、HTTP。这一页是入口：先看分组和获取方式，再进子页抄示例。

## 怎么获取

四个基础能力不经过 `ctx.capabilities.get()`，直接用 `ctx` 上的成员：

```ts
const response = await ctx.apiCall('/orders')
const eventSubscription = await ctx.events.on('cockpit.live.lifecycle', handler)
const wsSubscription = await ctx.ws.onBizCode('order_changed', handler)
await ctx.storage.local.set('key', { value: 1 })
await ctx.blobs.put('preview', blob)
```

其他能力统一按"可能不可用"处理——先声明权限，再获取，判空后使用：

```ts
const map = await ctx.capabilities.get('platform:map')
if (!map) {
  ctx.logger.warn('platform:map 在当前宿主或授权下不可用')
  return
}
```

`undefined` 是正常情况，不是报错：同一个插件可能装到多个页面，某个页面没提供这个能力很常见。

## 两个容易误会的地方

- `platform:navigation`、`platform:location`、`platform:notification` 虽然以 `platform:` 开头，但由**具体宿主**提供，不是主应用提供。可用范围以[能力可用性矩阵](../../70.capability-availability.md)为准：驾驶舱/项目/消息提供导航和通知，位置只有驾驶舱和项目提供，计划宿主三个都没有。
- `platform:paas-event` 已从当前能力目录移除，不能申报或获取；这与合法能力在某个宿主没有提供方是两回事。

## 通用限制

- 清单声明权限 ≠ 提供方存在；每次获取后都要判空。
- `platform:object-upload` 要求同源运行环境，目前只在驾驶舱宿主可用，详见[对象上传](./70.object-upload.md)。
- 能力客户端绑定当前插件实例：不要跨宿主保存句柄，宿主重挂后要重新获取。
- 主应用已注册提供方不代表底层资源就绪。例如 `platform:map` 仍要求全局地图已加载，未就绪时调用会失败，需要捕获。
