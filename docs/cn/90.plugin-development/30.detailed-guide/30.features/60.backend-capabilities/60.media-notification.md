# 媒体与前端通知

后端插件经常要：根据文件 ID 查媒体信息（预览地址）、把证据文件挂到业务对象上、给前端推一条"数据更新了"的通知。这一页讲 `media` 和 `notify` 两个全局对象。权限：`media:read` / `media:write` / `notify:publish`，三条代码路线都可用。

## 媒体事件从哪来

`media.photo_created` 和 `media.video_created` 是平台指定的消息类型（照片/视频文件生成时广播）。在清单 `events[]` 里订阅它们，是"文件落地后做后处理"的标准入口；订阅方法见[事件与流程](./30.event-flow.md)。

## media：读文件、挂文件

### 方法与权限

| 方法 | 权限 | 说明 |
| --- | --- | --- |
| `media.get(fileId, workspace?)` | `media:read` | 查单个文件的详情和签名 URL；媒体能力配置后接真 |
| `media.list(ownerType, ownerId)` | `media:read` | 当前不可用，调用报错；不要按普通列表能力设计 |
| `media.attach(ownerType, ownerId, fileId, role)` | `media:write` | 当前空壳，返回 `skipped=true`，不产生真实关联 |
| `media.ensureFolder(ownerType, ownerId, displayName, parentId?, workspace?)` | `media:write` | 配置后接真；当前实现要求非空 `workspace` |
| `media.move(fileId, folderId, workspace?)` | `media:write` | 配置后接真；当前实现要求非空 `workspace` |
| `media.rename(fileId, name, workspace?)` | `media:write` | 配置后接真；`name` 不带扩展名 |

成功路径直接返回值；不可用或空壳按方法分为抛 JS 异常和返回 `skipped`，不能统一套 `{ok,data}` 信封。

### media.get 示例

```ts
// handlers/evidence/links.ts
export function getMedia(input: RecordInput) {
  try {
    const file = media.get(String(input.file_id))
    return {
      fileId: file.fileId,
      previewUrl: file.previewUrl,
      originalUrl: file.originalUrl,
      linksUnavailable: false
    }
  } catch (err) {
    log.warn("媒体链接不可用", { fileId: String(input.file_id) })
    return { fileId: String(input.file_id), previewUrl: "", originalUrl: "", linksUnavailable: true }
  }
}
```

返回字段里有两个特殊值：

| 字段 | 值为 0 时 |
| --- | --- |
| `shotAtMs` | 平台无法可靠给出拍摄时间，不要自己猜 |
| `urlExpiresInSec` | 平台不知道签名 URL 的有效期 |

### 注意

- `media.get` 依赖部署方接通文件存储服务；未配置时直接抛错。插件作者不直接管理服务配置，测试前请部署方确认接入状态。
- 当前可用性按方法区分：`list` 不可用；`attach` 空壳并返回 `skipped=true` / `skipReason`；`ensureFolder`、`move`、`rename` 在媒体能力配置后接真。未配置媒体能力时，写方法统一返回 `skipped=true`。不能把 `skipped` 当成功。
- `ensureFolder`、`move`、`rename` 的接真实现依赖部署配置，并要求显式传非空 `workspace`；`rename.name` 只给显示名，不要带扩展名。
- `media.get` 返回的签名 URL 自带访问凭据，是敏感值：不要写日志、不要拼进错误信息、不要存进流程历史。
- 文件 ID 必须是纯数字字符串；多项目部署时注意工作区参数 `workspace` 一致性，否则会表现为"文件不存在"。

## notify：给前端发通知

### 方法

```text
notify.publish({ channel, to, bizCode, subCode, data })
  -> { delivered, skipped, skipReason, failReason }
```

| 参数 | 要求 |
| --- | --- |
| `channel` | 只接受 `project` / `organization` / `user_web` / `user_app` / `device` / `server` |
| `to` | 非空的目标列表（如项目 ID 数组） |
| `bizCode` / `subCode` | 必须非空；前端用 `ctx.ws.onBizCode(bizCode)` 收这路消息 |

参数不合法会直接抛错——即使通知能力未配置也会先校验参数。

### 示例

```ts
const result = notify.publish({
  channel: "project",
  to: [input.project_id],
  bizCode: "illegal_road_capture",
  subCode: "media_added",
  data: { dock_sn: input.dock_sn, tracking_id: input.tracking_id }
})

if (result.skipped) {
  log.warn("通知能力未配置", { reason: result.skipReason })   // skipped 不抛错
} else if (!result.delivered) {
  log.warn("通知投递失败", { reason: result.failReason })
}
```

返回值语义：

| 返回 | 含义 |
| --- | --- |
| `delivered: true` | 已送达前端通道 |
| `skipped: true` | 能力未配置，没发（尽力而为，不是错误） |
| `delivered: false, failReason: "..."` | 投递失败（如通道不可达），不抛错也不重试 |

### 注意

- 通知是**提醒性质**的：可能丢、可能重复。前端收到后应刷新数据，而 HTTP 接口查询才是权威数据源；前端刷新操作要做成幂等的。
- 通知通道由部署方配置，不是插件配置面板中的管理项；未就绪时按 `skipped` / `failReason` 处理，并保留主动刷新兜底。
- 前端侧如何接收通知消息，见 [HTTP、WebSocket 与事件](../../20.development/10.frontend/70.http-websocket-events.md)。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `media is not defined` | 清单没申报 `media:read`/`media:write` |
| `media.get` 抛"未装配媒体能力" | 部署未配置文件存储服务，联系部署方 |
| `media.attach` 返回 `skipped=true` | 该方法当前空壳，没有真实副作用；不要当成功。`ensureFolder/move/rename` 配置后接真，但需部署配置和 workspace |
| `notify.publish` 返回 `skipped` | 通知通道未配置；业务数据该提交照常提交 |
| 前端没收到通知 | `bizCode` 不匹配、`to` 为空，或投递失败（查 `failReason`）；通知是尽力而为，前端要有主动刷新兜底 |
