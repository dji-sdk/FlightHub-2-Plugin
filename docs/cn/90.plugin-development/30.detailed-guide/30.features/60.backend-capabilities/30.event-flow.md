# 事件与流程

插件和"事件"打交道有四个方向：**订阅**平台消息（比如媒体文件生成）、**写入**统一事件、**更新**事件状态、**启动**本插件的作业流程。这一页逐个讲清楚怎么写、抛什么错、怎么保证幂等。

## 订阅平台消息：events[]

平台会广播指定的消息类型，插件在清单 `events[]` 里声明订阅。当前类型有两种（平台指定，开发者不可自造类型）：

- `media.photo_created`：照片文件生成
- `media.video_created`：视频文件生成

源清单 `fh2-plugin.json`：

```json
{
  "events": [
    {
      "type": "media.video_created",
      "match": { "sub_file_type": "0" },
      "consumer": [
        { "handler": "events/media-video-created.ts", "entry": "onVideoCreated" }
      ]
    }
  ]
}
```

```ts
// events/media-video-created.ts
export function onVideoCreated(input: RecordInput, _ctx: EventCtx) {
  log.info('收到视频生成消息', { fileId: input.file_id })
  // 处理业务；需要重活就 flow.start 启动作业流程（见下文）
  return {}
}
```

规则：

| 规则 | 说明 |
| --- | --- |
| `match` | 消息体顶层字段的字符串等值筛选，多个条件 AND；不写 = 全收 |
| 多个消费方（`consumer`） | 后端运行时中命中的消费方并发执行、各自独立重试；全部结束后按最坏结果聚合消息处置 |
| 不同插件可订阅同一类型 | 平台扇出，消费方各自执行，但共享同一条消息的最终处置 |
| 至少一次投递 | 回调必须幂等（业务去重推荐 `store.createIfAbsent` 或条件 `update`） |

`consumer` 数组不保证执行先后。有业务依赖的逻辑应放在同一个消费函数内调用，或使用显式流程编排。全部结束后对消息按 **Requeue > Discard > Ack**（重新入队 > 丢弃 > 确认）取最坏结果，一个消费方失败不会阻止其他消费方执行。本地模拟器不用于证明后端运行时的并发、独立重试或消息确认/死信处置，需在已部署测试环境验证。

**入口必须返回对象**，通常为 `{}`。普通业务输出不会交给其他消费方，但顶层返回 `{ok:false,error:{code,message}}` 时会按 `error.code` 分类处置；执行到函数末尾未返回、`return undefined` 或裸 `return` 会作为可重试错误处理。

| 脚本结果或错误 | 单个消费方的处置 |
| --- | --- |
| 正常返回对象（如 `{}`） | 确认（`Ack`） |
| 消息缺字段 → 抛 `INVALID_ARGUMENT` | 契约错：丢弃（`Discard`），不重投；已配置死信保存时进入死信队列 |
| 消息没命中业务 → 抛 `NOT_FOUND` | 确认消息，不重投 |
| 其他错误或非对象返回 | 按目标环境约定的尝试次数上限有界重试，耗尽后丢弃（`Discard`） |
| 可重试错误处理/退避期间因关停取消 | 重新入队（`Requeue`） |

错误分类也适用于事件入口顶层的失败信封；重试次数上限和死信保存由部署方与消息提供方确认，只有已启用死信保存时，丢弃（`Discard`）的消息才进入死信队列，不保证自动恢复。HTTP 接口处理函数和流程脚本**不自动提升返回的失败信封**；若 `store` 操作失败应让调用失败，必须显式 `throw result.error`，不能套用事件入口的信封分类规则。

## 写入统一事件：platform.insertEvent()

权限 `event:write`。把一条事件写进统一事件模型（写后可被 `trigger.stream` 的流程消费，也可被其他系统读取）：

```ts
const inserted = platform.insertEvent({
  eventId: "cascade:20260911:42",
  tenantId: "tenant-a",
  eventType: "incident",
  status: "unacknowledged",
  occurredAt: ctx.now,
  payload: { sourceId: "42" }
})
```

| 返回 | 含义 |
| --- | --- |
| `true` | 写入成功（HTTP 2xx 且业务码 0） |
| `false` | 事件服务提供方返回"已存在"（重复 `eventId`），不是错误 |
| 抛错 | 缺 `eventId`、事件服务提供方未接入、传输失败、非 0 业务码等 |

⚠️ `inserted` 只能用于观测：事件服务提供方对重复 `eventId` 也可能返回成功。业务去重要靠自己的唯一键，不要依赖这个返回值判断"本次是新建"。

此能力依赖事件服务提供方接入；未接入时调用直接抛错。插件作者申报 `event:write` 不代表提供方已就绪，接入前请部署方确认测试环境可用，并分别验证写入结果和后续消费。

## 更新事件状态：update_event_status

这是流程 JSON 里的**平台受控步**，不是 JS 方法（没有对应权限名）：

```json
{
  "id": "mark_handling",
  "action": "update_event_status",
  "inputs": {
    "status": { "const": "handling" },
    "eventId": { "from": "trigger.eventId" },
    "flightMissionId": { "from": "steps.dispatch.missionId" }
  },
  "when": { "field": "trigger.eventId", "op": "present" }
}
```

成功输出 `{ "eventStatus": "handling" }`。要点：

- `status` 必须是常量，且出现在清单 `eventStatuses[]` 里（装载期对账，对不上起不来）。
- `flightMissionId` 传空不会清空已有值。
- 目标事件不存在（404）是错误，不是幂等成功。

## 启动插件作业：flow.start()

权限 `flow:start`，HTTP、事件和流程脚本三路均按有效 `allowlist` 注入。它只能启动声明了 `trigger.job` 的流程；注入不代表部署的流程启动服务提供方可用，调用仍可能失败，递归和重试副作用需评审：

重耗时的视频处理建议交给流程作业，这是超时与重试设计建议，不是路线硬隔离。

```ts
// handlers/... 或 events/...
const result = flow.start("lane-change-postprocess", input.event_id, {
  event_id: input.event_id,
  video_file_id: input.video_file_id
})
// { already: false } 新启动；{ already: true } 同一作业已存在——两者都不是错误
```

`seed` 的键必须与目标流程 `trigger.job.seed` 声明**逐字一致**（缺键、多键都报错）；同一 `(flowName, bizId)` 靠流程实例 ID 去重，没有 `retry` 方法，要重跑就换新的 `bizId`。

本例传两个 `seed` 键，目标声明应为 `"job":{"seed":["event_id","video_file_id"]}`。[作业、目标轨迹与视频处理](./80.job-trajectory-video.md)中的三键例子是另一份片段示例，不能将这里的两键调用直接拼到其三键声明上。

上述调用是函数内片段，HTTP、事件和流程脚本的入口最终仍须返回对象。各能力按具体方法签名处理返回或错误：`store` 使用信封，`cache` 逐方法查生成的 `types/`，其他能力不统一套用 `.ok/.data`，见[能力目录](../../70.api-reference/20.backend/80.host-capability-catalog.md#返回与错误)。

## 流程的五种触发轴

`flow.start` 只是五种流程触发方式之一。全部触发轴（`api` / `schedule` / `stream` / `bizNotify` / `job`）见[触发方式](../../20.development/20.backend/70.triggers.md)；流程编排本身见[流程编排](../../20.development/20.backend/60.workflow.md)。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 收不到媒体消息 | 清单 `events[]` 没声明，或 `match` 条件把消息筛掉了 |
| 消息处理被反复重试 | 抛了非 `INVALID_ARGUMENT`/`NOT_FOUND` 的错误；先做业务幂等，再决定抛什么 |
| `insertEvent` 报提供方未接入 | 请部署方确认事件服务提供方已接入且可用 |
| `update_event_status` 装载失败 | `status` 常量没写进清单 `eventStatuses[]` |
| `flow.start` 报流程不允许由插件启动 | 目标流程没声明 `trigger.job` 触发轴 |
| `flow.start` 报 seed 不匹配 | 传入的键与 `trigger.job.seed` 声明不一致，逐字核对 |
