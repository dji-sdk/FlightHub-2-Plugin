# 资源租约

资源租约用于"同一时刻只有一个流程占用某个资源"的互斥，目前**在规划中，暂不可用**。

## 当前状态

- 能力清单里没有 `lease:*` 权限名，也没有 `resourceLease` 全局对象。
- 在清单 `allowlist` 里申报 `lease:acquire` 之类的名字，插件会在装载期被直接拒绝，进程起不来。
- 没有 `resourceLease` 全局对象；不要把提案中的方法写进代码。

## 临时替代：用数据存储做互斥

需要互斥时，可以用 `store` 的原子操作自己维护一张资源占用表（建表和 `store` 用法见 [数据存储](./50.data-store.md)）：

```ts
// 原子占坑：resource_key 上有唯一索引，created=false 表示已被占用
const first = store.createIfAbsent(
  "resource_lease",
  {
    id: ctx.stableId("lease:" + input.resourceKey),
    resource_key: input.resourceKey,
    owner: input.owner,
    expires_at_ms: String(input.expiresAtMs).padStart(13, "0")
  },
  ["resource_key"]
)
if (!first.ok) throw first.error
if (first.data.created) return { acquired: true }

// 条件抢占/续租：affected=1 才算抢到
const changed = store.update(
  "resource_lease",
  { resource_key: { eq: input.resourceKey }, owner: { eq: input.expectedOwner } },
  { owner: input.owner, expires_at_ms: String(input.expiresAtMs).padStart(13, "0") }
)
if (!changed.ok) throw changed.error
return { acquired: changed.data.affected === 1 }
```

⚠️ 这个替代只是"记账型"互斥：

- 没有平台可信时钟、没有自动过期回收、没有隔离令牌（旧持有者可能继续执行副作用）。
- 只适合业务层面的软互斥，**不适合保护真实设备控制、载荷独占**等强资源。
- 进程退出不会自动释放记录，要自己设计过期与接管策略。
