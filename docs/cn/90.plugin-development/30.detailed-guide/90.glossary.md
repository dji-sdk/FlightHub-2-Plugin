# 术语表

第一次遇到不懂的词，来这里查。同一概念在手册里只用一个叫法。

| 术语 | 代码标识 | 一句话解释 |
| --- | --- | --- |
| 插件 | — | 一段独立的功能代码，装进司空就能用：前端插件改界面，后端插件提供接口和流程 |
| 能力工程 | 完整 Capability | 一个工程同时包含前端插件、后端插件和本地模拟数据，共享一套配置；创建向导选择「0=完整 Capability」的产物 |
| 前端源清单 | `fh2-plugin.json` | 前端插件的声明文件：ID、入口、权限、要挂的扩展点 |
| 后端源清单 | `fh2-plugin.json` | 后端插件的声明文件：`pluginId`、`allowlist`、`flows`、`scripts`、`events`；前后端源清单同名但内容不同 |
| 后端运行时清单 | `dist/plugin.json` | 构建产物，宿主实际装载的清单；由工具链生成，**不要手改** |
| 前端构建清单 | `dist/fh2-plugin.json` | 前端构建产物清单，宿主安装的是它，不是源清单 |
| 上传包 | `fh2-plugin pack` | 打包命令产出的 zip；根级 `packages.json` 描述包含哪些能力，包内各插件目录另有各自的 `plugin.json` 打包清单 |
| 宿主 | `ctx.host` | 承载插件的页面应用；前端有 `cockpit`、`plan`、`message`、`project` 四个 |
| 主应用 | — | 加载插件引擎的主应用。主应用不是宿主 |
| 插件入口 | `activate` | 前端插件启动时执行的函数，在入口代码 `plugin.ts` 里；申请资源、贡献扩展都从这里开始 |
| 上下文（前端） | `ctx`、`PluginContext` | 前端平台传给 `activate` 的对象；能力、存储、事件、HTTP 都从它上面拿 |
| 上下文（后端） | `ctx`、`HandlerCtx`、`EventCtx`、`AdapterCtx` | 后端脚本收到的对象，只带请求信息（`now`、`requestId`、幂等键等）；能力是全局注入的，不从 `ctx` 拿 |
| SDK 文档模块名 | `fh2-plugin-sdk` | 文档 `import` 使用的逻辑模块名，实际路径以生成工程配置为准，不据此修改依赖或工具链别名 |
| 扩展点 | `extensions[].point` | 宿主预留的界面位置（工具栏按钮、左面板等），插件只能往这些位置放东西 |
| 扩展 | `ctx.extensions.contribute()` | 插件对某个扩展点的具体贡献——「在这个位置放什么」 |
| 能力（前端） | `ctx.capabilities.get()` | 宿主提供给前端插件的功能；清单 `permissions` 声明 → `ctx.capabilities.get()` 判空获取 |
| 能力（后端） | `allowlist` | 平台提供给后端脚本的功能；清单 `allowlist` 申报 → 全局对象注入（没申报的不存在） |
| 插件界面 | `defineView` | 插件自己的界面代码，挂在宿主给的容器里；不接收 `PluginContext`，通过通信通道和插件入口交换数据，但这不代表无法访问浏览器网络 |
| 通信通道 | `state`、`methods` | 插件入口与界面之间传状态和方法的那条通道；`client` 上的方法平铺调用 |
| 入口隔离环境 | `isolated-realm` / `isolated-iframe` | 插件入口的运行环境，由宿主选择；入口网络护栏阻止原生 `fetch`、`XMLHttpRequest`、`WebSocket`，使用 `ctx.apiCall()` / `ctx.ws`，不适用于界面代码 |
| 界面样式隔离 | `ShadowRoot` | 插件界面的 DOM/CSS 隔离；JavaScript 仍在宿主同一 Realm 执行，不是 JavaScript 安全沙箱，也不能保证界面无法绕过受管 API |
| 跨宿主通信服务 | `definePluginService` | 同一插件在不同宿主实例之间共享方法与事件的通道；不能跨插件使用 |
| 本地调试页面 | `fh2-plugin dev` | 启动的本地模拟宿主页面（默认 `http://127.0.0.1:5175`），带多宿主容器和热更新；它只是模拟，最终以真实宿主验证为准 |
| 司空 | — | 插件最终部署运行的产品环境；`preview` 命令连接的真实系统就是它 |
| 平台事件 | `ctx.events.on()` | 宿主主动推给插件的事件（目前只有驾驶舱急停和直播生命周期两个） |
| HTTP 接口处理函数 | `handlers/**/*.ts`、`HandlerCtx` | 后端插件的 HTTP 接口脚本：文件路径 + 命名导出 = 接口名 |
| 后端运行时 | — | 已部署环境中装载后端产物、执行接口与事件脚本并调度流程的服务；不由 `build` / `pack` 启动 |
| 事件处理函数 | `events[]`、`EventCtx` | 订阅平台消息并自动执行的脚本，声明在清单 `events[]` |
| 流程 | `flows[]` | 用 JSON 写的步骤编排，跑在持久化引擎上，可以等信号、重试、跨天执行 |
| 触发器 | `trigger` | 流程的启动方式，五种可选一种或多种：`api` / `schedule` / `stream` / `bizNotify` / `job` |
| 流程脚本 | `adapters/`、`AdapterCtx` | 供流程 `run_script` 步骤执行的脚本，要在清单 `scripts[]` 里声明 |
| 连接 | `connections[]` | 外部系统的配置形状声明；真实地址和密钥由部署方配置，不写进清单 |
| 数据实体 | `schema.sql` | 插件业务数据的表定义；`schema.sql` 是唯一事实源，构建时投影进产物清单 |
| 幂等键 | `Idempotency-Key` | 让重复请求产生同一结果的调用标识；网关层缓存响应，写操作传业务稳定键、读操作不传 |
| 请求 ID | `X-Request-Id` | 一次 HTTP 请求的追踪标识，用于排错；它不是幂等键 |
| PUID | `puid` | 后端插件某个版本在插件管理服务里的唯一 ID；本地开发不用填 |
| 本地 HTTP 模拟器 | `fh2-plugin dev` | 工程含后端且非 `--frontend-only` 时启动，执行插件 HTTP 接口和事件脚本与内存存储；不是真实网关，不执行流程或消息队列 |
