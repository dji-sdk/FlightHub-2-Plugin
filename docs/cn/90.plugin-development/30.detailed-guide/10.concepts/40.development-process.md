# 开发流程

这一页描述插件开发工具 `1.0.0` 的日常循环：建工程 → 改清单 → 生成类型 → 写代码 → 本地调试 → 校验构建。首次看到面板走[快速入门](../../10.quick-start/00.index.md)，让 AI 协助实现走[AI 开发 Skill](../../20.ai-development-skill/00.index.md)；完整环境准备和前后端练习仍在[完整练习](../20.development/40.hands-on/10.environment-preparation.md)。

## 1. 创建工程

先按[环境准备](../20.development/40.hands-on/10.environment-preparation.md)构建插件化开发者工具。在开发者工具目录之外、可写的插件父目录执行 `fh2-plugin create`，按提示填写；未注册全局 CLI 时，用源码 `bin/fh2-plugin.mjs` 代替 `fh2-plugin`：

| 向导问什么 | 本页填写什么 |
| --- | --- |
| 工程类型 | `0`（完整能力工作区） |
| 工作区目录 | `exp_project_demo`，须不存在或为空 |
| 名称 | `项目插件示例` |
| 包管理器 | `pnpm` |
| 是否立即安装依赖 | `是` |

向导结束后进入工程：

```bash
cd exp_project_demo
```

脚本或 CI 需要一次性传参时，才使用 `--template`、`--capability-id`、`--package-manager` 等长参数；完整清单见 [CLI 参考](../70.api-reference/10.frontend/70.toolchain-cli.md#交互创建与自动化创建)。日常开发不需要背这些参数。

默认能力工作区生成 `packages.json`，能力子目录包含 `capabilities.json`、两个前端成员、一个后端成员及本地模拟器。纯前端、纯后端和全栈是业务成员组合，不是三个不同的平台模型；需要上传行业包时从工作区组织成员，不在单插件根直接打包交付。

CLI 仍提供以下模板；单插件模板适用于独立工程或已有成员，不是默认行业上传路线：

| 模板 | 内容 | 适合 |
| --- | --- | --- |
| `capability-fullstack`（默认） | 工作区 + 能力目录 + 前后端成员 + 本地模拟器 | 新建可聚合交付的业务工程 |
| `frontend-basic` | 单个前端插件（清单 + 入口 + 界面） | 独立前端工程，上传前须组织为能力 / 行业包 |
| `backend-basic` | 单个后端插件 | 独立后端工程，上传前须组织为能力 / 行业包 |

`official_*` 前缀用于官方插件，生态与实验插件用 `exp_*`。

## 2. 每次改动后的固定动作

在生成工作区根使用已有脚本，它们选择实际能力子目录；进入成员根时核对该成员的 `package.json`。前端清单变化后生成 `src/generated/plugin-types.ts`；后端清单或 `schema.sql` 变化后重新生成 `types/`。不要手改生成结果：

```bash
pnpm run generate    # 按成员生成类型，不手改生成文件
pnpm run validate    # 校验清单与代码的一致性
```

只改业务代码时按影响复验类型、测试和构建；不能因为清单没改就省略代码与契约的一致性检查。工作区根没有所有成员的类型检查脚本时，到成员根运行已有检查。

## 3. 本地调试

```bash
pnpm run dev
```

这条命令会：首次构建 → 启动本地模拟页面 → 监听源码重建。含后端且未选仅前端模式时，还启动本地 HTTP 模拟器；它不执行真实流程，不证明生产存储或设备能力就绪。

浏览器打开终端本次完整地址，分别检查构建、宿主挂载、插件激活、界面和业务结果。需要真实预览时仅走 HTTP PAC，先同源登录并进入项目，再手填本次资源根、校验权限并同意后加载，见[真实环境预览](../40.debug-and-test/10.local-development.md#真实环境预览)。

## 4. 提交前检查

以下展示单个前端成员已有的检查脚本；先在该成员根确认 `package.json`，不要把这四条当成所有工作区根都具备的脚本。后端和全栈成员按各自测试、类型及构建配置复验：

```bash
pnpm run test      # 单元测试
pnpm run tsc       # 类型检查
pnpm run lint      # 代码规范
pnpm run build     # 构建产物
```

检查通过只说明本次本地验证结果，不等于发布或目标环境运行通过。前端 `dist/fh2-plugin.json` 的 `manifestVersion`、`engines`、`buildInfo` 由工具链生成，不复制回源清单；后端构建产物是 `dist/plugin.json`。交付时核对执行根、聚合布局和目标环境要求，见[构建与交付](../60.delivery-and-security/00.index.md)。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 改了清单，代码里类型没更新 | 忘了跑 `pnpm run generate` |
| `validate` 报某个扩展字段不认识 | 把运行时字段（状态、回调）写进清单了；移回代码里的 `contribute` |
| 本地调试页面里看不到插件 | 先看 `build` 是否成功，再看插件声明的扩展点是否属于当前预览的宿主 |
| 构建失败 | 处理终端第一条报错，通常是入口代码引了 Vue 或界面代码引到了入口 |
