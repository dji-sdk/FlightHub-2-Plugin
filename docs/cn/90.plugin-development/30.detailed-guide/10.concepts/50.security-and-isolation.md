# 安全与隔离

插件能接触真实项目和设备数据，所以前端、后端和交付各有一条安全边界。这一页先讲共同原则，再分别讲前端隔离和后端安全。

## 共同边界

- 插件通过公开扩展点、宿主能力和后端 API 扩展产品，不修改司空源码。
- 安装审核与代码审核是安全边界；ShadowRoot、本地构建成功和类型检查都不能代替审核。
- 插件不公开信任等级，也不在清单里声明 `trusted`、`trustLevel`、`sandbox` 等运行档位。
- 只传可序列化的 `PluginValue`：JSON 数据、`Blob`、`Date`、`Map`、`ArrayBuffer` 等；不传 DOM、Vue 对象、能力句柄、宿主对象、函数、Cookie、token 或密钥。

## 前端隔离

前端插件分两部分，约束不同：

| 部分 | 运行位置 | 平台约束 |
| --- | --- | --- |
| 插件入口（Entry） | 独立 iframe 或 realm | 内联 Guard 阻止原生 `fetch`、XHR、WebSocket、存储全局、`eval`、`window.open` 等 |
| 插件界面（View） | 宿主同一 JavaScript Realm，挂载在 ShadowRoot | 不接收 `PluginContext`；平台不安装同款 Guard；ShadowRoot 只隔离 UI/CSS |

入口业务网络必须走 `ctx.apiCall` / `ctx.ws`；存储用 `ctx.storage` / `ctx.blobs`；定时器用 `ctx.timers`。看到 `fetch` 失败、`localStorage` 为 `undefined`、`EvalError`，先检查是不是绕过了受管通道。

View 不接收上下文是 API 分工，不是 JavaScript 安全沙箱。界面需要数据时，通过契约方法让入口代取；不要自己在界面里发请求或操作宿主 DOM。

Entry Guard 是**防误用护栏**，不是安装安全边界；个别浏览器不可重定义的内置属性会被跳过。真正的安全边界仍是安装审核、代码审核和最小权限。

## 后端安全

后端脚本运行在同步沙箱中，额外约束：

- 能力按 `allowlist` 注入；没申报的对象不存在，不是返回 `undefined`。
- 只能相对导入本插件模块；禁止 Node 内置模块、裸包导入、动态 `import()`、`require`、`eval`。
- 不能 `async/await`、使用计时器或写循环等待；长流程用流程编排。
- 出网走 `connector.fetch` 或平台连接器，不直接访问任意网络。
- 飞行控制、下发任务、返航等高风险动作只通过流程受控步执行，不注入脚本。
- 秘密、token、签名 URL、请求体和敏感业务数据不写日志、错误信息、数据库或流程历史。

后端能力“已注入”只代表允许调用，不代表提供方一定可用；方法可能在调用点报未装配或返回 `skipped`，要按具体签名处理。

## 最小权限

清单只声明实际用到的权限：

- 前端 `permissions` 多申请不会让功能更稳，只会在安全评审和安装审核时被退回。
- 后端 `allowlist` 申报平台授不出的能力名会导致进程起不来。
- 拿不到能力时写降级逻辑，不要换一种方式硬拿。

## 错误写法与正确写法

| 错误写法 | 正确写法 |
| --- | --- |
| 入口里 `fetch('/api/...')` | `ctx.apiCall('/plugin/invoke', ...)` |
| 界面里直接 `fetch` 或读 `localStorage` | 通过契约方法让入口代取 |
| 后端脚本里 `await store.query(...)` | 同步调用 `store.query(...)`；长流程交给流程编排 |
| 后端脚本里调用飞行函数 | 用流程平台受控步 |
| 把 token 拼进错误信息 | 只写错误码、字段名和固定文案 |
| 用 ShadowRoot 当 JS 沙箱 | 按安装审核、代码审核和最小权限设计 |
