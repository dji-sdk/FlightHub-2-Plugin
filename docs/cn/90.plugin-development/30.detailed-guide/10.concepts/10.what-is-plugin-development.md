# 什么是插件开发

插件（Plugin）是具有自己身份和清单、由平台独立加载的功能代码。一个业务能力可以由前端成员、后端成员和共享契约组成；前端负责页面和交互，后端负责接口、事件、流程和数据。

这一页先建立统一模型。前端细节见[前端宿主、扩展点与能力](./30.host-and-capability-model.md)，后端细节见[后端运行时、入口与权限](./35.backend-runtime-and-permission.md)。

## 前端插件和后端插件

| | 前端插件 | 后端插件 |
| --- | --- | --- |
| 运行位置 | 项目、消息、计划、驾驶舱页面宿主 | 服务端 Worker 的脚本沙箱 |
| 主要用途 | 按钮、表单、卡片、列表、面板和界面交互 | HTTP 接口、事件消费、流程作业、数据读写 |
| 清单声明 | `extensions` 声明扩展点，`permissions` 声明宿主能力 | `allowlist` 声明可注入的全局能力，`events`/`scripts`/`flows` 声明入口 |
| 调用方式 | 基础能力用 `ctx`，其他能力用 `capabilities.get()` 并判空 | 能力按 `allowlist` 注入为全局对象；`ctx` 只带调用事实 |
| 产物 | 宿主可装载的前端插件包 | 运行时可装载的后端插件包 |

前后端是**两个不同的插件**，插件 ID 不同。前端调用后端时，`pluginId` 必须写后端的 ID，不能写前端 ID。

## 一个业务能力由什么组成

一项业务可以由几个插件配合完成。行业工作区用 `packages.json` 组织能力，能力目录用 `capabilities.json` 描述名称和用途，`frontend/`、`backend/` 放成员。

```text
exp_patrol/                       # 工作区根
├── packages.json                 # 行业包身份和成员
└── exp_patrol/                   # 能力目录
    ├── capabilities.json
    ├── frontend/
    │   ├── exp_patrol_teach/     # 前端插件：示教
    │   └── exp_patrol_panel/     # 前端插件：巡逻面板
    └── backend/
        └── exp_patrol_backend/   # 后端插件：流程、接口和数据
```

能力扩展（Capability）是**业务交付单元**；宿主能力 API 是**代码调用接口**。插件属于某项业务能力，并不会因此自动获得相机、地图或飞行权限。

## 一个插件由哪几部分组成

| 部分 | 位置 | 作用 |
| --- | --- | --- |
| 插件清单 | `fh2-plugin.json` | 声明身份、入口、权限、扩展点或后端入口 |
| 前端入口 | `src/plugin.ts` | 宿主激活时执行 `activate(ctx)`，获取能力、建立订阅、提交扩展 |
| 前端界面 | `src/views/**` | Vue 3 界面，通过状态和方法通道与入口协作 |
| 后端入口 | `handlers/`、`events/`、`adapters/` | HTTP 接口、事件回调、流程脚本 |
| 后端流程 | `workflows/*.json` | 步骤、依赖、等待信号和平台受控动作 |
| 共享契约 | 前后端共同维护的模块 | 输入、输出、错误和状态约定 |

最小前端插件可以只有清单 + 入口：在驾驶舱工具栏注册一个按钮。需要面板、列表或表单时再加 View。后端插件至少有一个清单和一个入口脚本；数据表由 `schema.sql` 定义。

## 前端入口和界面的分工

```text
入口 plugin.ts：拿 ctx，调能力、发请求、收消息、声明扩展
        │
        │  类型化状态 / 方法通道
        ▼
界面 views/**.vue：只画 UI 和响应操作，需要数据时向入口要
```

- 入口负责网络、权限和业务调用；界面不接收 `PluginContext`。
- 界面使用自带 Vue 3，挂在 WebComponent 的 ShadowRoot 中；ShadowRoot 只隔离 UI/CSS，不是 JavaScript 安全沙箱。
- 入口的网络护栏拦截原生 `fetch`、XHR 和 WebSocket；业务请求走 `ctx.apiCall`，实时消息走 `ctx.ws`。
- 入口、界面和宿主之间只传 `PluginValue`：JSON 数据、`Blob`、`Date`、`Map`、`ArrayBuffer` 等；不传 DOM、Vue 对象、能力句柄或函数。

完整写法见[界面与状态](../20.development/10.frontend/40.view-and-state.md)。

## 后端入口

后端有三种代码路线：

| 入口 | 放哪 | 怎么登记 |
| --- | --- | --- |
| HTTP 接口 | `handlers/**/*.ts` | 自动发现；文件路径 + 命名导出 = 接口名 |
| 事件回调 | `events/*.ts` | 清单 `events[]` 引用 |
| 流程脚本 | `adapters/*.ts` | 清单 `scripts[]` 引用 |

后端脚本是同步沙箱：没有 `async/await`、计时器、动态 `import()`、`require` 或 `eval`。能力按 `allowlist` 注入为全局对象；没申报的对象根本不存在，不是返回 `undefined`。

## 跨宿主服务和数据保存

跨宿主通信服务（Service）用于**同一前端插件在不同宿主中的短期协作**。例如项目侧请求消息侧打开派遣卡。服务按插件 ID 隔离，不是跨插件调用，也不是后端 HTTP 接口。

入口变量、Vue 状态和 Service 都不负责长期保存数据。需要持久化时使用配套后端存储；本地后端模拟器是进程内存，重启会丢失，不能当成生产数据库。
