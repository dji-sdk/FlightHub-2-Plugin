# 后端运行时、入口与权限

后端插件运行在服务端 Worker 的同步脚本沙箱里。它不通过 `ctx.capabilities.get()` 获取能力，也没有前端扩展点；入口由目录约定或清单声明，能力按 `allowlist` 注入为全局对象。

先记住三件事：

- `ctx` 只带这次调用的信息，不带数据库、网络等能力。
- 业务逻辑有三种路线：HTTP 接口、事件回调、流程脚本；另有一个只读判定入口 `evaluators`。
- 下发任务、返航等高风险动作只走流程受控步，不在脚本能力里。

## 四种入口

| 入口 | 代码位置 | 登记方式 | 名字怎么来 |
| --- | --- | --- | --- |
| HTTP 接口 | `handlers/**/*.ts` | 自动发现 | 文件路径 + 命名导出，例如 `handlers/issue/create.ts` + `export function create` → `issue.create` |
| 事件回调 | `events/*.ts` | 清单 `events[]` 引用 | `consumer.entry` 指定导出名 |
| 流程脚本 | `adapters/*.ts` | 清单 `scripts[]` 引用 | `name` 字段，缺省取文件名 |
| 只读判定 | `evaluators/*.ts` | 清单 `evaluators[]` 引用 | `name` 字段；由受审步 `evaluate` 调用 |

流程 JSON 放在 `workflows/`，必须在清单 `flows[]` 中列出才会装载。只保存 JSON 不等于登记，也不等于打包。

- HTTP 接口源码写 `export function create`，构建后生成运行时入口 `h_issue_create`。
- 调用方可用 `h_issue_create`、`issue_create` 或 `issue.create` 三种写法。
- 事件和流程脚本的 `entry` 由清单指定；`evaluators` 注入面为空，只能使用 `log`，适合纯判定。

## 能力按 allowlist 注入

后端能力不是 `ctx` 上的方法，而是平台按清单注入的全局对象：

```json
{
  "allowlist": ["data:read", "data:write", "media:read"]
}
```

```ts
// handlers/issue/list.ts
export function list (input: RecordInput, _ctx: HandlerCtx) {
  const page = store.query('issue', {}, { limit: 20 })
  log.info('list', { total: page.data.total })
  return { total: page.data.total }
}
```

- 没申报的对象**根本不存在**，不是返回 `undefined`；看到 `store is not defined` 先查 `allowlist`。
- 申报平台授不出的能力名会导致插件进程起不来。
- 流程脚本的非空 `scripts[].allowlist` 覆盖包级列表；为空或未写时回落包级。
- `evaluators` 不吃包级 `allowlist`，注入面恒空。
- `ctx` 只带本次调用事实（平台时间、幂等键、请求 ID 等），不带能力方法。

完整能力总表见[后端能力目录](../70.api-reference/20.backend/80.host-capability-catalog.md)。

## 同步沙箱

后端脚本是同步执行的，不能使用：

- `async/await`、Promise 回调
- `setTimeout` / `setInterval`
- 动态 `import()`、`require`
- `eval` / `new Function`
- Node 内置模块和裸包导入

允许从 `./` 相对路径导入本插件内的模块，共用逻辑放 `shared/`。需要延迟、重试、等待或长流程时，用流程编排，不要在脚本里写循环等待。

## 飞行控制不在脚本能力里

下发任务、返航等高风险动作从不注入脚本。脚本里没有飞行函数；只能通过流程 JSON 里的平台受控步完成，由平台在这些步骤上做校验。

## 最小清单

```json
{
  "pluginId": "exp_issue_backend",
  "name": "现场问题后端",
  "version": "1.0.0",
  "contractsRange": ">=1.1.0 <2.0.0",
  "allowlist": ["data:read", "data:write"],
  "events": [],
  "scripts": [],
  "flows": []
}
```

`version` 是插件自己的版本，不一定等于开发者工具版本。`contractsRange` 表示兼容的后端宿主契约范围；留空会失去装载保护。

## 常见误解

| 误解 | 实际 |
| --- | --- |
| 后端也可以用 `ctx.capabilities.get()` | 不能；能力是 `allowlist` 注入的全局对象 |
| 申报了权限就一定可用 | 只代表允许注入；提供方和运行条件仍可能不可用 |
| 脚本可以 `await` 一个接口 | 脚本同步执行；长流程用流程编排 |
| 脚本可以调飞行函数 | 不能；飞行控制只走流程受控步 |
| 只读判定可以读写数据 | 不能；`evaluators` 的注入面为空，只保留 `log` |
| 本地模拟器通过就能部署 | 不能；本地不执行真实 Workflow/队列，网关和存储也不同 |
