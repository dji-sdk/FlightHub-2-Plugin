# 第一个后端插件

这一页带你构建一个带 HTTP 接口的后端插件，再启动本地调试服务。后端插件用 TypeScript 编写：写接口脚本和源清单，工具链负责编译打包，平台负责加载和调用。首次调用推荐接着完成[全栈入门](./40.first-fullstack-plugin.md)，由前端通过 `ctx.apiCall` 受管调用；直接 curl 诊断使用本地后端调试网关的本次输出地址与凭据。

## 后端插件长什么样

一个后端插件 = 一个含 `fh2-plugin.json`（**源清单**）的目录。你写 TypeScript；`fh2-plugin build` 把它编译打包成运行时可装载的 JS 和 `dist/plugin.json`（运行时清单，不要手改）。

调用方通过统一入口调你的接口：

```text
POST /plugin/invoke
{ "pluginId": "exp_hello_backend", "handler": "example.create", "input": { "record_key": "demo-1", "title": "第一条记录" } }
```

平台按 `pluginId + handler` 找到构建后的入口函数执行，返回值原样给调用方。

## 前置条件

- 已完成[环境准备](./10.environment-preparation.md)。

> fh2-plugin-sdk 是插件开发 SDK；模块路径示意，实际导入保留生成工程配置。本页不提供同名 npm 包的安装指令；修改示例时保留生成文件的真实导入语句，只调整函数体和类型声明。

## 1. 用向导创建一个带后端的完整能力

本页默认创建完整能力工作区：外层工作区和内层能力目录同名，一个工程同时包含前端和后端，共享一套配置。在[环境准备](./10.environment-preparation.md)选定的工程父目录执行，保持 `FH2_TOOLS` 指向已初始化的固定源码。不做全局注册时，把下面的 `fh2-plugin` 换成环境准备中的源码 bin 调用：

```bash
cd "$HOME/fh2-plugin-dev"
fh2-plugin create
```

按向导填写：

| 向导问题 | 本页填写 |
| --- | --- |
| 工程类型 | `0`（完整 Capability） |
| 工作区目录 | `exp_hello` |
| Capability 名称 | `第一个后端插件` |
| 包管理器 | `pnpm` |
| 是否立即安装依赖 | `是` |

目录名同时作为能力 ID；成员 ID 自动派生为 `exp_hello_frontend`、`exp_hello_issues` 和 `exp_hello_backend`。若 `exp_hello` 已经存在（例如快速入门刚创建过），**直接复用该工程，不要再次 create**；需要一份干净工程时，向导的工作区目录改用未占用名称，并把本文的 `exp_hello` 与派生 ID 同步替换。等待依赖安装和安装后类型复验完成后再继续。脚本自动化才需要长参数，见 [CLI 参考](../../70.api-reference/10.frontend/70.toolchain-cli.md#交互创建与自动化创建)。

```bash
cd exp_hello
pnpm run generate
pnpm run validate
```

> 只想要独立后端工程时，向导的“工程类型”选择 `2`（后端插件），再按提示填写 Plugin ID、目录和名称。本文后续目录与全栈教程按完整能力工作区讲解。

生成的工程长这样（注意三层：工作区根 → 能力工程目录 → 各插件）：

```text
exp_hello/                                # 工作区根
├── package.json                          # 工作区脚本（generate/validate/dev/build/pack 都在这跑）
├── packages.json                         # 平台上传清单
└── exp_hello/                            # 能力工程目录（与外层工作区同名）
    ├── capabilities.json                 # 能力声明（名称与描述）
    ├── frontend/exp_hello_frontend/           # 前端插件（下一篇全栈教程用）
    ├── frontend/exp_hello_issues/             # 另一个前端示例（本页先不管）
    ├── backend/exp_hello_backend/             # 后端插件（本页重点）
    └── mock/                             # 本地模拟数据与事件样例
```

成员 ID 从能力 ID `exp_hello` 自动派生。**前后端是两个不同的插件 ID**，记住这一点，全栈教程里会用到。

## 2. 认识后端插件

`exp_hello/backend/exp_hello_backend/` 目录（下文简称后端插件目录）：

```text
├── fh2-plugin.json      # 源清单：身份、权限、声明有哪些脚本和流程
├── handlers/            # HTTP 接口脚本（放进去自动登记，一个文件一个接口）
│   └── example/
│       ├── create.ts    #   → 接口名 example.create
│       ├── list.ts      #   → 接口名 example.list
│       └── get.ts       #   → 接口名 example.get
├── events/              # 消息回调脚本（由清单 events[] 引用）
│   └── example-created.ts
├── adapters/            # 流程用脚本（由清单 scripts[] 引用）
│   └── example-script.ts
├── workflows/           # 流程编排 JSON（由清单 flows[] 列出）
│   └── example-flow.json
├── shared/              # 多入口共用的业务逻辑
├── types/               # fh2-plugin types 生成的类型声明，不要手改
├── schema.sql           # 建表 SQL：存储契约的唯一事实源
└── tsconfig.json
```

打开 `fh2-plugin.json`（源清单）：

```json
{
  "pluginId": "exp_hello_backend",
  "name": "第一个后端插件 后端",
  "version": "0.1.0",
  "description": "后端插件示例：接口、事件和流程脚本复用记录处理逻辑，构建后由插件运行时执行。",
  "contractsRange": ">=1.1.0 <2.0.0",
  "allowlist": ["data:read", "data:write"],
  "flows": ["workflows/example-flow.json"],
  "connections": [],
  "scripts": [
    {
      "description": "记录写入的流程脚本：与 HTTP 接口处理函数复用处理逻辑，通过 record_key 唯一键保证幂等。",
      "name": "example-script",
      "path": "adapters/example-script.ts",
      "entry": "handle",
      "io": {
        "inputs": [
          { "name": "record_key", "type": "string", "required": true },
          { "name": "title", "type": "string", "required": true }
        ],
        "outputs": [
          { "name": "id", "type": "string" },
          { "name": "created", "type": "bool" }
        ]
      }
    }
  ],
  "events": [
    {
      "description": "消息队列里来一条 example.created 就幂等地落一条记录(source=event)。",
      "type": "example.created",
      "consumer": [
        { "handler": "events/example-created.ts", "entry": "onExampleCreated" }
      ]
    }
  ]
}
```

四个关键点：

- **`allowlist` 是权限声明**。申报了 `data:read`/`data:write`，脚本里才有 `store` 这个全局对象可用；没申报的对象根本不存在。
- **存储不在这里声明**。数据表由 `schema.sql` 单点定义，工具链从它派生存储实体——不要在清单里再写一份。
- **HTTP 接口不用逐个登记**。放在 `handlers/` 目录下就会被自动发现。
- **流程和事件要显式列出**。`flows[]`、`scripts[]`、`events[]` 是白名单，列了才装载。

## 3. 读一个接口

模板自带的 `handlers/example/create.ts`（这就是"新增一个接口 = 新增一个文件"）：

```ts
import { createRecord } from '../../shared/records'
import type { RecordResult, RecordInput } from '../../shared/records'
import type { HandlerCtx } from 'fh2-plugin-sdk/backend'

export function create (input: RecordInput, _ctx: HandlerCtx): RecordResult {
  // source 记录"这条记录从哪种入口来"
  return createRecord(input, 'handler')
}
```

命名规则：**文件路径 + 命名导出 = 接口名**。`handlers/example/create.ts` + `export function create` → 接口名 `example.create`（构建后生成稳定入口名 `h_example_create`，调用时 `example.create` / `example_create` / `h_example_create` 三种写法都认）。

业务逻辑在 `shared/records.ts` 里，被 HTTP、事件、流程三种入口共用。`createRecord` 做三件事——校验输入、幂等落库、回执：

```ts
export function createRecord (input: RecordInput, source: string): RecordResult {
  const recordKey = requireText(input, 'record_key')   // 必填校验，缺失抛 INVALID_ARGUMENT
  const title = requireText(input, 'title')
  const got = createStoreRecord('example_record', {
    record_key: recordKey,                             // 业务唯一键
    title,
    source,                                            // 'handler' / 'event' / 'workflow'
    status: 'pending',
    handled_at_ms: '',
  }, ['record_key'])                                   // 唯一键 = record_key
  const record = got.record
  return {
    id: String(record.id),
    record_key: recordKey,
    title,
    source,
    status: String(record.status),
    created: got.created === true,                     // false = 幂等命中已有记录，不是错误
  }
}
```

所以调 `example.create` 至少要传 `record_key` 和 `title`。想加自己的接口？复制 `create.ts` 换一个文件名和导出名（如 `handlers/example/archive.ts` + `export function archive` → `example.archive`），详细规则见 [HTTP 接口](../20.backend/20.http-handler.md)。

## 4. 启动本地后端调试

在工作区根（`exp_hello/`）执行：

```bash
pnpm exec fh2-plugin dev --root exp_hello/backend/exp_hello_backend
```

这条命令在后端插件目录上只构建并运行独立后端调试网关，不打开前端页面；终端会打印本次 Gateway URL 和本地调用凭据。工作区根的 `pnpm run dev:backend` 是 Workbench 的 backend-only 模式，供浏览器链路使用，不是本节的独立 curl 网关。`build` / `pack` 只生成产物，不监听端口；仅完成构建不能调用接口。保持该命令运行后，可按本页 curl 验证接口，也可停止后改用[全栈入门](./40.first-fullstack-plugin.md)的完整 `dev` 界面链路。

### 本地 curl 诊断

以下请求只用于本机调试。将终端本次打印的 Gateway URL 和本地调用凭据填入变量；不要复用历史端口或令牌，也不要写入源码、日志或报告。仅完成 `build` 不会使接口可访问。

| 环境变量 | 来源与约定 |
| --- | --- |
| `FH2_DEV_URL` | 本次终端打印的后端 Gateway URL |
| `FH2_PLUGIN_TOKEN` | 本次终端打印的本地调用凭据 |

```bash
FH2_DEV_URL='<本次打印的后端 Gateway URL>'
FH2_PLUGIN_TOKEN='<本次打印的本地调用凭据>'

# 新建记录；使用点分名调用 example.create
curl -sS -X POST "$FH2_DEV_URL/plugin-api/plugin/invoke" \
  -H "Origin: $FH2_DEV_URL" \
  -H "x-plugin-token: $FH2_PLUGIN_TOKEN" \
  -H 'content-type: application/json' \
  -H 'idempotency-key: demo-001' \
  --data '{"pluginId":"exp_hello_backend","handler":"example.create","input":{"record_key":"demo-1","title":"第一条记录"}}'
```

首次创建成功时，响应的 `data.created` 为 `true`：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": "…",
    "record_key": "demo-1",
    "title": "第一条记录",
    "source": "handler",
    "status": "pending",
    "created": true
  }
}
```

再试两个场景，体会幂等的两层：

**同一个 `record_key`、换一个新的 `idempotency-key`**（把 `demo-001` 改成 `demo-002`，其余原样再发一次）——业务唯一键命中，`created` 变成 `false`，不会出第二条记录。这是 `createIfAbsent` + `record_key` 唯一索引的幂等。

**同一个 `idempotency-key` 原样重发**——本地运行时直接返回第一次的缓存结果（`created` 仍是 `true`）。这是网关层的请求幂等，重试不会重复执行。写操作要传业务上稳定的幂等键，读操作不用传。

再投一条本地模拟事件，并验证事件重放不会产生第二条记录：

```bash
# mock/events/ 相对外层工作区根
curl -sS -X POST "$FH2_DEV_URL/plugin-api/mock/backend/event" \
  -H "Origin: $FH2_DEV_URL" \
  -H 'content-type: application/json' \
  --data-binary @exp_hello/mock/events/example-created.json

# 同一业务键、换消息 id 再投一条
curl -sS -X POST "$FH2_DEV_URL/plugin-api/mock/backend/event" \
  -H "Origin: $FH2_DEV_URL" \
  -H 'content-type: application/json' \
  --data '{"id":"evt-2","type":"example.created","data":{"record_key":"from-event-1","title":"事件来的"}}'
```

最后看列表和本地内存快照（读操作，不带幂等键）：

```bash
curl -sS -X POST "$FH2_DEV_URL/plugin-api/plugin/invoke" \
  -H "Origin: $FH2_DEV_URL" \
  -H "x-plugin-token: $FH2_PLUGIN_TOKEN" \
  -H 'content-type: application/json' \
  --data '{"pluginId":"exp_hello_backend","handler":"example.list","input":{}}'

curl -sS "$FH2_DEV_URL/plugin-api/mock/backend/state" \
  -H "Origin: $FH2_DEV_URL"

unset FH2_DEV_URL FH2_PLUGIN_TOKEN
```

`/plugin-api/mock/backend/state` 是本地调试辅助接口，不是部署环境的业务 API。本地成功只证明 Mock 网关、脚本调用和内存存储工作，不证明真实数据库、消息队列或目标网关已就绪。

## 预期结果与自查

- [ ] `pnpm run validate` 通过（校验清单、流程、脚本入口的一致性）。
- [ ] 保持后端 Dev Gateway 命令运行，用本次打印的 Gateway URL 和凭据完成创建、业务幂等、事件重放和列表调用；本地快照能看到数据。
- [ ] 同 `record_key` 换幂等键重调，`created: false`，快照里没有第二条。
- [ ] 明白目录和成员 ID 的区别：外层工作区/能力 ID 都是 `exp_hello`，后端插件 ID 是 `exp_hello_backend`。
