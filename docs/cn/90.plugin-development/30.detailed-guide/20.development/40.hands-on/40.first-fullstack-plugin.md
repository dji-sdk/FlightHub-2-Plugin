# 第一个全栈插件

这一页把前端和后端接起来：在面板里填一个标题 → 点按钮调后端接口 → 数据存进本地后端内存 → 保持同一 dev 进程运行，刷新页面后再读回来。本文适用 Toolchain / SDK `1.0.0`，演示前后端协作，不证明数据已持久化。

## 前置条件

- 已完成[第一个后端插件](./30.first-backend-plugin.md)的工程创建与校验（已有 `exp_hello` 能力工程；若快速入门已创建同名工程则直接复用，不要重复 create，需要干净工程时先在后端教程选择新的未占用目录）；不要求先取得 curl 凭据。
- 端口 5175 空闲。

> fh2-plugin-sdk 是插件开发 SDK；模块路径示意，实际导入保留生成工程配置。本页不表示同名 npm 包已发布；已有文件保留真实导入语句，仅替换函数体与类型声明，新文件参照同一生成工程中相应 API 的真实导入路径，不添加模块别名。

## 1. 先记住两个 ID 和一条通道

同一个能力工程里，前端插件和后端插件是**两个不同的插件**：

| | 前端插件 | 后端插件 |
| --- | --- | --- |
| ID | `exp_hello_frontend` | `exp_hello_backend` |
| 位置 | `exp_hello/exp_hello/frontend/exp_hello_frontend/` | `…/backend/exp_hello_backend/` |

调用通道只有一条：

```text
前端 ctx.apiCall('/plugin/invoke', { body: { pluginId, handler, input } })
        │  pluginId 必须写后端的那个 ID（不是前端的）
        ▼
插件运行时（自动处理鉴权、自动加 /plugin-api 前缀）
        │
        ▼
后端按 (pluginId, handler) 执行入口函数
```

本页功能修改共 6 个文件，全部在前端插件目录 `…/frontend/exp_hello_frontend/` 下（下面统一省略这个前缀）。除特别说明外，每个代码块都是**整文件替换**；不要在旧文件上猜局部 diff 或导入接线。第 8 节还会新建一个测试文件，用于验证失败调用不会变成未处理拒绝。

这是推荐的首次接口调用路径：插件 SDK 的 `ctx.apiCall` 交由宿主提供的网络通道处理，插件不获取或硬编码令牌。

## 3. 调用封装：src/shared/backend.ts（新建）

新建 `src/shared/backend.ts`，并用下面内容**整文件替换**。整个工程共用这一份封装；三件事写死在里面：后端插件 ID、单 `/` 开头的接口路径、错误怎么抛：

```ts
import { isPluginError } from 'fh2-plugin-sdk'
import type { JsonValue, PluginContext } from 'fh2-plugin-sdk'

// 后端插件 ID：能力工程里默认是 <capabilityId>_backend，与前端 ID 不同。
const BACKEND_PLUGIN_ID = 'exp_hello_backend'

// bizKey 传业务上稳定的键（如记录 ID）：写操作传，重试不会变成两次请求；读操作不传。
export async function invoke<T> (
  ctx: Pick<PluginContext, 'apiCall'>,
  handler: string,
  input: Record<string, JsonValue>,
  bizKey?: string,
): Promise<T> {
  try {
    let idempotencyKey: string | undefined
    if (bizKey !== undefined) {
      const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(bizKey))
      const digest = Array.from(new Uint8Array(hash), byte => byte.toString(16).padStart(2, '0')).join('')
      idempotencyKey = `${handler}-${digest}`
    }
    const res = await ctx.apiCall<{ code: number; message: string; data: JsonValue }>('/plugin/invoke', {
      method: 'POST',
      body: { pluginId: BACKEND_PLUGIN_ID, handler, input },
      ...(idempotencyKey === undefined ? {} : { idempotencyKey }),
    })
    // 只有网关返回 code === 0 才会走到这里，data 就是业务数据
    return res.data as T
  } catch (error) {
    if (isPluginError(error) && error.code === 'PLUGIN_GATEWAY_ERROR') {
      // 本地与目标网关的非零数字码在 detail.gatewayCode；网络或格式错误可能没有该字段
      const detail = (error.detail ?? {}) as { gatewayCode?: number; gatewayMessage?: string }
      throw new Error(`[网关 ${detail.gatewayCode ?? '?'}] ${detail.gatewayMessage ?? error.message}`)
    }
    if (isPluginError(error)) {
      throw new Error(`${error.code}: ${error.message}`)
    }
    throw error
  }
}
```

三个易错点：

- 接口路径写 `/plugin/invoke`，**不要**自己加 `/plugin-api` 前缀或写完整网址，网关负责。
- 失败不是返回值：`code !== 0` 时 `ctx.apiCall` 直接抛 `PluginError`（code 是 `PLUGIN_GATEWAY_ERROR`，真实业务码在 `detail.gatewayCode`），不会走到返回值那一行。
- 幂等键必须业务稳定（同一个操作重试时键不变）。读操作不传。

业务键可能包含长中文，不能把原文或不定长的 URL 编码直接放进请求头。这里在插件入口内用浏览器 Web Crypto 的 SHA-256 对 `bizKey` 做摘要，转成固定 64 个十六进制 ASCII 字符，再带上接口名前缀。相同接口名和相同业务键每次生成相同请求键，无随机值；请求体中的业务数据不变。

`apiCall` 的请求键限额是 1–256 字符。本例 `example.create-<摘要>` 长度为 79；该拼法要求接口名前缀不超过 191 字符，普通示例接口名远小于它。摘要解决长业务键的请求头长度，不替代业务唯一索引或完整的生产重试设计。此实现依赖浏览器 `TextEncoder` / `crypto.subtle`；Web Crypto 需要安全上下文，使用本地回环地址或目标 HTTPS 环境。

封装只需要 `apiCall`，所以用 `Pick<PluginContext, 'apiCall'>` 接受各插件生成的具体上下文，不要求它提供无关扩展声明。HTTP 传输按 `JsonValue` 约束；`T` 是本插件维护的接口数据结构，这里的类型转换不替代业务数据校验。

## 5. 入口：src/hosts/cockpit/hello-example.ts

状态仍由插件入口持有；`createRecord` 调后端、`listRecords` 拉列表，成功失败都写回状态。用下面内容**整文件替换** `src/hosts/cockpit/hello-example.ts`；导入路径已按生成工程写好，不需要另配别名：

```ts
import { createViewState } from 'fh2-plugin-sdk'
import type { AppCockpitContext } from '../../generated/plugin-types'
import { helloPanelView } from '../../views/hello-panel/contract'
import type { HelloPanelState, RecordSummary } from '../../views/hello-panel/contract'
import { invoke } from '../../shared/backend'

interface RecordListResult {
  readonly items: ReadonlyArray<RecordSummary>;
  readonly total: number;
}

function errorMessage (error: unknown, action: string): string {
  return `${action}失败：${error instanceof Error ? error.message : String(error)}`
}

/** 入门示例：工具栏按钮打开左侧面板；面板里可计数、创建并查看后端记录。 */
export async function registerHelloExample (ctx: AppCockpitContext): Promise<void> {
  const state = createViewState<HelloPanelState>({ count: 0, records: [], message: '' })

  // 拉一次列表并写回状态；失败也返回状态，不让 Vue 事件得到未处理拒绝。
  // messagePrefix 用于保留创建失败信息；刷新再失败时组合呈现两段错误。
  async function refreshRecords (messagePrefix = ''): Promise<HelloPanelState> {
    try {
      const result = await invoke<RecordListResult>(ctx, 'example.list', {})
      state.update(current => ({ ...current, records: result.items, message: messagePrefix }))
      return state.get()
    } catch (error) {
      const refreshMessage = errorMessage(error, '刷新')
      state.update(current => ({
        ...current,
        message: messagePrefix === '' ? refreshMessage : `${messagePrefix}；${refreshMessage}`,
      }))
      return state.get()
    }
  }

  await helloPanelView.handle(ctx, {
    state,
    methods: {
      increment: () => {
        state.update(current => ({ ...current, count: current.count + 1 }))
        return state.get()
      },
      async createRecord (input: { record_key: string; title: string }) {
        let createMessage = ''
        try {
          // 写操作传业务稳定键：同一个 record_key 重试不会产生第二条
          await invoke(ctx, 'example.create', input, input.record_key)
        } catch (error) {
          createMessage = errorMessage(error, '创建')
          state.update(current => ({ ...current, message: createMessage }))
        }
        return await refreshRecords(createMessage)
      },
      listRecords: () => refreshRecords(),
    },
  })

  const panel = await ctx.extensions.contribute('hello-panel', {
    visible: false,
    label: '示例面板',
    icon: 'plugin',
    render: () => helloPanelView.get(ctx),
  })

  await ctx.extensions.contribute('hello-action', {
    icon: 'plugin',
    label: '打开示例面板',
    active: false,
    disabled: false,
    async onTrigger () {
      await panel.reveal()
    },
  })
}
```

## 6. 挂载：src/views/hello-panel/mount.ts

用下面内容**整文件替换** `src/views/hello-panel/mount.ts`。界面侧通过 `client` 调入口的方法——**方法平铺在 client 上**（`client.createRecord(...)`，不是 `client.methods.createRecord`）：

SDK `1.0.0` 的客户端把每个方法返回值投影为 `Promise<Awaited<返回类型>>`。入口 `increment` 可以同步返回状态，但这里的 `client.increment()` 和传给 Vue 的 `onIncrement` 都返回 `Promise<HelloPanelState>`。

```ts
import { createApp, reactive } from 'vue'
import type { Component } from 'vue'
import type { ViewInstance, ViewMountContext } from 'fh2-plugin-sdk'
import { helloPanelView } from './contract'

export function mountHelloPanel (ctx: ViewMountContext, component: Component): ViewInstance {
  const state = reactive({ count: 0, records: [] as Array<{ record_key: string; title: string }>, message: '' })
  const client = helloPanelView.client(ctx.port)
  const subscription = client.state.subscribe((next) => {
    state.count = next.count
    state.records = [...next.records]
    state.message = next.message
  })
  const app = createApp(component, {
    state,
    onIncrement: () => client.increment(),
    onCreate: (input: { record_key: string; title: string }) => client.createRecord(input),
    onRefresh: () => client.listRecords(),
  })
  app.mount(ctx.mountElement)

  return {
    dispose () {
      subscription.dispose()
      client.dispose()
      app.unmount()
    },
  }
}
```

（同目录的 `index.ts` 不用改。）

## 8. 失败调用单测

新建 `tests/hello-example.test.ts`，并用下面内容**整文件替换**。测试只做两件事：`listRecords` 失败时把错误写入状态并正常返回；`createRecord` 失败后刷新成功时保留创建失败信息。这里不引入重试或全局错误处理器。

```ts
import { describe, expect, it, vi } from 'vitest'
import type { AppCockpitContext } from '../src/generated/plugin-types'
import type { HelloPanelState } from '../src/views/hello-panel/contract'
import { registerHelloExample } from '../src/hosts/cockpit/hello-example'

interface CapturedViewOptions {
  state: { get: () => HelloPanelState };
  methods: {
    increment: () => HelloPanelState;
    createRecord: (input: { record_key: string; title: string }) => Promise<HelloPanelState>;
    listRecords: () => Promise<HelloPanelState>;
  };
}

const captured = vi.hoisted(() => ({ options: undefined as CapturedViewOptions | undefined }))

vi.mock('fh2-plugin-sdk', async (importOriginal) => {
  const actual = await importOriginal<typeof import('fh2-plugin-sdk')>()
  return {
    ...actual,
    definePluginView: vi.fn(() => ({
      handle: vi.fn(async (_ctx: unknown, options: CapturedViewOptions) => {
        captured.options = options
      }),
      get: vi.fn(),
    })),
  }
})

function createTestContext (apiCall: ReturnType<typeof vi.fn>): AppCockpitContext {
  return {
    apiCall,
    extensions: {
      contribute: vi.fn(async () => ({ reveal: vi.fn() })),
    },
  } as unknown as AppCockpitContext
}

function requireCapturedOptions (): CapturedViewOptions {
  const options = captured.options
  expect(options).toBeDefined()
  if (options === undefined)
    throw new Error('helloPanelView.handle 未被调用')
  return options
}

describe('hello-example 失败调用', () => {
  it('listRecords 失败时写入状态并返回当前状态', async () => {
    captured.options = undefined
    const apiCall = vi.fn().mockRejectedValueOnce(new Error('gateway unavailable'))
    await registerHelloExample(createTestContext(apiCall))

    const result = await requireCapturedOptions().methods.listRecords()

    expect(result.message).toBe('刷新失败：gateway unavailable')
    expect(result.records).toEqual([])
    expect(apiCall).toHaveBeenCalledWith('/plugin/invoke', expect.objectContaining({
      method: 'POST',
      body: {
        pluginId: 'exp_hello_backend',
        handler: 'example.list',
        input: {},
      },
    }))
  })

  it('createRecord 失败后刷新成功时保留创建失败信息', async () => {
    captured.options = undefined
    const apiCall = vi.fn()
      .mockRejectedValueOnce(new Error('create rejected'))
      .mockResolvedValueOnce({
        code: 0,
        message: 'success',
        data: {
          items: [{ record_key: 'demo-1', title: '第一条记录' }],
          total: 1,
        },
      })
    await registerHelloExample(createTestContext(apiCall))

    const result = await requireCapturedOptions().methods.createRecord({
      record_key: 'demo-1',
      title: '第一条记录',
    })

    expect(result.message).toBe('创建失败：create rejected')
    expect(result.records).toEqual([{ record_key: 'demo-1', title: '第一条记录' }])
  })
})
```

## 9. 验证

在外层工作区根（`exp_hello/`，有 **`package.json` + `packages.json`**；下方路径相对这个目录）按顺序执行：

```bash
pnpm run generate
pnpm run validate
pnpm run test
pnpm --dir exp_hello/frontend/exp_hello_frontend run tsc
pnpm --dir exp_hello/frontend/exp_hello_frontend run lint
pnpm run build
```

以上命令全部通过后，再启动完整开发链路：

```bash
pnpm run dev
```

本页在外层工作区根运行 `pnpm run dev`，默认端口为 5175；后面的 curl 使用同一地址。

`build` / `pack` 不启动接口服务。上述本地界面验证依赖持续运行的 `dev`，它为能力工程提供插件运行时与本地 HTTP 模拟器。数据仅保存在当前 dev 进程内；下面的页面刷新测试期间不要重置后端、重启 dev 或改变实体结构。本轮写入在这些情况下会丢失并恢复初始数据，不是持久化数据库。

打开本地调试页面后，先按[前端入门](./20.first-frontend-plugin.md#_3-跑起来)的设备小窗步骤进入驾驶舱，再验证：

1. 在**直播左侧竖排工具栏的插件区**悬停找到“打开示例面板”（当前 Mock 通用插件区在 AR 之前），点开面板。填记录键（如 `demo-ui-1`）和标题，点**创建记录**——列表里出现这条记录。
2. 换一个记录键再创建一条，列表变成两条。
3. **用第二条的记录键再点一次创建**——列表总数仍为两条，不会产生第三条（`record_key` 唯一键幂等）。
4. **刷新页面**，重新打开面板，点**刷新列表**——同一 dev 进程未重置时记录还在。这只证明后端内存不随浏览器刷新丢失；重启服务后的持久化读回须在目标环境另验。
5. 不填记录键直接创建——本地 HTTP 400 / 数字 `40006`，面板显示「创建失败」及 `[网关 40006] INVALID_ARGUMENT: record_key 不能为空`，而不是白屏。

| 验证范围 | 支持边界 |
| --- | --- |
| 本地失败提示 | 当前本地后端返回数字信封；非零码使 `ctx.apiCall` 抛 `PLUGIN_GATEWAY_ERROR`，数字码在 `detail.gatewayCode`，原错误标识在 `gatewayMessage` |
| HTTP 与目标环境 | 数字分类对齐不代表 HTTP 状态一致；本地 `NOT_FOUND` 为 404 / `20001`，未分类 `BRIDGE_FAILED` 为 400 / `50301`，不能把 HTTP 400 一律当契约错。目标网关、真实存储和重试行为另验，见[后端调试](../../40.debug-and-test/30.backend-debugging.md#已知限制) |


保持本机 `dev` 运行时，也可以用 curl 查看内存存储快照；这个无需令牌的回环调试接口不用于部署环境：

```bash
curl -sS 'http://127.0.0.1:5175/plugin-api/mock/backend/state' -H 'Origin: http://127.0.0.1:5175'
```

## 预期结果与自查

- [ ] 前端清单已声明 `platform:http`；调用的 `pluginId` 是后端的 ID（`…_backend`）。
- [ ] 只有入口代码调 `ctx.apiCall()`，界面代码只通过通道要数据（`HelloPanel.vue` 里没有 `ctx`）。
- [ ] 界面用平铺方法调用（`client.createRecord(...)`），不是 `client.methods.createRecord`。
- [ ] `listRecords` 失败时面板显示“刷新失败”，方法 Promise 正常返回；`createRecord` 失败后若刷新成功，创建失败信息不被覆盖。
- [ ] 同一 dev 进程未重置时，创建的数据在页面刷新后仍能读回；未把内存读回当成持久化验收。
- [ ] `code !== 0` 时界面显示了错误信息，而不是白屏。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 调用被拒、报能力不可用 | 前端清单没声明 `platform:http`，或改完清单没跑 `generate` |
| 本地 HTTP 404 / `code: 40006`，文案含 `HANDLER_NOT_FOUND` 或 `PLUGIN_NOT_FOUND` | `handler` 字段中的接口名和后端文件路径对不上；或 `pluginId` 写成了前端的 ID |
| 界面显示 `[object Object]` | 把整个信封当数据用了；封装里取 `data` 字段 |
| 点了没反应、控制台报 `client.methods is not a function` | 界面客户端的方法是平铺的，写 `client.createRecord(...)` |
| 列表不更新 | `state.update` 要返回**新对象**（`{ ...current, records: … }`），返回原对象不会通知订阅者 |
| 控制台出现未处理拒绝 | 检查是否绕过 `refreshRecords` 直接返回 `invoke`；入口方法应捕获调用失败并返回状态 |
| 找不到“打开示例面板” | 进入驾驶舱，确认插件已启用，按钮位置见[打开插件面板](../../../10.quick-start/10.first-plugin.md#_3-启动驾驶舱打开插件面板) |
| 本地正常、真实环境不行 | 按[HTTP 真实环境预览](../../40.debug-and-test/20.frontend-debugging.md#转到真实环境)使用完整项目页 URL，配置 PAC、同源登录、手填本次资源根并完成宿主校验/权限同意/重载；preview 只覆盖前端，后端用目标环境已安装版本 |
