# 触发方式

每条流程必须声明**至少一种触发方式**。触发方式写在流程 JSON 的 `trigger` 字段里，五种可以并存：

```json
{
  "trigger": {
    "api": { "seed": ["taskUuid"] },
    "schedule": { "intervalSec": 300 }
  }
}
```

| 触发方式 | 一句话 | 典型场景 |
| --- | --- | --- |
| `api` | 外部 HTTP 调启动端点 | 人工触发、前端按钮、其他服务调用 |
| `schedule` | 按固定间隔定时执行 | 每 5 分钟采集一次数据 |
| `stream` | 统一事件模型的消息到达时执行 | 警情签收后启动处置流程 |
| `bizNotify` | 业务任务系统的任务通知到达时执行 | 巡逻任务下发后启动巡逻流程 |
| `job` | 只能被插件自己的代码用 `flow.start` 启动 | 消息回调里触发后处理作业 |

## api：HTTP 启动

```json
{ "api": { "seed": ["taskUuid", "projectUuid"] } }
```

- 声明后，`POST /flows/<流程名>/start` 才可用；**没声明时调用返回 40301**（是"不允许"不是"不存在"）。
- `seed` 列出调用方要传的字段名，调用时放在请求体的 `trigger` 对象里，流程步骤用 `trigger.<字段名>` 取用。`seed` 可以为空数组——那就是一个纯按钮流程。
- 幂等：同一个 `bizId` 永远对应同一条流程实例，重复启动返回 `already: true` 而不是再跑一条。

## schedule：定时执行

```json
{ "schedule": { "intervalSec": 30, "paused": false } }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `intervalSec` | ✅ | 间隔秒数 |
| `executionTimeoutSec` |  | 单次执行的超时 |
| `paused` |  | `true` 表示建好但不跑（先上线后放开） |

平台负责维护调度，你只声明"多久跑一次"和是否暂停。上一轮没跑完不会堆积——调度不会并发启动同一流程的多个实例。定时与队列行为在已部署测试环境验证，本地 `dev` 不执行流程。

## stream：事件消息触发

> **什么是"统一事件模型"**：平台维护的一个统一事件库。警情、设备上报、媒体入库这类"发生了什么事"都以事件的形态存在其中，每个事件有标准字段（`eventId`、`eventType`、`status`、发生时间、坐标、`payload` 等）。它有三个用途：插件用 `platform.insertEvent()` **写入**事件；流程用 `stream` 触发**消费**事件；用 `update_event_status` 步骤**更新**事件状态。你在[消息订阅](./30.event-handler.md)里订阅的 `media.photo_created` 等消息，也是从平台事件链路产生的。

```json
{
  "stream": {
    "match": { "status": "unacknowledged", "event_type": "警情" },
    "seed": ["eventId", "eventType", "occurredAt", "priority", "lat", "lng", "payload"]
  }
}
```

- 消费统一事件模型的消息流；`match` 是消息顶层字段的等值筛选（AND），**必须非空**——不做无条件的全收订阅。
- `match` 可用的字段：`event_id`、`event_type`、`tenant_id`、`source`、`status`、`priority`、`occurred_at`、`flight_mission_id`、`result_code`、`notify_on`、`payload`（`payload` 只能整体匹配）。
- `status` 字段的取值必须在清单 `eventStatuses` 里声明过（装载时校验）。
- `seed` 是允许播进流程触发的字段白名单（驼峰命名），步骤用 `trigger.<字段名>` 取用；`lat`/`lng` 可从消息坐标派生。
- `paused: true` 可暂停消费。

## bizNotify：业务通知触发

```json
{
  "bizNotify": {
    "subscriber": "patrol_demo",
    "seed": ["taskUuid", "projectUuid", "dockSn", "waylineUuid", "occurredAt"],
    "params": {
      "recheck_delay_sec": { "as": "recheckDelaySec", "type": "number", "max": 1800 }
    }
  }
}
```

- 消费业务任务系统的下发通知，按任务的 `biz_ext` 顶层键与 `subscriber` 匹配（`biz_ext` 是任务上的业务扩展字段区，下发方在创建任务时把业务参数放在其中某个键下）。
- `params` 声明允许透传的业务扩展参数：`as` 改名、`type` 校验类型、`max` 限上限——白名单之外的字段一律不进流程。

## job：只能被插件代码启动

```json
{ "job": { "seed": ["event_id", "video_file_id"] } }
```

- 声明 `job` 轴后，这个流程**只能**被插件脚本里的 `flow.start(flowName, bizId, seed)` 启动（需要 `flow:start` 权限），外部 HTTP 启动会拒绝。
- `seed` 逐字对账：`flow.start` 传的字段多了少了都报契约错——接口契约由声明锁定。
- 典型用法：[消息订阅](./30.event-handler.md)收到视频回调 → 匹配到待处理记录 → `flow.start` 启动后处理流程。

```js
// 事件回调里启动 job 流程
flow.start('lane-change-postprocess', eventId, {
  event_id: eventId,
  video_file_id: fileId,
})
// 返回 { already } —— 同一个 bizId 重复启动是幂等的，already=true 是正常表现
```

## 组合使用

一个流程可以同时有多个触发轴。例如巡逻抓拍流程：`bizNotify`（任务下发自动启动）+ `api`（提供手工重放入口）。

```json
{
  "trigger": {
    "bizNotify": { "subscriber": "patrol_demo", "seed": ["taskUuid"] },
    "api": { "seed": ["taskUuid"] }
  }
}
```

## 常见坑

| 现象 | 原因 |
| --- | --- |
| 装载失败提示 `缺 trigger` | 流程 JSON 里没写 `trigger`，或五轴一个都没写 |
| `POST /flows/x/start` 返回 40301 | 没声明 `api` 轴 |
| `flow.start` 报契约错 | `seed` 与流程声明的 `job.seed` 不一致（多了/少了/拼错） |
| `stream.match.status` 校验失败 | 状态值没在清单 `eventStatuses` 里声明 |
| 定时任务突然不跑了 | 有人把 `paused` 设成了 `true`；或流程改名导致调度 ID 变了 |
