# 连接外部系统

插件经常要和客户自己的系统打交道：从交警平台拉警情、往客户业务系统回写数据。平台提供两条**受管通道**，插件自己不能裸发网络请求：

| 通道 | 全局对象 | 用途 | 权限 |
| --- | --- | --- | --- |
| 调用平台已注册的连接器 | `connector.invoke(id, payload)` | 调用环境已接入的下游系统 | `integration:write` / `integration.gis:read` |
| 受管出网（HTTP） | `connector.fetch(req)` | 调用部署白名单允许的外部 HTTP 接口 | `egress:fetch` |

## 连接的两半：插件声明形状，部署给值

外部系统的地址、账号、密码不应该写死在插件里。平台把它拆成两半：

**插件侧**：源清单 `fh2-plugin.json` 里声明"我需要一个什么样的连接"（只有字段形状，没有值）：

```json
{
  "connections": [
    {
      "description": "级联平台（警情来源）",
      "id": "traffic.connector.cascade",
      "requires": [
        { "name": "baseUrl", "type": "string", "required": true },
        { "name": "loginName", "type": "string", "required": true },
        { "name": "password", "type": "string", "required": true, "secret": true },
        { "name": "source", "type": "number", "required": true }
      ]
    }
  ]
}
```

**部署侧**：部署方为连接 ID 提供真实值。插件作者提交连接 ID、字段形状和目标地址需求，由部署方完成配置并确认测试环境可用；插件作者不直接操作部署配置或管理接口。

装载时平台逐字校验：缺必填项、多给了键、类型不对都会**拒绝启动**。`secret: true` 的字段只影响启动日志（打"已配置"而不是值），不做加密。

## 在脚本里使用连接

```js
// 拿到本插件的连接配置（platform.getConfig 返回当前连接那份配置的副本）
export function handle(input: RecordInput, ctx: AdapterCtx) {
  var config = platform.getConfig()      // { baseUrl, loginName, password, source, connectorId }
  // ...
}
```

配合流程的 `run_script` 步骤时，连接 ID 由步骤入参传入，平台按它把对应的配置块给到 `platform.getConfig()`。也就是说：**同一份脚本配不同连接 ID，就能接入不同环境的外部系统**。

`config:get` 只决定方法是否注入，不会自动选择连接。可用调用必须同时有清单连接声明、部署提供的值和流程步骤 `inputs.connectorId` 接线。HTTP / 事件入口没有这套步骤级连接选择，不能仅传一个同名业务字段就期待 `platform.getConfig()` 取得配置；缺少绑定会在调用时失败。

## 受管出网：connector.fetch

```js
var result = connector.fetch({
  method: 'GET',
  url: config.baseUrl + '/api/events?from=' + from,
  headers: { 'Authorization': 'Bearer ' + token },
  timeoutSec: 10,
})
// result: { status, headers, body }
```

| 项 | 说明 |
| --- | --- |
| 入参 | `{method, url, headers, body, timeoutSec}`；url 必须是绝对地址 |
| 出参 | `{status, headers, body}`；HTTP 错误状态**不抛异常**，看 `status` 自己判断 |
| 管控 | 目标地址受平台白名单与限额约束 |
| 权限 | `egress:fetch` |

HTTP 错误状态是返回值，不会自动变成脚本异常；检查 `status` 后还须按外部系统的业务码判断成功。超时与 5xx 是否适合重试取决于对方的副作用和幂等协议，不能一律当成安全重试。

HTTP 接口抛错后平台**不会自动重发请求**，由调用方先查结果再决定；流程抛出可重试错误会重跑整段脚本，事件则按每次投递的配置尝试。写请求须传对方认可的稳定业务键，单纯抛默认 `Error` 不提供去重或恢复保证，见[错误模型](../../70.api-reference/30.shared/20.error-model.md)与[重试边界](../../70.api-reference/20.backend/60.workflow-dsl.md#重试边界)。

## 凭据纪律

外部系统的账密是敏感信息，处理它们只有三条纪律：

1. **配置值只从 `platform.getConfig()` 拿**，不要把账密写进流程 JSON、脚本常量或清单。
2. **不要把凭据写进错误信息、返回值和日志**。流程的执行历史、HTTP 响应都是长期留存且可能被广泛可见的。抛错时带上"哪一步失败"就够，不要带请求原文。
3. 调用外部系统成功的标志以返回的 `status` 和业务码为准，不要假设网络层一定抛错。

## 完整示例：定时采集外部系统

下面是"每 30 分钟拉一次外部警情、写入事件模型"的业务组合骨架，不是完整可运行工程。辅助函数尚未实现，且清单节选没有登记 `flows`。按[流程指南](./60.workflow.md)补齐流程登记、脚本输入与输出及时间接线，再由部署方提供连接值和目标环境校验；本地 `dev` 不执行定时流程。

`fh2-plugin.json`（节选）：

```json
{
  "connections": [ { "id": "traffic.connector.cascade", "requires": [ { "name": "baseUrl", "type": "string", "required": true } ] } ],
  "scripts": [ {
    "name": "cascade-ingest", "path": "adapters/cascade-ingest.ts", "entry": "handle",
    "allowlist": ["egress:fetch", "config:get", "event:write"],
    "io": {
      "inputs": [ { "name": "intervalSec", "type": "number", "required": true } ],
      "outputs": [ { "name": "inserted", "type": "number" } ]
    }
  } ]
}
```

`workflows/cascade-ingest.json`：

```json
{
  "name": "cascade-ingest",
  "trigger": { "schedule": { "intervalSec": 1800 } },
  "steps": [ {
    "id": "ingest", "action": "run_script",
    "inputs": {
      "script": { "const": "cascade-ingest" },
      "connectorId": { "const": "traffic.connector.cascade" },
      "now": { "from": "run.now" },
      "intervalSec": { "from": "run.intervalSec" }
    }
  } ]
}
```

```js
// adapters/cascade-ingest.ts（骨架）
export function handle(input: RecordInput, ctx: AdapterCtx) {
  var config = platform.getConfig()
  var token = login(config)                      // 三步 SSO 登录外部平台
  var rows = pull(config, token, input)          // connector.fetch 拉一个时间窗的警情
  var events = toEvents(rows, ctx.now)           // 转成统一事件模型的字段
  var inserted = insertEvents(events)            // platform.insertEvent 逐条写（按 eventId 幂等）
  return { inserted: inserted }
}
```

要点：

- 采集用**固定回溯窗口**（每次拉"最近 N 分钟"），不维护游标；重复数据靠事件模型的 eventId 幂等吸收。
- 平台按已配置的定时触发和步骤策略调度，不能代替脚本的输入校验、去重和失败处理。连续失败耗尽尝试后不保证自动补采，应与部署方约定对账或人工恢复。
- 同一轮有多个外部调用时，后续失败可能让前面的调用重新执行。按[受管出网限制](../../30.features/60.backend-capabilities/20.config-egress-integration.md#connector-fetch-受管出网)控制请求数、时长和响应体，并把脚本预算与单次网络超时分开核对。

## 常见坑

| 现象 | 原因 |
| --- | --- |
| 启动失败提示连接配置不完整 | 核对源清单的连接 ID 与字段声明，再请部署方检查缺键、多键或类型问题 |
| `platform.getConfig()` 报未绑定连接 | 检查连接声明、部署值和流程步骤 `inputs.connectorId`；HTTP / 事件入口不能套用步骤级选择 |
| `connector.fetch` 报目标不允许 | 出网地址不在部署白名单内，将目标主机与业务用途交给部署方确认放行 |
| 外部系统返回 401 | 连接凭据可能过期；请部署方轮换配置并重启后端运行时，不要把凭据写进插件 |
| 凭据出现在日志/错误里 | 违反了凭据纪律第 2 条；立即轮换密码并修脚本 |
