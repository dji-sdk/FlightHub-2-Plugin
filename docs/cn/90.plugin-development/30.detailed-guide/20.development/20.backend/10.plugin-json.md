# 后端源清单 fh2-plugin.json

`fh2-plugin.json` 是后端插件的身份证和说明书：平台靠它识别插件、授予权限、装载流程和脚本。这一页逐个字段说明。

## 最小清单

```json
{
  "pluginId": "exp_my_backend",
  "name": "我的第一个后端插件",
  "version": "0.1.0"
}
```

必填只有 `pluginId`、`name`、`version`。`pluginId` 是可交付插件身份：创建向导与交付链路要求 `official_` 或 `exp_` 前缀的小写短名，不要使用无前缀示例。`flows`、`connections`、`scripts`、`events` 等数组字段都是可选：没有对应内容时可以不写，写空数组不是装载要求。

## 全部字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `pluginId` | ✅ | 插件唯一身份。创建与交付使用 `official_` / `exp_` 前缀的小写短名；源 Schema 的结构限制另为 1~64 字符且禁冒号，不把无前缀 ID 视为可交付身份 |
| `name` | ✅ | 展示名，人和日志看 |
| `version` | ✅ | 整包统一版本，发布/回滚的单位 |
| `description` |  | 说明文字 |
| `contractsRange` |  | 声明兼容的宿主契约版本，如 `">=1.1.0 <2.0.0"`。只支持 `>= > <= < = ==` 用空格连接，不支持 `^`、`~` |
| `flows` |  | 流程 JSON 路径列表，如 `["workflows/main.json"]`。**白名单制**：只装载列出的文件 |
| `connections` |  | 外部系统连接声明（只有形状，值在部署配置），见[连接外部系统](./80.external-connections.md) |
| `scripts` |  | 流程用脚本声明，见下文 |
| `events` |  | 消息订阅声明，见[消息订阅](./30.event-handler.md) |
| `eventStatuses` |  | 本插件用到的事件状态值词汇表，供流程的状态步骤和事件筛选使用 |
| `allowlist` |  | 包级权限，HTTP 接口和事件脚本共用，见[ctx 与能力注入](./40.context-and-allowlist.md) |
| `evaluators` |  | 只读判定脚本（无任何能力注入），供流程条件判断使用 |
| `entities` |  | **不要写**。存储契约由 `schema.sql` 单点定义，构建时自动投影；在源清单手写会与派生结果冲突 |

任何不认识的字段都会导致**整包拒绝装载**——包括从旧文档抄来的 `handlers[]`、`triggers[]`、`whitheList`。HTTP 接口按 `handlers/` 目录约定登记，不在清单里声明。

## scripts[]：流程用脚本

给流程的 `run_script` 步骤用的脚本，需要在清单里声明名字、输入输出和权限：

```json
{
  "scripts": [
    {
      "description": "记录写入的流程脚本",
      "name": "example-script",
      "path": "adapters/example-script.ts",
      "entry": "handle",
      "allowlist": ["data:read", "data:write"],
      "io": {
        "inputs": [
          { "name": "record_key", "type": "string", "required": true },
          { "name": "title", "type": "string", "required": true }
        ],
        "outputs": [
          { "name": "id", "type": "string" },
          { "name": "created", "type": "bool" }
        ]
      }
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 脚本名，流程步骤用 `{"script": {"const": "example-script"}}` 引用。留空则取文件名（去后缀） |
| `path` | 插件内相对路径（约定放 `adapters/`），`.ts` 源文件 |
| `entry` | 入口函数名，缺省 `handle` |
| `allowlist` | **只给这个脚本**的权限。留空则回落到包级 `allowlist`；写了就**只**用自己声明的（不是合并） |
| `io` | 输入输出契约。`inputs[].required` 校验必填；`outputs` 声明了就必须产出 |

注意：`entry` 指向的是你 TypeScript 源文件里 `export` 的函数名——和 HTTP 接口处理函数的目录约定命名是两套规则，别混用。

## events[]：消息订阅

```json
{
  "events": [
    {
      "type": "example.created",
      "consumer": [
        { "handler": "events/example-created.ts", "entry": "onExampleCreated" }
      ]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `type` | 消息类型。模板自带的 `example.created` 只用于本地模拟联调；真实平台消息的可用类型以[消息订阅](./30.event-handler.md)为准 |
| `match` | 消息体顶层字段的等值筛选（AND）。不写 = 全收 |
| `consumer` | 后端运行时中命中的消费方并发执行、各自独立重试；全部结束后按最坏结果聚合消息处置 |
| `consumer.handler` | 脚本路径（放 `events/` 目录），`.ts` 源文件 |
| `consumer.entry` | 入口函数名，缺省 `handle` |

`consumer` 数组不表达业务先后依赖；需要先后执行的逻辑应放在同一个消费函数内调用，或使用显式流程编排。入口必须返回对象，通常为 `{}`；失败信封的处置见[消息订阅](./30.event-handler.md)。本地模拟器不用于证明后端运行时的并发、重试和消息处置语义，这些行为需在已部署的测试环境验证。

## 版本兼容（contractsRange）

宿主有一个契约版本（当前 `1.1.0`）。插件声明它能兼容的范围：

```json
{ "contractsRange": ">=1.1.0 <2.0.0" }
```

宿主版本不在范围内 → 拒绝装载。这样宿主升级大版本时，旧插件不会带病运行。不确定时留空，由发布平台处理。

## 装载期检查清单

发布前自查一遍，这些在装载时都会被检查：

- [ ] 所有字段名拼写正确（严格模式，多一个都不行）
- [ ] `flows[]` / `scripts[].path` / `events[].consumer[].handler` 指向的文件都存在
- [ ] `events[].consumer[].entry` / `scripts[].entry` 指向的导出函数真的在源文件里
- [ ] 所有 TS 能通过类型检查和构建
- [ ] `allowlist` 里的能力名都真实存在（见[能力目录](../../70.api-reference/20.backend/80.host-capability-catalog.md)），申报了授不出的名字整包起不来
- [ ] 流程名、连接 ID、脚本键、实体名不与其他插件包冲突
