# 插件清单（fh2-plugin.json）

插件清单是插件的"身份证 + 施工图"：平台靠它知道插件叫什么、代码入口在哪、要在哪些位置放什么东西。这一页把每个字段讲清楚，照着写就能通过校验。

清单文件固定叫 `fh2-plugin.json`，放在工程根目录。改的永远是它，不是 `dist/fh2-plugin.json`（那是构建产物，见[工程结构](./10.project-structure.md)）。

## 一个能直接抄的例子

`fh2-plugin.json`：

```json
{
  "id": "exp_project_tasks",
  "name": "项目任务插件",
  "version": "0.1.0",
  "description": "在项目侧边栏展示任务",
  "entry": "./plugin.js",
  "permissions": ["platform:http", "project:context"],
  "extensions": [
    {
      "id": "task-entry",
      "point": "project.sidebar-actions",
      "path": "/plugin-tasks",
      "position": 50
    }
  ],
  "views": {
    "task-panel": { "entry": "./views/task-panel.js" }
  },
  "contributes": {
    "icons": [{ "id": "plugin", "src": "./icons/plugin.svg" }]
  },
  "config": {
    "refreshSeconds": {
      "type": "number",
      "default": 30,
      "label": "刷新间隔（秒）",
      "min": 5,
      "max": 300
    }
  }
}
```

## 必填与选填字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 插件 ID，格式见下文 |
| `name` | ✅ | 显示名称 |
| `version` | ✅ | 严格的 SemVer，如 `0.1.0`（三段数字，不能写 `v1.0` 或 `1.0`） |
| `entry` | ✅ | 入口产物路径，以 `./` 开头，固定写 `./plugin.js` |
| `extensions` | ✅ | 扩展声明数组，可以为空数组 |
| `description` / `author` | — | 可选 |
| `permissions` | — | 申请的能力权限名，见下文 |
| `views` | — | 界面声明，键是界面 ID |
| `contributes.icons` | — | 图标资源，`{id, src}`，供扩展的 `icon` 字段按 ID 引用 |
| `config` | — | 用户可配置项 |

> 清单里的路径（`entry`、`views.*.entry`、图标 `src`）都指向**构建产物**，以 `./` 开头、以 `.js`/`.svg` 结尾。源码里的 `.ts`/`.vue` 文件经 `fh2-plugin build` 打包后对应到这些产物路径——工程里不需要真的存在 `./plugin.js` 这个文件。

命名规则：

- 插件 ID 匹配 `^(official|exp)_[a-z0-9]+([_-][a-z0-9]+)*$`，即以 `official_` 或 `exp_` 开头、全小写。
- 扩展 ID、界面 ID、图标 ID 只用字母、数字和连字符，不能用下划线和点。

## permissions：先声明，后使用

`permissions` 里只能填能力目录列出的 ID（如 `platform:http`、`cockpit:context`）。规则是：**清单里先声明，代码里才能拿到**。没声明的能力，运行时 `ctx.capabilities.get()` 会返回 `undefined`。

能力清单和每个能力的方法见[能力目录](../../70.api-reference/10.frontend/40.capability-catalog.md)。其中四个基础能力不需要 `capabilities.get()`：

- `platform:http` → `ctx.apiCall`
- `platform:websocket` → `ctx.ws`
- `platform:events` → `ctx.events`
- `platform:storage` → `ctx.storage`

用法见[HTTP、WebSocket 与事件](./70.http-websocket-events.md)。

## extensions：静态字段与运行时字段

每条扩展 `{id, point, ...}` 里，`point` 后面能跟什么字段由扩展点契约决定。分两类：

- **静态字段**：写死在清单里，运行期不能改。表达"放在哪个位置"。
- **运行时字段**：在入口代码里通过 `ctx.extensions.contribute()` 提交，可以随时更新。表达"长什么样、点击干什么"。

各扩展点的静态字段：

| 扩展点 | 静态字段 |
| --- | --- |
| `cockpit.ui.toolbar-actions` | 可选 `anchor`：`footer-toolbar` \| `footer-toolbar:before-ai` |
| `cockpit.ui.flight-actions` | 可选 `anchor`：`flight-actions` \| `flight-actions:after-return-home` |
| `cockpit.ui.live-overlay` | 必填 `overlayLevel`：`normal` \| `top`；可选 `stream` |
| `plan.form-extensions` | 必填 `planType`：`all` \| `normal` \| `atob` \| `manual`；可选 `anchor`：`form-end` \| `task-strategy:after` |
| `project.sidebar-actions` | 必填 `path`；可选 `position`（数字，越小越靠前） |
| 其余扩展点 | 无静态字段 |

按钮文案 `label`、图标 `icon`、禁用 `disabled`、点击回调 `onTrigger`、渲染 `render` 这些全是运行时字段，**写进清单会被校验拒绝**。完整契约见[扩展点目录](../../70.api-reference/10.frontend/30.extension-point-catalog.md)。

## config：用户可配置项

`config` 的每个值只能是 `boolean`、`number`、`string` 三种，且必须带 `default` 和 `label`：

`fh2-plugin.json`（节选）：

```json
{
  "config": {
    "mode": { "type": "string", "default": "auto", "label": "模式", "enum": ["auto", "manual"] },
    "threshold": { "type": "number", "default": 80, "label": "阈值", "min": 0, "max": 100 },
    "enabled": { "type": "boolean", "default": true, "label": "启用" }
  }
}
```

入口代码里直接读快照：`ctx.config.refreshSeconds`（类型由 generate 生成的类型文件保证）。注意：配置是激活时的快照，用户改配置后平台会**停止旧运行时、用新配置重新激活**，所以不要在运行期指望配置热更新。

## 这些字段不要写

```text
manifestVersion   engines   buildInfo      ← 构建时由工具链写入 dist 产物
trusted   trustLevel   sandbox               ← 运行方式由平台决定，插件无权自报
```

源清单出现以上任何一个字段，构建直接失败。清单也不允许未知顶层字段。插件无权给自己声明信任等级。

## 改完清单之后

```bash
pnpm run generate   # 重新生成类型（App*Context、扩展 ID、配置类型）
pnpm run validate   # 校验清单
pnpm run build      # 构建产物
```

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 报 `FH2_PLUGIN_VERSION_INVALID` | `version` 不是严格 SemVer，改成 `0.1.0` 这样的三段式 |
| 报 `FH2_EXTENSION_STATE_IN_MANIFEST` | 把 `label`、`icon` 等运行时字段写进了清单，移到 `contribute()` |
| 报 `FH2_EXTENSION_METHOD_IN_MANIFEST` | 把 `onTrigger`、`render` 等方法写进了清单，同上 |
| 报 `FH2_EXTENSION_FIELD_UNKNOWN` | 扩展字段名拼写错误，对照扩展点契约 |
| 报 `FH2_MANIFEST_VIEW_NOT_FOUND` | 扩展或代码引用了一个 `views` 里不存在的界面 ID |
| 报 `FH2_MANIFEST_ICON_NOT_FOUND` | 清单扩展声明里的图标 ID 不在 `contributes.icons` 里（构建期就会报）。代码里 `contribute()` 传的 `icon` 是运行时解析：ID 未声明**不会报错**，但图标渲染不出来（项目/消息显示占位，驾驶舱渲染为空）——务必两处都声明 |
| 报 `FH2_SOURCE_BUILD_FIELD` | 清单里写了 `manifestVersion`/`engines`/`buildInfo` 等构建字段，删掉 |
| 权限校验不通过 | `permissions` 只能取能力目录列出的 ID，见[能力目录](../../70.api-reference/10.frontend/40.capability-catalog.md) |
