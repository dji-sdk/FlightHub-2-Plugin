# 工具链与本地调试页面

插件开发的所有命令都来自一个 CLI：`fh2-plugin`，由插件开发工具链（文档模块名 `fh2-plugin-toolchain`）提供。这一页讲清核心命令各自干什么、怎么配合，以及本地调试页面是什么。完整命令清单以 `fh2-plugin --help` 为准。

> `fh2-plugin-toolchain` 是插件开发工具链；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

本文适用于插件化开发者工具中的 SDK / 工具链 `1.0.0`。环境准备见[环境准备](../40.hands-on/10.environment-preparation.md)，首次打开插件面板用[快速入门](../../../10.quick-start/00.index.md)，让 AI 协助已有工程见[AI 开发 Skill](../../../20.ai-development-skill/00.index.md)。保留生成工程的依赖和配置，不把说明用模块名当作安装包名。

## 核心命令全景

```text
fh2-plugin create        生成新工程
      │
fh2-plugin generate      改了清单就重跑：清单 → 类型文件
      │
写代码 ⇄ fh2-plugin dev   日常开发循环：自动构建 + 本地调试页面实时预览
      │
fh2-plugin validate      发布前校验清单与源码一致性
      │
fh2-plugin build         正式构建 dist/
      │
fh2-plugin preview       可选：在真实司空环境里验证前端产物
      │
fh2-plugin pack          按执行根生成 zip，核对上传布局
```

| 命令 | 这一步要核对什么 |
| --- | --- |
| `create` | 默认能力工作区模板包含两个前端成员、一个后端成员和本地模拟器；单插件模板是独立工程，不直接形成行业上传包 |
| `generate` | 前端生成 `src/generated/plugin-types.ts`，后端生成 `types/`；清单或 `schema.sql` 变化后按工程根重新生成，不手改产物 |
| `validate` | 检查所选工程的清单、源码与接线；本地通过不等于工作流已通过同版本权威后端校验 |
| `build` | 生成 `dist/`；失败不发布半成品，但已有旧产物不能当作本次成功 |
| `dev` | 构建并启动本地调试；工程有后端时可启动本地 HTTP 模拟器，独立后端不启动页面 |
| `preview` | 通过 HTTP PAC 在获授权的目标宿主预览本地前端；必须手填来源并确认 |
| `pack` | 根据工作区、能力或单插件根生成不同布局；打包成功不等于可上传、已安装或运行通过 |

参数、选择规则和机器输出统一查[CLI 参考](../../70.api-reference/10.frontend/70.toolchain-cli.md)及所选工具的 `--help`，不沿用旧版本旗标。

`dist/fh2-plugin.json`（构建产物清单）由 `build` 生成：工具链会写入构建字段，并把清单里的逻辑路径替换成带 hash 的资源路径。`pack` 在它的基础上打包。

不确定参数时随时看帮助：

```bash
pnpm exec fh2-plugin dev --help
```

模板把日常命令映射到 `package.json` 脚本。在带 `packages.json` 的生成工作区根运行已有脚本，它们会选择能力子目录；直接调用 CLI 时须显式核对 `--root`。`dev:cockpit`、`tsc`、`lint` 不是所有根都有的脚本，先看当前 `package.json`。

## 本地调试页面：模拟宿主

本地调试页面由 `dev` 命令启动，加载本地产物并模拟宿主。首次构建成功后按终端完整地址打开，不只打开 origin；地址中的组织、项目、设备和路由都是本次场景的一部分。前端重建成功触发页面刷新，能力工作区的后端重建只重载本地后端。

下面在生成工作区根执行，先将 `CAPABILITY_ROOT` 设置为实际含 `capabilities.json` 的能力目录路径。三条是不同启动方式，切换前先停止自己的旧进程；驾驶舱命令不假设根上有 `dev:cockpit` 脚本：

```bash
pnpm run dev
pnpm exec fh2-plugin dev cockpit --root "$CAPABILITY_ROOT"
pnpm run dev:frontend
```

细节：

- 首次构建成功后才开始对外服务；构建失败时看终端诊断。
- `--no-watch` 做单次构建后启动；`--port 5180` 换端口。
- 工程含后端且未选仅前端模式时，启动本地后端和 HTTP 模拟网关；它不执行真实流程，也不证明持久化和设备链路可用。只调前端可选 `--frontend-only`。
- 页面切换决定所需宿主：团队 / 插件页保留 `project+message`，计划页再加 `plan`，驾驶舱再加 `cockpit`；页面不可见不等于宿主卸载。看 Host 面板的实际挂载状态，而非仅看界面。
- 连接真实 HTTP 网关时，按[本地开发](../../40.debug-and-test/10.local-development.md)核对目标 origin 和 `FH2_DEV_LOGIN_TOKEN`。这不会把本地 WebSocket / 平台事件变成真实订阅，不在代码、命令或日志中填写凭据值。

## preview：在真实司空里调试

当前 `preview` 仅支持 **HTTP 目标 + 本机同源受限代理 + PAC**，不需要本地证书。目标必须是允许插件调试的私有化环境，你须有登录和项目权限；HTTPS-only 目标停止此路线，不降级协议或绕过 TLS。

在生成工作区根，先把 `FH2_URL` 设置为获授权的完整 HTTP 项目页地址（保留路径、查询和路由），再执行：

```bash
pnpm run preview -- --fh2-url "$FH2_URL" --no-open
```

启用终端打印的 PAC，在同一 Origin 登录并进入项目，手填资源根，由宿主校验后勾选临时运行同意并确认重载；用完在宿主禁用来源、关闭 PAC。只替换前端资源，后端仍是目标环境已安装的版本。完整操作与代理限制见[真实环境预览](../../40.debug-and-test/10.local-development.md#真实环境预览)。

两种加载模式：

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| `overlay` | 目标环境已安装同 ID 插件时，用本地产物覆盖它的前端资源 | 验证即将发布的改动 |
| `temporary` | 允许目标未安装的插件临时运行；不成为正式安装 | 经确认后验证新插件，用完显式禁用来源 |

## 发布前检查

先停止自己的 dev / preview 进程，避免工程锁冲突。下面在生成工作区根执行已有脚本，`CAPABILITY_ROOT` 仍指向实际能力目录；当前根没有 `tsc` / `lint` 时，到各成员根执行其类型检查、测试和代码检查，不直接跳过这些验证：

```bash
pnpm run generate
pnpm exec fh2-plugin generate --root "$CAPABILITY_ROOT" --check
pnpm run validate
pnpm run test
pnpm run build
pnpm run pack
```

核对 `pack` 的执行根和产物布局：`packages.json` 工作区生成行业聚合上传包，`capabilities.json` 能力根生成能力包，`fh2-plugin.json` 单插件根的独立运行时 zip 不能直接作为平台上传包。上传与安装步骤见[行业包构建与打包](../../60.delivery-and-security/20.industry-package.md)及[安装、升级与回滚](../../60.delivery-and-security/50.installation-and-upgrade.md)。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 直接跑 `rsbuild build` 被拒绝 | 必须用 `fh2-plugin build`，构建上下文由工具链提供 |
| 本地调试页面里看不到插件 | 确认 `dist/` 已生成、首次 build 成功；没改过 `--plugins-dir` 时它指向项目的 `dist` |
| 5175 端口被占用 | `pnpm run dev -- --port 5180` 换端口；驾驶舱高保真默认 5176，同样可用 `--port` 调整 |
| 本地接口一直 404 | 加了 `--frontend-only` 不会启动模拟网关；去掉它，或确认 handler 路径正确 |
| 想连真实后端但报鉴权错误 | `--gateway-target` 需要有效的登录 token；确认目标地址是纯 origin（无路径、无查询参数） |
| 旧证书 / 协议参数被拒绝 | 当前 HTTP PAC 路线不使用证书或旧协议旗标；核对本次 `preview --help`，不要绕过拒绝 |
| `preview` 面板打开但没加载插件 | 检查同源登录 / 项目、PAC、本次资源根、清单校验、权限同意及确认重载；链接不会自动填写来源 |
| `preview` 里后端行为不对 | 后端用的是目标环境已安装的版本，不是本地代码；需要调后端请回 `dev` 模式 |
