# 存储、Blob 与定时器

插件代码运行在隔离环境里，**没有浏览器原生的 `localStorage`、`indexedDB`，也没有全局 `setTimeout`**。需要本地缓存、临时文件、定时任务时，用平台提供的三个替代品：`ctx.storage`、`ctx.blobs`、`ctx.timers`。它们有个共同好处：运行时停止时，平台会统一回收这些资源，不会泄漏。

## 前置条件

清单里声明 `platform:storage`（KV 和 Blob 共用这一个权限）：

`fh2-plugin.json（节选）`：

```json
{ "permissions": ["platform:storage"] }
```

## KV 缓存：ctx.storage

`ctx.storage.local`（持久）和 `ctx.storage.session`（会话级）用法相同，都有 `get`、`set`、`remove`、`keys` 四个方法：

```ts
// src/hosts/project/activate.ts（节选）
// 读：拿不到或不存在时是 undefined，要准备默认值
const saved = await ctx.storage.local.get('preferences')
const preferences = saved && typeof saved === 'object' && !Array.isArray(saved)
  ? saved
  : { compact: false }

// 写：值必须是 JSON 安全的
await ctx.storage.local.set('preferences', { compact: true })

// 删
await ctx.storage.session.remove('temporary-filter')
```

两条边界：

- 值必须是可 JSON 序列化的普通数据。传 Vue 响应式对象、函数、能力句柄会被拒绝。
- 读取结果要自己校验形状。它是缓存不是数据库，随时可能拿回 `undefined` 或旧格式。

它也不适合放大文件、登录凭证或需要跨用户同步的权威数据——前者用 Blob，后者放后端。

## 临时文件：ctx.blobs

截图、抓帧这类二进制数据放 `ctx.blobs`：

```ts
// src/hosts/cockpit/activate.ts（节选）
await ctx.blobs.put('preview', imageBlob)          // 存
const blob = await ctx.blobs.get('preview')        // 取，可能是 undefined
const url = blob ? await ctx.blobs.url('preview') : undefined

if (url)
  state.update(current => ({ ...current, previewUrl: url })) // 给界面展示用
```

`ctx.blobs.url(key)` 返回受平台台账管理的 Object URL，两点限制：

- 只在当前运行时有效。重新 `put` 同名 key、`remove`、或运行时停止后，旧 URL 随时可能失效。
- 所以它只能当短期预览地址用，不要存进数据库或发给后端长期保存。业务的权威媒体文件应上传到后端（见[HTTP、WebSocket 与事件](./70.http-websocket-events.md)）。

## 定时任务：ctx.timers

```ts
// src/hosts/cockpit/activate.ts（节选）
const timer = ctx.timers.setInterval(() => {
  void refresh().catch(error => {
    ctx.logger.warn('刷新失败', { message: error instanceof Error ? error.message : String(error) })
  })
}, 30_000)

// 提前停止（运行时停止时平台也会自动清掉）
ctx.timers.clearInterval(timer)
```

四个方法 `setTimeout` / `clearTimeout` / `setInterval` / `clearInterval` 与全局同名函数用法一致，区别是平台会登记它们，运行时停止时统一清除——这就是"不会在插件卸载后还在跑"的保证。

注意：每次激活只创建一次定时器。如果激活逻辑可能重复执行，先 `clear` 旧的再建新的。

## 哪些数据放哪里

| 数据 | 放哪里 |
| --- | --- |
| 用户偏好、界面状态等小缓存 | `ctx.storage.local` / `session` |
| 截图、抓帧等短期二进制 | `ctx.blobs` + `url()` 给界面预览 |
| 权威业务数据、需要跨用户/跨刷新 | 后端接口 |
| 跨宿主实时协作 | 跨宿主通信服务（见[跨宿主通信服务](./60.plugin-service.md)） |

## 日常命令与预期

```bash
pnpm run generate
pnpm run validate
pnpm run tsc
pnpm run dev
```

预期：KV 读不到值时走默认分支；Blob URL 在当前运行时内可被界面使用；宿主页面卸载后不再有任何定时回调。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 报 `STORAGE_QUOTA_EXCEEDED` | 超出配额；清掉不用的 key，或把大块数据挪到后端 |
| `get()` 返回 `undefined` | 正常的缺值场景；按默认值分支处理，不要当成故障 |
| `set()` 被拒绝 | 值不是 JSON 安全的（传了函数、Vue 响应式对象、Map/Set 等）；先转普通对象 |
| 定时器回调重复执行 | 激活逻辑被跑了多次，每次都新建了定时器；创建前先 `clear`，或保证只创建一次 |
| Blob 图片突然加载不出来 | 重新 `put`/`remove` 或运行时重启后旧 URL 失效；需要时重新调 `blobs.url()` |
| 想用 `localStorage` 调试 | 隔离环境里没有它；统一走 `ctx.storage` |
