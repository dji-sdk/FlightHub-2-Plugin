# HTTP、WebSocket 与事件

插件和外界通信有三条通道：调后端接口（HTTP）、收后端推送（WebSocket）、收平台语义事件。这一页讲三条通道各自的写法和边界。共同前提：**插件不自己建连接、不碰登录态**，通道都由宿主提供，你只管调用。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## 前置条件

清单里声明对应权限（`fh2-plugin.json` 节选）：

```json
{
  "permissions": ["platform:http", "platform:websocket", "platform:events"]
}
```

这三个能力不走 `ctx.capabilities.get()`，直接用 `ctx.apiCall`、`ctx.ws`、`ctx.events`。

## HTTP：ctx.apiCall()

`ctx.apiCall(endpoint, options)` 是插件入口业务 HTTP 的**唯一**出口。Entry Guard 会拦截裸的 `fetch`/`XHR`/`WebSocket`：裸 `fetch` 以浏览器网络错误形态失败，XHR/WebSocket 在构造或调用时抛错。`PLUGIN_NETWORK_BLOCKED` 则表示 `ctx.apiCall` 的 endpoint 或参数没有通过平台校验，两者不要混在一起排障。

```ts
// src/hosts/project/activate.ts（节选）
import { isPluginError } from 'fh2-plugin-sdk'

interface InvokeEnvelope<T> {
  readonly code: number
  readonly message: string
  readonly data: T
}

// pluginId 写后端插件的 ID（前后端是两个插件，ID 通常不同）
const BACKEND_ID = 'exp_demo_backend'

try {
  const response = await ctx.apiCall<InvokeEnvelope<{ readonly list: readonly string[] }>>('/plugin/invoke', {
    method: 'POST',
    body: { pluginId: BACKEND_ID, handler: 'issue.list', input: {} },
    timeoutMs: 10_000,
  })
  // 能走到这里说明网关返回 code === 0；response 是完整信封
  ctx.logger.info('任务列表', { list: response.data.list })
} catch (error) {
  if (isPluginError(error)) {
    // 网关业务码非零（如 40006 参数错误、50301 系统错误）会以 PluginError 抛出
    ctx.logger.warn('请求失败', { code: error.code, message: error.message })
  }
  throw error
}
```

要点：

- **endpoint 分两类**：调用平台内部接口用单个 `/` 开头的相对路径，不要带 `/plugin-api` 前缀，平台最终请求 `{服务地址}/plugin-api<endpoint>`；调用外部 HTTP(S) 服务可传绝对 URL，但必须命中宿主网关的出网白名单，且 body 只能是 JSON，不开放自定义 Header。
- **失败直接抛错**：网关返回非零业务码时，`ctx.apiCall` 抛 `PluginError`（`code` 为 `PLUGIN_GATEWAY_ERROR`，`detail` 里带网关业务码），不会把失败信封当正常返回值。成功时才返回完整 JSON 信封（`{code, message, data}`），`data` 要自己取。
- 带 `pluginId` 的插件后端统一入口是 `POST /plugin/invoke`，请求体 `{pluginId, handler, input}`。`handler` 写法见[后端接口处理函数](../20.backend/20.http-handler.md)。
- `options` 支持 `{method, body, timeoutMs, idempotencyKey}`；`GET` 请求不能带 body；写操作（POST/PUT/PATCH/DELETE）可给稳定的 `idempotencyKey`，平台会把它映射为网关 `Idempotency-Key` 请求头，实际去重语义以后端契约为准。
- 鉴权由平台代劳：插件 token 的换取和请求头（`x-plugin-token` 等）都自动处理，你不要自己拼 token。

上传文件的写法：

```ts
// 受控 multipart 上传
await ctx.apiCall('/upload/attachment', {
  method: 'POST',
  body: {
    kind: 'multipart',
    fields: { scene: 'inspection' },
    files: [{ field: 'file', name: 'photo.jpg', contentType: 'image/jpeg', blob: imageBlob }],
  },
})
```

体积限制：相对路径请求的单个 Blob body 最大 10MB；multipart 最多 8 个文件、单文件 10MB、总计 20MB。绝对 URL 请求只接受 JSON body。超限会被拒绝。

## WebSocket：ctx.ws.onBizCode()

插件只读订阅宿主已建好的 WebSocket 连接，按后端的 `bizCode` 过滤消息：

```ts
// src/hosts/cockpit/activate.ts（节选）
const subscription = await ctx.ws.onBizCode<{ readonly id: string }>(
  'scene_alert',
  event => {
    if (event.subBizCode !== 'alert_notify') return
    ctx.logger.info('收到告警', { id: event.data.id, timestamp: event.timestamp })
  },
)
```

每条消息的形状：

| 字段 | 说明 |
| --- | --- |
| `bizCode` | 后端业务码，订阅时指定 |
| `subBizCode` | 子业务码，消息没带时为 `null` |
| `timestamp` | 后端时间戳（毫秒），没带时为 `null` |
| `data` | 业务数据 |

边界要清楚：插件不能建连、不能发送、不能控制重连，这些全由宿主管理。后端用 `notify.publish` 广播的通知会经共享连接到达这里，按 `bizCode` 匹配即可。

## 平台事件：ctx.events.on()

平台事件是宿主预定义的语义信号，目录是封闭的，目前只有两个：

| 事件名 | payload | 触发时机 |
| --- | --- | --- |
| `cockpit.emergency-stop` | `{timestamp, source?}` | 急停已触发/受理（不保证执行成功） |
| `cockpit.live.lifecycle` | `{phase, liveId, cameraIndex, timestamp}` | 直播通道生命周期变化 |

```ts
// src/hosts/cockpit/activate.ts（节选）
const listener = await ctx.events.on('cockpit.live.lifecycle', event => {
  if (event.payload.phase === 'first-frame')
    ctx.logger.info('直播首帧已渲染', { liveId: event.payload.liveId })
})
```

`cockpit.live.lifecycle` 的 `phase` 有四个值：`started`（建联成功）、`first-frame`（首帧渲染完成，逐帧处理的安全起点）、`stopped`、`channel-changed`。两个事件都只在驾驶舱派发；历史事件不缓存、不重放，激活前发生的收不到。

`ctx.events.on` 返回可注销的句柄，随运行时停止自动回收；提前不需要时 `await listener.dispose()`。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 报 `PLUGIN_NETWORK_BLOCKED` | `ctx.apiCall` 的 endpoint、method、body 或幂等键不合法；核对单个 `/` 开头、无 `/plugin-api` 前缀和参数类型。裸 `fetch`/`XHR`/`WebSocket` 是 Entry Guard 拦截，不会以这个稳定错误码到达插件 |
| 报 `PLUGIN_GATEWAY_ERROR` | 网关返回了异常；检查 endpoint 拼写（单 `/` 开头、无 `/plugin-api` 前缀）和后端服务状态 |
| 报 `TIMEOUT` | 请求超时；调大 `timeoutMs` 或检查后端耗时 |
| 接口报错但拿不到网关业务码 | 非零业务码以 `PluginError` 抛出（`code: 'PLUGIN_GATEWAY_ERROR'`），网关码在 `error.detail`；用 `isPluginError` 判断后再读 |
| WebSocket 一直收不到消息 | 核对权限 `platform:websocket`、`bizCode` 拼写；确认后端确实在广播该业务码 |
| 平台事件收不到 | 两个事件只在驾驶舱派发；确认当前 `ctx.host.id === 'cockpit'` 且订阅发生在事件发生前 |
| 上传文件被拒 | 超限：multipart ≤8 个文件、单文件 ≤10MB、总计 ≤20MB；相对路径请求的原始 Blob body ≤10MB，绝对 URL 只接受 JSON body |
