# 前端工程结构

这一页讲插件工程里每个目录放什么、哪些文件是工具生成的、代码依赖只能朝哪个方向走。新建工程后对照这页看一遍，后面就不会把文件放错位置。

## 前置条件

- 已用 `fh2-plugin create` 创建工程（模板选 `frontend-basic`，或使用能力工程 `capability-fullstack` 中的前端插件）。
- 依赖已安装，项目根目录有 `fh2-plugin.json` 和 `rsbuild.config.ts`。

SDK 与工具链的环境要求见[环境准备](../40.hands-on/10.environment-preparation.md)。

## 推荐布局

```text
exp_example/
├── fh2-plugin.json                # 插件清单（你维护）
├── package.json
├── rsbuild.config.ts
├── public/                        # 图标等静态资源（可选）
├── src/
│   ├── plugin.ts                  # 唯一入口代码
│   ├── generated/
│   │   └── plugin-types.ts        # generate 生成，不要手改
│   ├── hosts/
│   │   └── <host>/activate.ts     # 每个宿主页面一份激活逻辑
│   ├── shared/                    # 数据结构、纯函数、请求封装（跨宿主复用）
│   └── views/
│       └── <view-id>/
│           ├── contract.ts        # 界面契约（入口和界面共用）
│           ├── index.ts           # 默认导出 defineView(...)
│           ├── mount.ts           # 挂载/卸载逻辑
│           └── Panel.vue          # Vue 组件
└── dist/                          # build 生成，不要手改
```

> 如果用的是默认的能力工程模板（`capability-fullstack`），工作区根会多出 `packages.json`，插件分属 `<capabilityId>/frontend/<插件ID>/` 和 `<capabilityId>/backend/<插件ID>/`，能力目录里还有 `capabilities.json` 和 `mock/`。每个插件内部的结构与上图相同。

## 依赖方向

一个方向，不能反：

```text
src/plugin.ts（入口）
   └─> src/hosts/<host>/activate.ts
          └─> src/shared/  +  src/views/<id>/contract.ts

src/views/<id>/（界面）
   └─> Vue 组件 + contract.ts + UI 库
```

两条硬规则：

- 界面代码只依赖 Vue、契约和 UI 库，不导入宿主激活逻辑。挂载函数收到界面挂载上下文，不接收入口的 `PluginContext` 或能力注册表。
- 入口代码不导入 Vue、`.vue` 文件或界面的 mount 文件。Vue 相关的东西只能放 `src/views/`。

为什么这样分：入口与界面通过类型化通道传数据，避免把业务权限与 UI 依赖混在一起。界面自带 Vue 3，在宿主同一 JavaScript 运行域执行，ShadowRoot 只隔离 UI/CSS，不是 JavaScript 沙箱；不接收 `PluginContext` 不等于无法访问浏览器网络。入口安装网络护栏，界面不安装，作者应把业务网络与能力调用留在入口，不通过界面绕过受管通道或修改宿主 DOM / 全局状态。安全边界是安装审核与代码审核（见[平台架构](../../10.concepts/20.platform-architecture.md)）。构建会检查入口与界面的依赖边界，但不是浏览器安全隔离。

## 构建配置

模板已生成 `rsbuild.config.ts`，一般不需要改。下面只说明配置结构，不要按示意模块名改写生成文件的导入路径：

> `fh2-plugin-toolchain` 是插件开发工具链；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

```ts
// rsbuild.config.ts
import { defineConfig } from '@rsbuild/core'
import { pluginVue } from '@rsbuild/plugin-vue'
import { fh2Plugin } from 'fh2-plugin-toolchain/rsbuild'

export default defineConfig({
  plugins: [
    pluginVue(),
    fh2Plugin({
      manifestPath: './fh2-plugin.json',
      pluginEntry: './src/plugin.ts',
      typesOutDir: './src/generated',
      validateOnBuild: true,
    }),
  ],
  output: { distPath: { root: 'dist' } },
})
```

注意：必须用 `fh2-plugin build` 构建，不能直接跑 `rsbuild build`。`fh2Plugin()` 会拒绝脱离工具链的构建，因为清单改写、入口产物这些步骤由工具链负责。

## 谁维护哪个文件

| 路径 | 谁生成 | 规则 |
| --- | --- | --- |
| `fh2-plugin.json` | 你 | 只写源清单允许的字段，见[插件清单](./20.manifest.md) |
| `src/**` | 你 | 业务代码都在这里 |
| `src/generated/plugin-types.ts` | `fh2-plugin generate` | 改清单后重新生成；不要手改 |
| `dist/fh2-plugin.json` | `fh2-plugin build` | 含 hash 路径和构建字段 |
| `dist/plugin.*.js` | `fh2-plugin build` | 入口产物（单个 ESM 文件） |
| `dist/views/*` | `fh2-plugin build` | 每个界面一个独立 bundle 和配套 CSS |

业务代码只从 `src/` 和依赖包导入，永远不要从 `dist/` 导入。

## 日常命令与预期

```bash
pnpm run generate                      # 清单变化后重新生成类型
pnpm exec fh2-plugin generate --check  # 只检查类型是否过期，不写文件
pnpm run validate                      # 校验清单、目录结构和源码一致性
pnpm run build                         # 构建 dist/
```

预期：`dist/` 只在构建成功后才更新；入口是单个 ESM 文件；每个界面按界面 ID 独立打包。`generate --check` 失败就跑一次 `generate`；构建报"入口包含 Vue"就把相关依赖挪进 `src/views/`。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 直接 `rsbuild build` 被拒绝 | 必须经 `fh2-plugin build`，构建上下文由工具链提供 |
| 构建报"入口包含 Vue" | Vue 组件、样式只能放 `src/views/`，入口代码不要 import 它们 |
| 改了清单但类型没变化 | 重新跑 `pnpm run generate`；`src/generated/` 不会自动更新 |
| `generate --check` 一直失败 | 说明类型文件与清单不同步，跑一次 `pnpm run generate` 覆盖旧文件 |
| 引用了 `dist/` 里的文件 | 业务代码只能从 `src/` 和依赖包导入；`dist/` 是产物不是源码 |
| 能力工程里找不到后端产物 | 后端插件在 `<capabilityId>/backend/<插件ID>/` 下独立构建，产物在其自身 `dist/`；纯前端插件没有后端目录也能正常构建 |
