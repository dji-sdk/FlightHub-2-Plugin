# 最小后端插件

这个示例做出一个带 HTTP 接口的最小后端插件：业务源码只含一个源清单和一个接口脚本。构建可验证接口发现；接口服务与网关凭据就绪后可验证脚本执行和幂等 ID。Toolchain / SDK `1.0.0` 当前本地模拟器使用数字错误信封，但 HTTP 状态与请求校验不等同于部署服务，下方分别列出支持边界。

> fh2-plugin-sdk 是插件开发 SDK；模块路径示意，实际导入保留生成工程配置。依赖获取见[环境准备](../20.development/40.hands-on/10.environment-preparation.md)，不按示意名安装 npm 包；新建脚本参照生成接口处理函数的真实导入路径，仅使用下方类型与函数体。

## 这个示例做什么

- 提供一个接口 `demo.start-session`：传入机场 SN，返回一个由幂等键派生的会话 ID。
- 同一个幂等键重复调用，返回**同一个**会话 ID——验证幂等。
- 传空 SN、缺幂等键、多传顶层字段、调不存在的接口，核对本地数字码和 HTTP 状态，再与目标网关对照；不能把本地通过当作部署环境验收。

## 关键代码讲解

### 目录结构

```text
exp_min_demo/                             # 工作区根：package.json、packages.json
└── exp_min_demo/                         # 能力工程目录
    ├── capabilities.json
    ├── frontend/                        # 生成的前端示例，本页保留不改
    ├── mock/                            # 本地数据
    └── backend/exp_min_demo_backend/
        ├── fh2-plugin.json              # 业务源清单
        ├── handlers/demo/start-session.ts # → demo.start-session
        ├── types/                       # 工具链生成，勿手改
        └── tsconfig.json                # 保留生成的检查配置
```

后端插件的接口按 `handlers/` 目录约定登记：`handlers/demo/start-session.ts` + `export function startSession` → `demo.start-session`。没有清单字段需要逐个声明接口。

### 源清单

工作区内 `exp_min_demo/backend/exp_min_demo_backend/fh2-plugin.json`：

```json
{
  "pluginId": "exp_min_demo_backend",
  "name": "最小后端示例",
  "version": "0.1.0"
}
```

清单是严格解析的：出现未知字段整包拒装。必填项只有 `pluginId` / `name` / `version`；`flows`、`connections`、`scripts` 等数组可选。本例不使用它们，直接省略。

### 接口脚本

```ts
// handlers/demo/start-session.ts
import type { HandlerCtx } from 'fh2-plugin-sdk/backend'

interface RecordInput { readonly [key: string]: unknown }

function requireDockSn (input: RecordInput) {
  const sn = String(input.dockSn || '').trim()
  if (!sn) {
    // 契约错误；当前本地模拟器映射为数字 40006，HTTP 差异见下方对照
    throw { code: 'INVALID_ARGUMENT', message: 'dockSn 不能为空' }
  }
  return sn.toUpperCase()
}

function sessionOf (ctx: HandlerCtx, scope: string) {
  // 用幂等键 + scope 派生稳定 ID：同一请求多次调用结果相同
  // 请求没带 Idempotency-Key 时这里会抛契约错，平台不会生成随机值兜底
  return 'SESS-' + ctx.stableId(scope).slice(0, 12)
}

export function startSession (input: RecordInput, ctx: HandlerCtx) {
  const sn = requireDockSn(input)
  return {
    sessionId: sessionOf(ctx, 'session:' + sn),
    dockSn: sn,
    startedAt: ctx.now          // 本次调用的墙钟（RFC3339），不是跨调用稳定时间
  }
}
```

要点：

- `input` 是调用方传来的整块数据，平台不校验，校验要自己写（上面的判空就是）。
- 返回值必须是对象，原样放进响应的 `data`。
- `store`、`log` 等能力是平台按清单 `allowlist` 注入的全局对象——本例没用到所以没有申报。

## 怎么在本地跑起来

在确认的业务父目录运行创建向导：选择「0=完整 Capability」，工作区目录输入 `exp_min_demo`，成员 ID、展示名和包管理器按默认值确认，并选择立即安装。默认后端成员 ID 就是 `exp_min_demo_backend`。命令只要求终端能直接运行 `fh2-plugin`；未注册全局 CLI 时，把它替换为开发者工具目录中 `packages/fh2-plugin-toolchain/bin/fh2-plugin.mjs` 的实际路径：

```bash
fh2-plugin create
cd exp_min_demo
```

当前目录是工作区根，所有替换只在 `exp_min_demo/backend/exp_min_demo_backend/` 内进行：

- 用上方源清单替换 `fh2-plugin.json`。新建 `handlers/demo/start-session.ts` 时先保留生成接口处理函数使用的真实插件 SDK 导入语句，再填入本页类型与函数体；不要把逻辑模块名复制成可安装导入。
- 移除生成的 `handlers/example/`、`events/example-created.ts`、`adapters/example-script.ts`。
- 移除生成的 `shared/records.ts`、`shared/store.ts`、`shared/time.ts`、`shared/validation.ts`，以及 `workflows/example-flow.json` 和 `schema.sql`；本例不使用存储、事件或流程。
- 保留 `tsconfig.json` 和 `types/`（由 `generate` 重生成），保留工作区脚本、`packages.json`、能力声明与前端示例；不要删除整个工程。

仅改清单会留下依赖 `store` 的示例代码，而最小清单没有数据权限，构建仍会失败。完成上述精确替换后，从工作区根执行：

```bash
pnpm run generate
pnpm run validate
pnpm run build
pnpm run dev
```

`build` / `pack` 不监听端口，`dev` 才启动能力工程的插件运行时与本地 HTTP 模拟器。第一次体验受管接口调用可先完成[全栈入门](../20.development/40.hands-on/40.first-fullstack-plugin.md)，插件运行时为 `ctx.apiCall` 自动处理鉴权，不在插件中填写令牌。

### 接入接口服务后的 curl 诊断

以下仅是**接入已启用调试服务或部署环境之后**的诊断示意。目标服务需已加载 `exp_min_demo_backend`，并提供标准 `/plugin-api/plugin/invoke` 路由；仅构建成功不满足这些条件。

`PLUGIN_API_ORIGIN` 由实际接口服务接入配置提供，是不含路径的 HTTP(S) 服务源地址；非本机使用 HTTPS。`PLUGIN_TOKEN` 是插件网关按目标环境鉴权流程提供的有效插件令牌。API 基础路径、服务选择与鉴权配置以接入说明为准；直接后端服务的 Bearer 访问凭据与插件令牌不可互换。

独立 curl 诊断需先完成环境接入并取得有效插件令牌；未取得凭据时，使用全栈界面的受管调用或联系技术支持。

```bash
# 变量先由实际运行环境提供；缺少配置时停止，不发送请求。
export PLUGIN_API_ORIGIN="${PLUGIN_API_ORIGIN:?请设置实际接口服务的 origin}"
export PLUGIN_TOKEN="${PLUGIN_TOKEN:?请设置插件网关提供的有效插件 Token}"
curl -sS -X POST "${PLUGIN_API_ORIGIN%/}/plugin-api/plugin/invoke" \
  -H "Origin: ${PLUGIN_API_ORIGIN%/}" \
  -H "x-plugin-token: ${PLUGIN_TOKEN}" \
  -H 'content-type: application/json' \
  -H 'idempotency-key: demo-001' \
  --data '{"pluginId":"exp_min_demo_backend","handler":"demo.start-session","input":{"dockSn":"dock-7"}}'
```

接口已加载且鉴权有效时，成功响应如下：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "sessionId": "SESS-<稳定的12位>",
    "dockSn": "DOCK-7",
    "startedAt": "<UTC 时间>"
  }
}
```

同一请求键的本地缓存重放会返回第一次的 `startedAt`；换键会执行新调用，墙钟可以不同。不要把缓存现象解释成正式运行时每次重试的 `ctx.now` 恒定。

### 本地响应与正式网关对照

本地后端错误返回 `{code: 数字, message: 原错误标识及文案, data: null}`。以下分别列出当前本地行为与已部署后端服务契约；插件网关的实际 HTTP / 鉴权行为仍按目标环境验证：

| 请求 | 当前本地模拟器 | 已部署后端服务契约（需目标验证） |
| --- | --- | --- |
| 缺少有效插件令牌 | HTTP 401，`10005` | 按目标插件网关的鉴权流程诊断 |
| 空白 `dockSn` | HTTP 400，数字 `40006`，文案含 `INVALID_ARGUMENT` | HTTP 400，数字 `40006` |
| 缺幂等键且调用 `stableId` | HTTP 400，数字 `40006`，文案含 `IDEMPOTENCY_KEY_REQUIRED` | 契约错误，数字 `40006` |
| 调用请求多一个顶层字段 | 当前被接受，HTTP 200、`code: 0` | HTTP 400，数字 `40001` |
| 不存在的接口处理函数 | HTTP 404，数字 `40006`，文案含 `HANDLER_NOT_FOUND` | 插件调用契约错误，数字 `40006` |

缺键时的当前响应示例：

```json
{
  "code": 40006,
  "message": "IDEMPOTENCY_KEY_REQUIRED: stableId 需要 Idempotency-Key。",
  "data": null
}
```

数字分类对齐不代表 HTTP 状态对齐：本地 `NOT_FOUND` 为 HTTP 404 / `20001`，`CONFLICT` 为 409 / `20001`；未分类 `BRIDGE_FAILED` 仍是 HTTP 400 / `50301`，不能因 HTTP 400 把它改成契约错。顶层字段宽松也仍是本地限制。经前端 `ctx.apiCall` 调用时，非零数字码抛 `PLUGIN_GATEWAY_ERROR`，数字码在 `detail.gatewayCode`。完整分类与差异见[错误码](../80.error-codes.md#本地-http-错误)。


## 验证清单

- [ ] 同一个 `Idempotency-Key` 调两次，`sessionId` 不变。
- [ ] 换一个幂等键，`sessionId` 变化。
- [ ] `pnpm run generate`、`validate`、`build` 通过。
- [ ] HTTP 验证前，接口服务已启用、目标后端已加载，且网关提供的环境变量已配置；缺少凭据时不将 curl 记为通过。
- [ ] 空白 SN、缺幂等键、错误接口名的本地数字错误与上表一致，HTTP 状态分别核对，不把本地结果当作目标网关已通过。
- [ ] 顶层多余字段在当前本地模拟器会被接受；正式 `40001` 拒绝行为在目标网关另验。
- [ ] 日志里没有请求体、令牌等敏感数据。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| `/plugin/invoke` 返回 404 | 确认 `pnpm run dev` 已启动且没用 `--frontend-only`；`pluginId` 要用后端插件的 ID |
| 本地 HTTP 404 / `code: 40006`，文案含 `HANDLER_NOT_FOUND` | 检查公开接口名 `demo.start-session`，不要传源码路径；后端 `pluginId` 必须为 `exp_min_demo_backend` |
| 插件没被装载 | 清单有未知字段会整包拒装；对照[源清单参考](../70.api-reference/20.backend/10.plugin-manifest.md)检查 |
| 改了 TS 没生效 | dev 的热更基于构建；确认终端没有构建报错，必要时重启 dev |
| 端口被占 | 先检查占用者，只停止自己启动的 dev，或改用空闲端口 |
