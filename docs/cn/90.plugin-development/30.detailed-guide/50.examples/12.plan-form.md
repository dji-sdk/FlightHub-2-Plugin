# 计划表单任务清单

这个示例在计划创建表单的末尾加一块自定义区域（一个任务清单），并在提交计划时参与校验、给原生请求附加自定义字段。用到 `plan.form-extensions` 扩展点。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## 这个示例做什么

- 新建/复制计划时，表单末尾出现"任务清单"区域，可以筛选任务状态。
- 点提交时，平台先调用你声明的 `validate` 做校验，再调用 `onSubmit` 拿到你返回的自定义字段，合并进原生提交请求。
- 编辑已有计划时走另一条路：宿主只调用 `onEditSubmit`，不渲染你的界面。

## 关键代码讲解

### 清单：声明扩展点和适用计划类型

`fh2-plugin.json`：

```json
{
  "id": "exp_plan_form",
  "name": "计划表单扩展示例",
  "version": "0.1.0",
  "entry": "./plugin.js",
  "extensions": [
    {
      "id": "exp-plan-extension",
      "point": "plan.form-extensions",
      "planType": "all",
      "anchor": "form-end"
    }
  ],
  "views": {
    "plan-tasks": { "entry": "./views/plan-tasks.js" }
  }
}
```

- `planType` 可选 `all` / `normal` / `atob` / `manual`；`all` 表示全部具体计划类型（`normal` / `atob` / `manual`）都适用。
- `anchor` 控制插入位置：`form-end`（表单末尾，默认）或 `task-strategy:after`（策略区之后）。
- 清单里只声明这些静态字段；`render / validate / onSubmit` 在运行时用 `contribute` 提交。

### 入口：贡献渲染、校验和提交补丁

```ts
// src/plugin.ts
import { createViewState, definePlugin } from 'fh2-plugin-sdk'
import type { AppPlanContext } from './generated/plugin-types'
import { planTasksView } from './views/plan-tasks/contract'

interface Task {
  id: number;
  name: string;
  state: 'done' | 'running' | 'todo';
}
interface PlanTasksState {
  filter: 'all' | Task['state'];
  tasks: Task[];
}

export default definePlugin({
  async activate (rawCtx) {
    if (rawCtx.host.id !== 'plan')
      return
    const ctx = rawCtx as AppPlanContext

    const state = createViewState<PlanTasksState>({
      filter: 'all',
      tasks: [
        { id: 1, name: '起飞前检查', state: 'done' },
        { id: 2, name: '航线确认', state: 'running' },
        { id: 3, name: '现场拍照', state: 'todo' },
        { id: 4, name: '数据回传', state: 'todo' },
      ],
    })

    await planTasksView.handle(ctx, {
      state,
      methods: {
        setFilter: ({ filter }) => {
          state.update(current => ({ ...current, filter }))
        },
        complete: ({ id }) => {
          state.update(current => ({ ...current, tasks: current.tasks.map(task => task.id === id ? { ...task, state: 'done' } : task) }))
        },
      },
    })

    await ctx.extensions.contribute('exp-plan-extension', {
      render: () => planTasksView.get(ctx),
      // 校验：无副作用，只读状态做判断
      validate: async () => {
        const current = state.get()
        const hasTodo = current.tasks.some(task => task.state !== 'done')
        return hasTodo ? { valid: false, message: '请先完成全部检查项' } : { valid: true }
      },
      // 校验全部通过后才执行；返回值合并进原生提交请求的自定义字段
      onSubmit: async () => ({ check_tasks: true }),
    })
  },
})
```

### 界面契约与组件

```ts
// src/views/plan-tasks/contract.ts
import { definePluginView } from 'fh2-plugin-sdk'

export interface PlanTasksState {
  readonly filter: 'all' | 'done' | 'running' | 'todo';
  readonly tasks: ReadonlyArray<{ id: number; name: string; state: 'done' | 'running' | 'todo' }>;
}

export const planTasksView = definePluginView<{
  state: PlanTasksState;
  methods: {
    setFilter: (input: { filter: PlanTasksState['filter'] }) => void;
    complete: (input: { id: number }) => void;
  };
}>('plan-tasks')
```

```vue
<!-- src/views/plan-tasks/PlanTasks.vue -->
<script setup lang="ts">
import { computed } from 'vue'
import type { PlanTasksState } from './contract'

const props = defineProps<{
  state: PlanTasksState;
  methods: { setFilter: (input: { filter: PlanTasksState['filter'] }) => Promise<void>; complete: (input: { id: number }) => Promise<void> };
}>()

const visible = computed(() =>
  props.state.filter === 'all'
    ? props.state.tasks
    : props.state.tasks.filter(task => task.state === props.state.filter),
)
</script>

<template>
  <div class="plan-tasks">
    <div>
      <button
        v-for="f in (['all', 'done', 'running', 'todo'] as const)"
        :key="f"
        :data-active="state.filter === f"
        @click="methods.setFilter({ filter: f })"
      >
        {{ f }}
      </button>
    </div>
    <ul>
      <li v-for="task in visible" :key="task.id">
        {{ task.name }} - {{ task.state }}<button v-if="task.state !== 'done'" @click="methods.complete({ id: task.id })">
          标记完成
        </button>
      </li>
    </ul>
  </div>
</template>
```

### 界面入口：src/views/plan-tasks/index.ts

新建这个文件，不能只复制 Vue 组件而省略挂载和方法接线：

```ts
import { createApp, reactive } from 'vue'
import { defineView } from 'fh2-plugin-sdk'
import { planTasksView } from './contract'
import type { PlanTasksState } from './contract'
import PlanTasks from './PlanTasks.vue'

export default defineView({
  mount (ctx) {
    const state = reactive<PlanTasksState>({ filter: 'all', tasks: [] })
    const client = planTasksView.client(ctx.port)
    const subscription = client.state.subscribe(next => Object.assign(state, next))
    const app = createApp(PlanTasks, { state, methods: {
      setFilter: (input: { filter: PlanTasksState['filter'] }) => client.setFilter(input),
      complete: (input: { id: number }) => client.complete(input),
    } })
    app.mount(ctx.mountElement)
    return { dispose () {
      subscription.dispose()
      client.dispose()
      app.unmount()
    } }
  },
})
```

筛选只改变显示列表；点击每个未完成项的「标记完成」，直到全部为 `done`，校验才通过。
本例 `check_tasks` 是插件自定义提交补丁，需由目标业务接口接受，不是原生表单已有字段。


### 提交管线的固定顺序

真实宿主提交计划时按这个顺序执行：

```text
筛选适用的贡献
-> 全量 validate（无副作用）
-> 全量 onSubmit（收集自定义字段）
-> 校验自定义字段之间、与原生字段之间的冲突
-> 合并进原生请求后发送
```

自定义字段的约束：

- 同一次提交中，**最多一个插件**能返回非空自定义字段（biz_ext），多个插件都返回会被整体阻断。
- 自定义字段是挂在一个业务标识下的，key 最长 64 字符，整体不超过 4KB。
- 插件字段与原生字段重名时，提交在发送前整体阻断并提示冲突。

### 聚焦单测：tests/example.test.ts

新建测试文件。它验证入口方法和状态，不替代浏览器或目标环境验收：

```ts
import { describe, expect, it, vi } from 'vitest'
import type { PluginContext } from 'fh2-plugin-sdk'
import plugin from '../src/plugin'

const captured = vi.hoisted(() => ({ session: undefined as any, contribution: undefined as any }))
vi.mock('../src/views/plan-tasks/contract', () => ({ planTasksView: {
  handle: async (_ctx: unknown, session: unknown) => {
    captured.session = session
  },
  get: () => ({}),
} }))

describe('计划检查项', () => {
  it('未完成时拒绝提交，完成全部检查后返回合法补丁', async () => {
    const contribute = vi.fn(async (_id, value) => {
      captured.contribution = value
      return { dispose: vi.fn() }
    })
    await plugin.activate({ host: { id: 'plan' }, extensions: { contribute } } as unknown as PluginContext)
    expect(await captured.contribution.validate()).toEqual({ valid: false, message: '请先完成全部检查项' })
    captured.session.methods.setFilter({ filter: 'todo' })
    expect(captured.session.state.get().filter).toBe('todo')
    for (const task of captured.session.state.get().tasks) captured.session.methods.complete({ id: task.id })
    expect(await captured.contribution.validate()).toEqual({ valid: true })
    expect(await captured.contribution.onSubmit()).toEqual({ check_tasks: true })
  })
})
```

## 怎么在本地跑起来

先完成[环境准备](../20.development/40.hands-on/10.environment-preparation.md)，再创建工程。保留生成工程的依赖、构建配置和实际 SDK 导入路径，按本页合并清单并修改业务实现；新增文件的 SDK 导入路径沿用模板。按上方清单完成后可在本地调试页面验证列表与筛选，提交钩子及字段合并需在真实计划宿主验证。

在确认的业务父目录运行创建向导，选择「1=前端插件」，Plugin ID 输入 `exp_plan_form`，其余项按默认值确认并选择立即安装。命令只要求终端能直接运行 `fh2-plugin`；未注册全局 CLI 时，把它替换为开发者工具目录中 `packages/fh2-plugin-toolchain/bin/fh2-plugin.mjs` 的实际路径：

```bash
fh2-plugin create
cd exp_plan_form
# 按文件修改清单完成替换、新建和原模板清理，再执行检查
pnpm run generate
pnpm run validate
pnpm run test
pnpm run tsc
pnpm run lint
pnpm run build
pnpm exec fh2-plugin dev --frontend-only
```

验证步骤：

1. 打开本地调试页面，切到计划区，新建计划，表单末尾出现"任务清单"。
2. 点状态筛选按钮，列表实时过滤（数据经通信通道在入口代码里更新）。
3. 本地调试页面只呈现界面，不执行完整的产品提交管线；`validate / onSubmit` 的合并效果要在真实计划宿主（或其测试环境）里验证。
4. 编辑已有计划：确认你的界面不渲染、只有 `onEditSubmit` 被调用。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 区域不出现 | 当前是编辑模式（只支持 create/copy 渲染）、`planType` 不匹配，或激活报错 |
| 出现在错误位置 | `anchor` 没写或缺省为 `form-end`；只有 `task-strategy:after` 会进策略区 |
| 提交被整体阻断 | `validate` 返回了 `valid: false`，或与其他插件的自定义字段/原生字段冲突 |
| 本地调试页面里看不到提交效果 | 预期行为：完整提交管线需在真实计划宿主验证 |
| 界面直接改了宿主表单 DOM | 禁止这样做；只通过通信通道更新自己的状态，提交靠 `onSubmit` |
