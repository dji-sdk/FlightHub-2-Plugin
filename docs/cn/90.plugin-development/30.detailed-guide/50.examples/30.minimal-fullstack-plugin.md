# 最小全栈插件

这个示例分为 **可运行示例（界面/HTTP）+ 集成示例（媒体事件）**：驾驶舱面板上报"现场问题"，通过后端接口存储并流转状态（new → acknowledged → resolved）；媒体事件部分讲解如何把照片挂到问题上，需要目标环境验证。本文适用 Toolchain / SDK `1.0.0`。

最短路径：先按“怎么在本地跑界面/HTTP”跑通；再看“关键代码讲解”改自己的字段；媒体事件和正式运行按“支持条件与边界”另验。

> fh2-plugin-sdk 是插件开发 SDK；模块路径示意，实际导入保留生成工程配置。本页不表示同名 npm 包已发布。已有文件保留真实导入语句，仅替换业务函数与类型；新文件参照生成工程中相应 API 的真实导入路径，不添加模块别名。测试中的 `fh2-plugin-toolchain` 同样是工具链逻辑模块名，保留生成测试的真实导入。

## 这个示例做什么

- 前端（驾驶舱左侧面板）：列出问题、上报新问题、签收、完成。
- 后端（4 个 HTTP 接口）：用平台数据存储读写 `issue` 实体，状态推进用条件更新防并发；本地使用内存存储，无需数据库。
- 媒体事件集成示例：消费 `media.photo_created`，意图是把照片挂到最新一条"已签收"的问题上；正式消息接入、输入投影、排序和数据库迁移在目标环境另验。
- 本地支持界面、HTTP、数字错误信封和去重/状态推进；照片、列表容量与 HTTP 状态差异的边界见下表及媒体集成示例。

| 范围 | 支持条件与边界 |
| --- | --- |
| 界面/HTTP | 工具链与模板已就绪，保持 `dev` 运行；重置为空数据后从单问题流程开始，调用由 `ctx.apiCall` 自动处理鉴权。数据仅在当前进程内，重置、重启或实体结构变化会丢失本轮写入 |
| 列表 | 全状态查询按创建时间倒序，最多返回 20 条；本地模拟器支持该对象式排序，但本示例未提供加载后续历史的分页界面 |
| 媒体集成示例 | 本地事件包装与正式消费输入不同，不能完成照片挂载验收；正式输入投影、排序和消息路由需目标环境验证 |
| 正式运行 | 后端包安装、SQL 迁移、网关鉴权和事件配置均是部署前置条件；本地调试不替代这些验收 |

### 后端源清单：声明权限和事件订阅

下文文件路径都以**工作区根**为起点。`exp_issue_demo/backend/exp_issue_demo_backend/fh2-plugin.json`：

```json
{
  "pluginId": "exp_issue_demo_backend",
  "name": "现场问题示例后端",
  "version": "0.1.0",
  "allowlist": ["data:read", "data:write"],
  "flows": [],
  "connections": [],
  "scripts": [],
  "events": [
    {
      "type": "media.photo_created",
      "consumer": [ { "handler": "events/photo-created.ts", "entry": "onPhotoCreated" } ]
    }
  ]
}
```

- `allowlist` 是权限声明：申报了 `data:read / data:write`，脚本里才有全局对象 `store` 可用。
- 接口不用在清单里登记，放 `handlers/` 目录就会被按路径发现。
- **存储不写清单**：数据表由 `schema.sql` 单点定义，工具链从它派生存储实体。

配套的建表脚本（`title` 上的唯一索引是 `createIfAbsent` 去重的前提）：

```sql
-- exp_issue_demo/backend/exp_issue_demo_backend/schema.sql（生产环境由发布流程执行）
CREATE TABLE IF NOT EXISTS plugin_db_issue (
  id         TEXT PRIMARY KEY,
  created_at TIMESTAMPTZ NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL,
  tenant_id  TEXT NULL,
  title      TEXT NULL,
  description TEXT NULL,
  severity   TEXT NULL,
  status     TEXT NULL,
  evidence_file_id TEXT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_issue_title ON plugin_db_issue (title);
CREATE INDEX IF NOT EXISTS idx_issue_status ON plugin_db_issue (status);
```

SQL 物理列使用 `created_at` / `updated_at`；正式 JS `store` 返回的公开时间字段是 `createdAt` / `updatedAt`，筛选和排序也使用这两个公开名。下面的 `orderBy` 必须写 `createdAt`，直接使用 SQL 列名会违反公开字段契约并返回 `UNKNOWN_FIELD`。本地模拟器同样返回公开平台列并支持对象式 `orderBy`；原始状态快照仍保留内部存储行，不要把快照字段当作脚本接口。目标环境的真实存储仍需复验。创建和更新时间由平台维护，不写进创建/更新的业务记录；建表语句保留物理列名。

不要把原始快照里的物理列名复制进业务查询。`store.query` 的返回、筛选及对象式排序均使用公开字段；工具升级后按环境准备步骤重装工程依赖，旧进程不会自动采用修复。

### 后端接口

```ts
// exp_issue_demo/backend/exp_issue_demo_backend/handlers/issue/create.ts
import type { HandlerCtx } from 'fh2-plugin-sdk/backend'

interface RecordInput { readonly [key: string]: unknown }

export function create (input: RecordInput, _ctx: HandlerCtx) {
  const title = String(input.title || '').trim()
  if (!title) {
    throw { code: 'INVALID_ARGUMENT', message: 'title 不能为空' }
  }
  const severity = ['low', 'medium', 'high'].indexOf(String(input.severity)) >= 0 ? String(input.severity) : 'medium'

  // 按标题去重：重复提交不会产生第二条记录，返回已有记录
  // created_at 由平台自动维护，不要自己写（它是保留字段）
  const saved = store.createIfAbsent('issue', {
    title: title,
    description: String(input.description || ''),
    severity: severity,
    status: 'new',
    evidence_file_id: ''
  }, ['title'])

  if (!saved.ok) {
    throw saved.error
  }
  return { id: saved.data.record.id, created: saved.data.created }
}
```

```ts
// exp_issue_demo/backend/exp_issue_demo_backend/handlers/issue/list.ts
import type { HandlerCtx } from 'fh2-plugin-sdk/backend'

interface RecordInput { readonly [key: string]: unknown }

export function list (input: RecordInput, _ctx: HandlerCtx) {
  // 不传状态时保留全部状态，使已签收记录仍可在界面点完成
  const status = String(input.status || '').trim()
  const result = store.query('issue', status ? { status: { eq: status } } : {},
    { orderBy: [{ field: 'createdAt', dir: 'desc' }], limit: 20 })
  if (!result.ok) {
    throw result.error
  }
  return { list: result.data.list, total: result.data.total }
}
```

| 列表约定 | 支持边界 |
| --- | --- |
| 全状态、`limit: 20` | 不传状态时包含已完成历史，使已签收的同一问题可继续完成；最多返回 20 条，不自动加载后续历史 |
| 本地历史数据 | 本地支持对象式 `orderBy`；最新 20 条记录可见，更早历史仍需分页。创建时间相同的记录用 ID 确定顺序，不能依赖接口完成先后 |
| 单问题验收 | 先重置为空数据，再验证上报、签收、完成；正式业务按需求实现分页并在目标环境复验排序，不改用字符串排序 |

```ts
// exp_issue_demo/backend/exp_issue_demo_backend/handlers/issue/acknowledge.ts
import type { HandlerCtx } from 'fh2-plugin-sdk/backend'

interface RecordInput { readonly [key: string]: unknown }

export function acknowledge (input: RecordInput, _ctx: HandlerCtx) {
  const id = String(input.id || '').trim()
  if (!id) {
    throw { code: 'INVALID_ARGUMENT', message: 'id 不能为空' }
  }

  // 条件更新：只有还是 new 才允许签收，affected === 1 才算成功
  const updated = store.update('issue',
    { id: { eq: id }, status: { eq: 'new' } },
    { status: 'acknowledged' })
  if (!updated.ok) {
    throw updated.error
  }
  if (updated.data.affected === 0) {
    throw { code: 'NOT_FOUND', message: '问题不存在或已被签收' }
  }
  return { id: id, status: 'acknowledged' }
}
```

```ts
// exp_issue_demo/backend/exp_issue_demo_backend/handlers/issue/resolve.ts
import type { HandlerCtx } from 'fh2-plugin-sdk/backend'

interface RecordInput { readonly [key: string]: unknown }

export function resolve (input: RecordInput, _ctx: HandlerCtx) {
  const id = String(input.id || '').trim()
  if (!id) {
    throw { code: 'INVALID_ARGUMENT', message: 'id 不能为空' }
  }
  const updated = store.update('issue',
    { id: { eq: id }, status: { eq: 'acknowledged' } },
    { status: 'resolved' })

    throw updated.error
  }
  if (updated.data.affected === 0) {
    throw { code: 'NOT_FOUND', message: '问题不存在或当前状态不可完成' }
  }
  return { id: id, status: 'resolved' }
}
```

### 后端事件消费

这部分是媒体事件集成示例，不是本地成功验收路径。以下 `file_id` 位于正式消息体的消费输入上；上线前还需核对目标后端运行时的消费声明、输入投影与事件路由，见[事件消费](../20.development/20.backend/30.event-handler.md)。

```ts
// exp_issue_demo/backend/exp_issue_demo_backend/events/photo-created.ts
import type { EventCtx } from 'fh2-plugin-sdk/backend'

interface RecordInput { readonly [key: string]: unknown }

export function onPhotoCreated (input: RecordInput, _ctx: EventCtx) {
  const fileId = String(input.file_id || '').trim()
  if (!fileId) {
    // 契约错误：消息进死信，不重投
    throw { code: 'INVALID_ARGUMENT', message: 'file_id 不能为空' }
  }

  // 找最新一条已签收的问题
  const found = store.query('issue', { status: { eq: 'acknowledged' } },
    { orderBy: [{ field: 'createdAt', dir: 'desc' }], limit: 1 })
  if (!found.ok) {
    throw found.error
  }
  const issue = found.data.list[0]
  if (issue === undefined) {
    // 没有进行中的问题：消息按正常处理，不挂载
    return { attached: false }
  }

  // 更新条件里带旧值（evidence_file_id 为空）：消息重复投递时第二次 affected=0，不会重复覆盖
  const updated = store.update('issue',
    { id: { eq: issue.id }, evidence_file_id: { eq: '' } },
    { evidence_file_id: fileId })
  if (!updated.ok) {
    throw updated.error
  }
  if (updated.data.affected === 0) {
    // 已经绑过照片（重复投递），幂等命中
    return { attached: false, issue_id: issue.id }
  }
  return { attached: true, issue_id: issue.id }
}
```

### 前端：统一调用封装

```ts
// exp_issue_demo/frontend/exp_issue_demo_frontend/src/shared/backend.ts
import { isPluginError } from 'fh2-plugin-sdk'
import type { JsonValue, PluginContext } from 'fh2-plugin-sdk'

// 注意：这里填后端清单里的 pluginId，不是前端的 id
const BACKEND_PLUGIN_ID = 'exp_issue_demo_backend'

export async function invoke<T> (
  ctx: Pick<PluginContext, 'apiCall'>,
  handler: string,
  input: Record<string, JsonValue>,
  idempotencyKey?: string,
): Promise<T> {
  try {
    const res = await ctx.apiCall<{ code: number; message: string; data: JsonValue }>('/plugin/invoke', {
      method: 'POST',
      body: { pluginId: BACKEND_PLUGIN_ID, handler, input },
      ...(idempotencyKey ? { idempotencyKey } : {}),
    })
    // 只有网关返回 code === 0 才会走到这里
    return res.data as T
  } catch (error) {
    if (isPluginError(error) && error.code === 'PLUGIN_GATEWAY_ERROR') {
      // 本地与目标网关的非零数字码在 detail.gatewayCode；网络或格式错误可能没有该字段
      const detail = (error.detail ?? {}) as { gatewayCode?: number; gatewayMessage?: string }
      throw new Error(`[网关 ${detail.gatewayCode ?? '?'}] ${detail.gatewayMessage ?? error.message}`)
    }
    throw error
  }
}
```

### 前端：面板状态与操作

```ts
// exp_issue_demo/frontend/exp_issue_demo_frontend/src/plugin.ts
import { createViewState, definePlugin } from 'fh2-plugin-sdk'
import { issuePanelView } from './views/issue-panel/contract'
import { invoke } from './shared/backend'

export interface IssuePanelState {
  readonly list: Array<{ id: string; title: string; severity: string; status: string }>;
  readonly busy: boolean;
  readonly error: string;
}

export default definePlugin({
  async activate (ctx) {
    if (ctx.host.id !== 'cockpit')
      return

    const state = createViewState<IssuePanelState>({ list: [], busy: false, error: '' })

    async function loadRecords () {
      const data = await invoke<{ list: IssuePanelState['list'] }>(ctx, 'issue.list', {})
      state.update(current => ({ ...current, list: data.list }))
    }

    async function runAction (action: () => Promise<void>): Promise<void> {
      state.update(current => ({ ...current, busy: true, error: '' }))
      try {
        await action()
      } catch (error) {
        state.update(current => ({ ...current, error: error instanceof Error ? error.message : '请求失败' }))
      } finally {
        state.update(current => ({ ...current, busy: false }))
      }
    }

    await issuePanelView.handle(ctx, {
      state,
      methods: {
        refresh: () => runAction(loadRecords),
        createIssue: (input: { title: string; description: string; severity: string }) => runAction(async () => {
          const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(JSON.stringify([input.title, input.description])))
          const key = Array.from(new Uint8Array(hash), byte => byte.toString(16).padStart(2, '0')).join('')
          await invoke(ctx, 'issue.create', input, `issue-create:${key}`)
          await loadRecords()
        }),
        acknowledge: (input: { id: string }) => runAction(async () => {
          await invoke(ctx, 'issue.acknowledge', { id: input.id }, `issue-ack:${input.id}`)
          await loadRecords()
        }),
        resolve: (input: { id: string }) => runAction(async () => {
          await invoke(ctx, 'issue.resolve', { id: input.id }, `issue-resolve:${input.id}`)
          await loadRecords()
        }),
      },
    })

    await ctx.extensions.contribute('issue-panel', {
      visible: true,
      label: '现场问题',
      icon: 'issue-board', // 图标必须在插件清单 contributes.icons 里声明，否则渲染为空
      render: () => issuePanelView.get(ctx),
    })
  },
})
```

相同标题、描述按固定数组顺序生成相同 SHA-256 摘要，重试得到相同请求键，无随机值。摘要是 64 个十六进制 ASCII 字符，`issue-create:<摘要>` 固定为 77 字符，满足 `apiCall` 的 1–256 字符限额，不因中文 URL 编码膨胀而超限。业务输入不截断；按标题去重仍由后端唯一索引决定。此实现依赖浏览器 `TextEncoder` / `crypto.subtle`，需本地回环地址或 HTTPS 安全上下文。摘要不等同于完整的生产重试/请求键设计，更严格的约束见[端到端幂等](../20.development/30.fullstack/20.idempotency.md)。

### 界面/HTTP 验收

**开始前先重置为空数据**：使用本页末尾的 `/plugin-api/mock/backend/reset` 命令，在面板点"刷新列表"，确认"暂无现场问题"，再从一个问题的流程开始。列表最多 20 条且包含已完成记录；列表按创建时间倒序；最新 20 条之外的历史没有分页入口。此处可运行示例验收不代表不限历史的业务界面已可用。

1. 打开 `dev` 打印的本地调试页面地址，从默认团队页的设备卡打开设备小窗，再进入虚拟驾驶舱新页签。
2. 点击驾驶舱顶部左侧的"现场问题"面板入口。`visible: true` 表示入口可见，不保证自动展开界面；不要误点另一个 `_issues` 插件的 AI 前工具栏入口。
3. 输入问题标题、描述和严重程度，点"上报问题"，列表显示"待签收"；重复同标题，仍为一条。
4. 点"签收"，同一条保留在列表，显示"处理中"，可以继续点"完成"变为"已完成"。这是本地界面/HTTP 验收，**没有照片也应能完成**。
5. 空标题上报时，本地 HTTP 400 / 数字 `40006`，面板显示 `[网关 40006] INVALID_ARGUMENT: title 不能为空`，而不是白屏。`ctx.apiCall` 抛出的错误是 `PLUGIN_GATEWAY_ERROR`，数字码在 `detail.gatewayCode`，不是普通失败返回值。

保持同一 dev 进程、未重置且实体结构不变时，刷新页面后点「刷新列表」仍可读回本轮问题；重置或重启后本轮数据会丢失，这不是持久化验收。本地数字分类不改变 HTTP 差异：`NOT_FOUND` 是 HTTP 404 / `20001`，未分类 `BRIDGE_FAILED` 是 HTTP 400 / `50301`，不能只按 HTTP 400 判断业务分类。目标网关与真实存储另验，见[后端调试](../40.debug-and-test/30.backend-debugging.md#已知限制)。


### 接入接口服务后的 curl 诊断

首次验证使用上方界面的 `ctx.apiCall` 受管通道，不需要手动获取凭据。以下 curl 仅是**接入已启用调试服务或部署环境之后**的诊断示意：目标服务需已加载本页后端，`PLUGIN_API_ORIGIN` 由实际接口服务接入配置提供，`PLUGIN_TOKEN` 由插件网关按目标鉴权流程提供。仅完成 `build` 不会使接口可用。

示例按同源服务的标准 `/plugin-api/plugin/invoke` 路径组织；服务源地址不含路径，非本机使用 HTTPS。实际 API 基础路径、服务选择和鉴权配置以目标服务接入说明为准；直接后端服务的 Bearer 访问凭据与插件令牌不可互换。没有独立诊断凭据时，使用上方界面的受管调用，或按接入说明完成授权后再运行 curl。

```bash
# 变量先由实际运行环境提供；缺少配置时停止，不发送请求。
export PLUGIN_API_ORIGIN="${PLUGIN_API_ORIGIN:?请设置实际接口服务的 origin}"
export PLUGIN_TOKEN="${PLUGIN_TOKEN:?请设置插件网关提供的有效插件 Token}"
```

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 本地 HTTP 404 / `code: 40006`，文案含 `PLUGIN_NOT_FOUND` 或 `HANDLER_NOT_FOUND` | `pluginId` 写成了前端的 `id`，或接口名不匹配；`body.pluginId` 必须是后端清单的 `pluginId` |
| 脚本里 `store is not defined` | 清单 `allowlist` 没申报 `data:read / data:write`；缺申报的对象根本不会注入 |
| 创建报契约错误要求幂等键 | 脚本用了 `ctx.stableId`；调用方必须带 `Idempotency-Key` |
| 重复上报出现两条记录 | 唯一键设计或 `createIfAbsent` 用法问题；核对 `uniqueBy` 字段 |
| 本地事件报 `file_id 不能为空` | 当前本地模拟器传包装信封，正式消费函数读消息体字段；仅改 JSON 不能解决，不把模拟器专用的 `input.data` 写进生产代码 |
| 目标事件没挂上照片 | 核对正式输入投影含 `file_id`，且记录仍是 `acknowledged`；先投照片再完成 |
| 本地照片选到旧记录 | 核对筛选与 `createdAt` 对象式排序，确认实际运行工具已更新；真实媒体输入仍在目标环境验收，不用字符串兼容分支 |
| 本地通过，目标环境未通过 | 按[HTTP 真实环境预览](../40.debug-and-test/20.frontend-debugging.md#转到真实环境)使用完整项目页 URL，配置 PAC、同源登录、手填本次资源根并完成宿主校验/权限同意/重载；只替换前端，后端包、SQL 与事件配置仍须在目标就绪 |
| 改了模拟测试数据，状态没变 | 注入事件或重置后再看；内存存储不会自动重读修改 |
