# 驾驶舱动作与左侧面板

这个示例在驾驶舱工具栏加一个按钮，点击后打开一个带 Vue 界面的左侧面板。它是"工具栏按钮 → 面板贡献 → Vue 界面"的最短闭环，也是大部分驾驶舱插件的起点。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## 这个示例做什么

- 工具栏出现"最小示例"按钮。
- 点击后左侧面板打开，显示图标、标题和一个计数按钮。
- 按钮本身不拥有界面容器，它调用面板贡献句柄的 `reveal()` 来展示并聚焦面板。
- 图标用 `ctx.blobs` 管理：写一次 Blob，拿受管的 URL 给界面用。

## 关键代码讲解

### 清单：声明按钮、面板和界面

`fh2-plugin.json`：

```json
{
  "id": "exp_minimal",
  "name": "最小示例",
  "version": "0.1.0",
  "entry": "./plugin.js",
  "permissions": ["platform:storage"],
  "extensions": [
    { "id": "open-minimal-panel", "point": "cockpit.ui.toolbar-actions" },
    { "id": "minimal-panel", "point": "cockpit.ui.left-panel" }
  ],
  "contributes": {
    "icons": [{ "id": "plugin", "src": "./icons/plugin.svg" }]
  },
  "views": {
    "minimal-panel": { "entry": "./views/minimal-panel.js" }
  }
}
```

清单里只声明扩展 ID 和扩展点；`label / icon / render / onTrigger` 这些运行时字段在激活时用 `contribute` 提交。`platform:storage` 权限用于 `ctx.blobs`。

### 图标文件：public/icons/plugin.svg

新建图标，清单的 `./icons/plugin.svg` 才能被构建找到（界面里的 Blob 图与工具栏图标是两份资源）：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24"><path fill="#2563eb" d="M4 4h16v16H4z"/></svg>
```

### 入口：两个贡献，一个句柄

```ts
// src/plugin.ts
import { createViewState, definePlugin } from 'fh2-plugin-sdk'
import type { AppCockpitContext } from './generated/plugin-types'
import { minimalPanelView } from './views/minimal-panel/contract'

export default definePlugin({
  async activate (rawCtx) {
    if (rawCtx.host.id !== 'cockpit')
      return
    const ctx = rawCtx as AppCockpitContext

    // 图标 Blob：写入一次，之后直接取受管 URL
    let logo = await ctx.blobs.get('minimal-logo')
    if (!logo) {
      logo = new Blob([
        '<svg xmlns="http://www.w3.org/2000/svg" width="64" height="64">'
        + '<rect width="64" height="64" rx="12" fill="#2563eb"/>'
        + '<text x="32" y="38" text-anchor="middle" font-size="20" fill="white">FH2</text>'
        + '</svg>',
      ], { type: 'image/svg+xml' })
      await ctx.blobs.put('minimal-logo', logo)
    }
    const blobUrl = (await ctx.blobs.url('minimal-logo')) ?? ''

    // 注册界面会话：这里用 handle 的工厂形态——
    // get(ctx, initialState) 传入的初始状态会作为工厂函数的入参，用于按内容创建状态
    await minimalPanelView.handle(ctx, initialState => ({
      state: createViewState(initialState),
      methods: {},
    }))
    // 常规场景（状态固定、不按实例区分）直接用对象形态：
    // await minimalPanelView.handle(ctx, { state: createViewState(...), methods: {...} })
    // 两种形态的说明见「界面与状态」一页。

    // 左侧面板：初始隐藏，等待 reveal()
    const panel = await ctx.extensions.contribute('minimal-panel', {
      visible: false,
      label: '最小示例',
      icon: 'plugin', // 图标 ID 需在清单 contributes.icons 声明
      render: () => minimalPanelView.get(ctx, { blobUrl }),
    })

    // 工具栏按钮：点击打开面板
    await ctx.extensions.contribute('open-minimal-panel', {
      icon: 'plugin', // 图标 ID 需在清单 contributes.icons 声明
      label: '最小示例',
      active: false,
      disabled: false,
      async onTrigger () {
        await panel.reveal()
      },
    })
  },
})
```

要点：

- `panel` 是贡献句柄，`reveal()` 同时完成"展示 + 聚焦"，不需要自己找容器。
- 重复点击同一个按钮复用同一份贡献，不会叠出多个面板。
- `blobUrl` 来自受管的 `ctx.blobs`。不要自己调 `URL.createObjectURL()`：自建对象 URL 不会进入引擎资源台账，卸载后可能泄漏。

### 界面：契约与挂载

```ts
// src/views/minimal-panel/contract.ts
import { definePluginView } from 'fh2-plugin-sdk'

export interface MinimalPanelState {
  readonly blobUrl: string;
}

export const minimalPanelView = definePluginView<{
  state: MinimalPanelState;
  initialState: MinimalPanelState;
  methods: Record<string, never>;
}>('minimal-panel')
```

```ts
// src/views/minimal-panel/index.ts
import { createApp, reactive } from 'vue'
import { defineView } from 'fh2-plugin-sdk'
import { minimalPanelView } from './contract'
import MinimalPanelView from './MinimalPanelView.vue'

export default defineView({
  mount (ctx) {
    const state = reactive({ blobUrl: '', count: 0 })
    const client = minimalPanelView.client(ctx.port)
    const subscription = client.state.subscribe((next) => {
      state.blobUrl = next.blobUrl
    })
    const app = createApp(MinimalPanelView, { state })
    app.mount(ctx.mountElement)
    return {
      dispose: () => {
        subscription.dispose()
        client.dispose()
        app.unmount()
      },
    }
  },
})
```

```vue
<!-- src/views/minimal-panel/MinimalPanelView.vue -->
<script setup lang="ts">
import { reactive } from 'vue'

const props = defineProps<{ state: { blobUrl: string; count: number } }>()
const local = reactive({ count: 0 }) // 点击计数是界面局部状态，关闭后重置
</script>

<template>
  <div class="minimal-panel">
    <img v-if="props.state.blobUrl" :src="props.state.blobUrl" alt="logo" width="32">
    <h3>最小示例</h3>
    <button @click="local.count++">
      点击了 {{ local.count }} 次
    </button>
  </div>
</template>
```

### 聚焦单测：tests/example.test.ts

新建测试文件。它验证入口方法和状态，不替代浏览器或目标环境验收：

```ts
import { describe, expect, it, vi } from 'vitest'
import type { PluginContext } from 'fh2-plugin-sdk'
import plugin from '../src/plugin'

const captured = vi.hoisted(() => ({ factory: undefined as any }))
vi.mock('../src/views/minimal-panel/contract', () => ({ minimalPanelView: {
  handle: async (_ctx: unknown, factory: unknown) => {
    captured.factory = factory
  },
  get: () => ({}),
} }))

describe('驾驶舱面板', () => {
  it('只注册一份面板，用 reveal 展示，并用受管 Blob URL', async () => {
    const reveal = vi.fn().mockResolvedValue(undefined)
    const contributions = new Map<string, any>()
    const contribute = vi.fn(async (id, value) => {
      contributions.set(id, value)
      return { reveal, dispose: vi.fn() }
    })
    const put = vi.fn().mockResolvedValue(undefined)
    await plugin.activate({ host: { id: 'cockpit' }, blobs: { get: vi.fn().mockResolvedValue(undefined), put, url: vi.fn().mockResolvedValue('blob:example') }, extensions: { contribute } } as unknown as PluginContext)
    expect(put).toHaveBeenCalledOnce()
    expect(contribute).toHaveBeenCalledTimes(2)
    await contributions.get('open-minimal-panel').onTrigger()
    expect(reveal).toHaveBeenCalledOnce()
    expect(captured.factory({ blobUrl: 'blob:example' }).state.get()).toEqual({ blobUrl: 'blob:example' })
  })
})
```

## 怎么在本地跑起来

先完成[环境准备](../20.development/40.hands-on/10.environment-preparation.md)，再创建工程。保留生成工程的依赖、构建配置和实际 SDK 导入路径，按本页合并清单并修改业务实现；新增文件的 SDK 导入路径沿用模板。本例的按钮、面板、计数与 Blob 预览可在驾驶舱调试页面验证，不需要发送设备命令。

在确认的业务父目录运行创建向导，选择「1=前端插件」，Plugin ID 输入 `exp_minimal`，其余项按默认值确认并选择立即安装。命令只要求终端能直接运行 `fh2-plugin`；未注册全局 CLI 时，把它替换为开发者工具目录中 `packages/fh2-plugin-toolchain/bin/fh2-plugin.mjs` 的实际路径：

```bash
fh2-plugin create
cd exp_minimal
# 按文件修改清单完成替换、新建和原模板清理，再执行检查
pnpm run generate
pnpm run validate
pnpm run test
pnpm run tsc
pnpm run lint
pnpm run build
pnpm exec fh2-plugin dev cockpit
```

`dev cockpit` 会启动高保真驾驶舱调试页面。验证步骤：

1. 工具栏出现"最小示例"按钮。
2. 点击后面板打开，显示图标、标题和计数按钮；重复点击不会出现第二个面板。
3. 界面里的点击计数是局部状态，关闭再打开面板后归零。
4. 卸载驾驶舱后，诊断面板里界面、通信端口、Blob、订阅等资源计数应全部归零。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 工具栏没有按钮 | 当前宿主不是 `cockpit`，或 `open-minimal-panel` 没提交成功 |
| 点击无面板出现 | 面板贡献没提交成功、`render` 抛错，或 `reveal()` 句柄失效 |
| 图标不显示 | Blob 写入或 URL 生成失败；检查 `platform:storage` 权限和诊断面板 |
| 重复点击出现多个界面 | 复用了不同的贡献；必须对同一扩展 ID 只 `contribute` 一次并用它的句柄 `reveal` |
| 卸载后资源计数非零 | `dispose` 漏释放，或代码绕过了 `ctx.timers` / `ctx.blobs` 自己管理资源 |
