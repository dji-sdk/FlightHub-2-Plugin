# 消息告警卡片

这个示例在消息中心的告警区挂一张可操作的卡片：初始"待处理"，点按钮后变成"已处理"或"已忽略"。用到 `message.alert-popups` 扩展点，并演示界面与入口代码之间如何通过通信通道同步状态。

> `fh2-plugin-sdk` 是插件开发 SDK；下文模块名用于说明，实际导入路径保留生成工程配置。模块名不表示已发布的 npm 包名。

## 这个示例做什么

- 消息区自动出现一张"示例告警"卡片，不需要插件去操作宿主的 DOM。
- 卡片上有"确认处理"和"忽略"两个按钮，点击后状态经通信通道回到入口代码，再同步回界面。
- 插件禁用或宿主卸载时卡片自动关闭。

## 关键代码讲解

### 清单

`fh2-plugin.json`：

```json
{
  "id": "exp_message_alert",
  "name": "消息告警示例",
  "version": "0.1.0",
  "entry": "./plugin.js",
  "permissions": [],
  "extensions": [
    { "id": "exp-alert-card", "point": "message.alert-popups" }
  ],
  "views": {
    "alert-card": { "entry": "./views/alert-card.js" }
  }
}
```

### 界面契约

```ts
// src/views/alert-card/contract.ts
import { definePluginView } from 'fh2-plugin-sdk'

export type Resolution = 'handled' | 'ignored'

export interface AlertCardState {
  readonly title: string;
  readonly occurredAt: string;
  readonly status: 'pending' | Resolution;
}

export const alertCardView = definePluginView<{
  state: AlertCardState;
  methods: {
    resolve: (input: { resolution: Resolution }) => void;
  };
}>('alert-card')
```

### 入口：注册状态、方法和贡献

```ts
// src/plugin.ts
import { createViewState, definePlugin } from 'fh2-plugin-sdk'
import type { AppMessageContext } from './generated/plugin-types'
import { alertCardView } from './views/alert-card/contract'
import type { AlertCardState } from './views/alert-card/contract'

export default definePlugin({
  async activate (rawCtx) {
    if (rawCtx.host.id !== 'message')
      return
    const ctx = rawCtx as AppMessageContext

    const state = createViewState<AlertCardState>({
      title: '示例告警：检测到一条待处理事件',
      occurredAt: new Date().toLocaleTimeString('zh-CN', { hour12: false }),
      status: 'pending',
    })

    await alertCardView.handle(ctx, {
      state,
      methods: {
        resolve: ({ resolution }) => {
          state.update(current => ({ ...current, status: resolution }))
        },
      },
    })

    await ctx.extensions.contribute('exp-alert-card', {
      visible: true,
      render: () => alertCardView.get(ctx),
    })
  },
})
```

真实宿主会把 `visible !== false` 的每个贡献交给消息中心，以高优先级、常驻（不自动关闭）的方式展示；多个插件的告警卡片可以并存。

### 界面：挂载与组件

```ts
// src/views/alert-card/index.ts
import { createApp, reactive } from 'vue'
import { defineView } from 'fh2-plugin-sdk'
import { alertCardView } from './contract'
import type { AlertCardState, Resolution } from './contract'
import AlertCard from './AlertCard.vue'

export default defineView({
  mount (ctx) {
    const state = reactive<AlertCardState>({
      title: '',
      occurredAt: '',
      status: 'pending',
    })
    const client = alertCardView.client(ctx.port)
    const subscription = client.state.subscribe((next) => {
      Object.assign(state, next)
    })
    const app = createApp(AlertCard, {
      state,
      onResolve: (input: { resolution: Resolution }) => client.resolve(input),
    })
    app.mount(ctx.mountElement)
    return {
      dispose: () => {
        subscription.dispose()
        client.dispose()
        app.unmount()
      },
    }
  },
})
```

```vue
<!-- src/views/alert-card/AlertCard.vue -->
<script setup lang="ts">
import type { AlertCardState, Resolution } from './contract'

defineProps<{
  state: AlertCardState;
  onResolve: (input: { resolution: Resolution }) => Promise<void>;
}>()

const statusText: Record<AlertCardState['status'], string> = {
  pending: '待处理',
  handled: '已处理',
  ignored: '已忽略',
}
</script>

<template>
  <div class="alert-card">
    <div class="alert-card__title">
      {{ state.title }}
    </div>
    <div class="alert-card__time">
      发生时间：{{ state.occurredAt }}
    </div>
    <div class="alert-card__status">
      状态：{{ statusText[state.status] }}
    </div>
    <div v-if="state.status === 'pending'" class="alert-card__actions">
      <button @click="onResolve({ resolution: 'handled' })">
        确认处理
      </button>
      <button @click="onResolve({ resolution: 'ignored' })">
        忽略
      </button>
    </div>
  </div>
</template>
```

### 聚焦单测：tests/example.test.ts

新建测试文件。它验证入口方法和状态，不替代浏览器或目标环境验收：

```ts
import { describe, expect, it, vi } from 'vitest'
import type { PluginContext } from 'fh2-plugin-sdk'
import plugin from '../src/plugin'

const captured = vi.hoisted(() => ({ session: undefined as any }))
vi.mock('../src/views/alert-card/contract', () => ({ alertCardView: {
  handle: async (_ctx: unknown, session: unknown) => {
    captured.session = session
  },
  get: () => ({}),
} }))

describe('告警卡片', () => {
  it('确认和忽略通过入口更新状态，而不是直接改宿主页面', async () => {
    const contribute = vi.fn().mockResolvedValue({ dispose: vi.fn() })
    await plugin.activate({ host: { id: 'message' }, extensions: { contribute } } as unknown as PluginContext)
    expect(contribute).toHaveBeenCalledWith('exp-alert-card', expect.objectContaining({ visible: true }))
    expect(captured.session.state.get().status).toBe('pending')
    captured.session.methods.resolve({ resolution: 'handled' })
    expect(captured.session.state.get().status).toBe('handled')
    captured.session.methods.resolve({ resolution: 'ignored' })
    expect(captured.session.state.get().status).toBe('ignored')
  })
})
```

## 怎么在本地跑起来

先完成[环境准备](../20.development/40.hands-on/10.environment-preparation.md)，再创建工程。保留生成工程的依赖、构建配置和实际 SDK 导入路径，按本页合并清单并修改业务实现；新增文件的 SDK 导入路径沿用模板。本例只演示卡片内存状态变化，不依赖后端回执接口，可在本地调试页面验证卡片与按钮交互。

在确认的业务父目录运行创建向导，选择「1=前端插件」，Plugin ID 输入 `exp_message_alert`，其余项按默认值确认并选择立即安装。命令只要求终端能直接运行 `fh2-plugin`；未注册全局 CLI 时，把它替换为开发者工具目录中 `packages/fh2-plugin-toolchain/bin/fh2-plugin.mjs` 的实际路径：

```bash
fh2-plugin create
cd exp_message_alert
# 按文件修改清单完成替换、新建和原模板清理，再执行检查
pnpm run generate
pnpm run validate
pnpm run test
pnpm run tsc
pnpm run lint
pnpm run build
pnpm exec fh2-plugin dev --frontend-only
```

验证步骤：

1. 打开本地调试页面，切到消息区，出现"示例告警"卡片，初始状态"待处理"。
2. 点"确认处理"→ 状态变"已处理"；点"忽略"→ 变"已忽略"。
3. 禁用插件，卡片关闭；重新启用后只出现一张。
4. 打开诊断面板，卸载消息宿主后确认界面、通信端口、订阅计数全部归零。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 卡片不出现 | 当前不是消息宿主、贡献没提交成功，或 `visible` 不是 `true` |
| 点按钮没反应 | 界面没订阅状态，或 `client.resolve` 抛错（看控制台） |
| 多个告警卡片互相覆盖 | 不应该发生：扩展点支持多个贡献并存，检查是否复用了同一个扩展 ID |
| 关闭后又出现 | 贡献仍可见或插件被重载；按诊断时间线确认 |
| 卸载后资源计数非零 | `dispose` 里漏了释放订阅、client 或 Vue app |
