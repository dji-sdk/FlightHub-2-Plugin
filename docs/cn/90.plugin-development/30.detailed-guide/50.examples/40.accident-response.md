# 事故快处

本页是事故快处的业务案例：项目宿主发现警情，消息宿主选设备和路线，驾驶舱宿主执行现场动作，后端流程推进事件状态并派遣无人机。本页提供分工、协议和部署依赖的节选，并非完整可启动工程。可运行练习见[最小后端插件](./20.minimal-backend-plugin.md)和[最小全栈插件](./30.minimal-fullstack-plugin.md)。

## 这个示例做什么

- **项目宿主（`project`）**：轮询警情列表（每 10 秒），签收警情后请求消息宿主展示派遣卡。
- **消息宿主（`message`）**：加载可用机场、规划航线并预览，把选好的路线提交给后端流程。
- **驾驶舱宿主（`cockpit`）**：按 URL 参数里的 `pluginEventId` 进入现场界面，结合事件状态和真实遥测决定是否显示"抵近目标"。
- **后端流程**：收到警情事件后启动流程，等待人工信号（签收、选路），再调受控步派遣任务、轮询任务结果。

两个插件包分工明确：前端插件 ID 是 `official_accident_response`，后端流程所在包的 `pluginId` 是 `official_accident_plugin`。它们**不是**同一个包，靠事件模型和流程 HTTP API 协作——不要为了"对齐"去改 ID。

## 关键代码讲解

### 前端：三宿主分发与跨宿主通信服务

> fh2-plugin-sdk 为文档使用的 SDK 模块名；实际路径使用生成工程配置。保留生成工程中的实际 import，不按文档模块名修改依赖或工具链别名。

```ts
// src/plugin.ts
import { definePlugin } from 'fh2-plugin-sdk'

export default definePlugin({
  async activate (ctx) {
    ctx.logger.info('事故快处插件开始激活', { hostId: ctx.host.id })
    if (ctx.host.id === 'message') {
      return (await import('./hosts/message/activate')).activate(ctx)
    }
    if (ctx.host.id === 'project') {
      return (await import('./hosts/project/activate')).activate(ctx)
    }
    if (ctx.host.id === 'cockpit') {
      return (await import('./hosts/cockpit/activate')).activate(ctx)
    }
  },
})
```

项目宿主调用、消息宿主提供的跨宿主通信服务（跨宿主请求展示派遣卡）：

// src/services/alert-flow.ts
import { definePluginService } from 'fh2-plugin-sdk'

### 后端：流程定义

流程名 `accident-response-cascade`，只由事件流（`stream`）触发：

`workflows/accident-response-cascade.json` 的架构节选如下；省略了信号输入输出、受控步入参及其他步骤，不能作为可发布的完整流程定义：

```json
{
  "name": "accident-response-cascade",
  "trigger": {
    "stream": {
      "match": { "status": "unacknowledged", "event_type": "警情" },
      "seed": ["eventId", "eventType", "occurredAt", "priority", "lat", "lng", "payload"]
    }
  },
  "steps": [
    { "id": "ack", "action": "wait_signal", "await": { "signal": "acknowledge", "timeoutSec": 3600 } },
    { "id": "pick", "needs": ["ack"], "action": "wait_signal", "await": { "signal": "route_selected", "timeoutSec": 3600 } },
    { "id": "dispatch", "needs": ["pick"], "action": "dispatch_mission", "inputs": { "...": "..." } },
    { "id": "poll", "needs": ["dispatch"], "action": "query_flight_task", "timeoutSec": 1800, "maxAttempts": 120 }
  ]
}
```

- `wait_signal` 是人工等待点：流程挂起，等前端发信号才继续。
- `dispatch_mission` 是平台受控步：只有它能下发飞行任务，脚本永远拿不到裸设备函数——这是安全边界。
- `query_flight_task` 每 15 秒轮询一次任务状态，最长 1800 秒；任务完成则流程收尾。

### 前端信号协议

前端只发三种信号，HTTP 路径固定：

```text
GET  /flows/accident-response-cascade/incidents/<eventId>/status
POST /flows/accident-response-cascade/incidents/<eventId>/signals/acknowledge
POST /flows/accident-response-cascade/incidents/<eventId>/signals/route_selected
POST /flows/accident-response-cascade/incidents/<eventId>/signals/ignore
```

规则：

- 每次发信号前必须先查 `awaitingSignal`——按钮由"流程正在等什么"决定，不是由前端本地状态猜。
- `route_selected` 的请求体只允许三个字段：`waylineUuid`、`dockSn`、`projectUuid`，一个不能少也不能多。
- `ignore` 只在流程等待 `route_selected` 时有效；返回 `40901` 说明当前不在等这个信号，重新查状态。
- 选好路线登记成功后复用同一个 `waylineUuid`，信号重试不会重复登记。

### 主路径

```text
acknowledge（签收）
→ 事件状态 acknowledged
→ route_selected（选路）
→ dispatch_mission（派遣）
→ 事件状态 handling，写入 flightMissionId
→ 每 15 秒 query_flight_task，最长 1800 秒
→ 任务完成：流程收尾
→ 任务失败/取消：流程终止
```

中途急停不走流程信号：停止飞行要用平台的真实急停能力，流程从轮询结果收敛。

## 案例定位与依赖

本案例不包含可公开获取的完整工程，因此不提供下载、进入案例目录或启动模拟器的命令。要实践插件创建、构建和 HTTP 调用，使用已有的[最小后端插件](./20.minimal-backend-plugin.md)；要实践前后端状态闭环，使用[最小全栈插件](./30.minimal-fullstack-plugin.md)。

复用本页架构到自己的插件时，先在自己的生成工程补齐清单、宿主激活、插件界面、跨宿主通信服务和完整流程接线。本地调试页面只能检查三宿主界面、模拟状态、路线呈现和能力调用，不提供真实账号、路线服务、流程或设备。

在自己的工程中，`validate` 检查流程 JSON、脚本入口和输入输出一致性，`build` 只生成产物，`pack` 构建并组装交付包，都不会启动网关。含后端且非 `--frontend-only` 的 `dev` 仅启动本地 HTTP 模拟器，不执行流程；流程实例的信号等待、重试和中断恢复需在已部署测试环境验证：

1. 重复触发同一业务 ID 不会产生第二个流程实例。
2. 发人工信号前先查询当前等待状态（`awaitingSignal`）。
3. 主步骤失败或取消后，收尾步骤仍会执行。

| 依赖 | 验证前提 |
| --- | --- |
| 插件与流程 | 部署方确认前后端版本、完整流程定义和信号协议已装载 |
| 事件模型与投递 | 部署方确认事件源、队列投递和状态更新可用，使用隔离测试警情 |
| 路线规划与登记 | 目标项目具备相应能力，生成的 `waylineUuid` 可查询并复用 |
| 任务服务与设备 | 测试账号具备权限，任务状态可查询，设备已获审批 |

⚠️ 本页不提供覆盖这些依赖的一键模拟工具。测试入口、授权和服务接入由部署方提供；需要运行日志或消息重放时联系技术支持或部署方。任何可能下发任务或设备命令的测试，必须使用隔离项目和审批过的设备。本地调试页面里的"派遣成功"只是模拟结果，不能作为真实航线或设备证据。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 项目宿主有警情但无法派遣 | 消息宿主的跨宿主通信服务未就绪，或设备/路线能力不可用 |
| 发信号返回 `40901` | 流程当前不在等这个信号；先查状态再操作 |
| `route_selected` 返回 `40003/40005` | 三个字段缺失、类型错误，或带了已废弃字段 |
| 派遣后长时间停在轮询 | 查任务服务状态和活动心跳；此时前端不应再发信号 |
| 驾驶舱宿主不显示"抵近目标" | URL 缺 `pluginEventId`、事件状态不允许，或飞机不在空中 |
| 前端把本地状态当流程状态 | 按钮和状态一律以 `awaitingSignal` 和事件模型为准 |
