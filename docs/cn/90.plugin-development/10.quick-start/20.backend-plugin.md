# 后端插件

这一页用最短路径做出一个可调用的后端接口：创建完整能力工程，认识后端成员，启动本地 HTTP 模拟器，用 curl 创建和查询记录。完整代码讲解见[第一个后端插件](../30.detailed-guide/20.development/40.hands-on/30.first-backend-plugin.md)。

## 1. 创建工程

在开发者工具目录外创建工作区，向导选择“完整能力工作区”：

```bash
mkdir -p "$HOME/fh2-plugin-projects"
cd "$HOME/fh2-plugin-projects"
fh2-plugin create
```

| 向导问题 | 本页填写 |
| --- | --- |
| 工程类型 | `0`（完整能力工作区） |
| 工作区目录 | `exp_hello` |
| 名称 | `第一个后端插件` |
| 包管理器 | `pnpm` |
| 是否立即安装依赖 | `是` |

进入工作区并生成、校验：

```bash
cd exp_hello
pnpm run generate
pnpm run validate
```

工程有三层：外层工作区根、同名能力目录、各插件成员。后端成员在：

```text
exp_hello/
└── exp_hello/
    └── backend/exp_hello_backend/
        ├── fh2-plugin.json
        ├── handlers/example/create.ts
        ├── handlers/example/list.ts
        ├── schema.sql
        └── shared/records.ts
```

后端插件 ID 是 `exp_hello_backend`，和前端 ID 不同。前端调用时必须写后端 ID。

## 2. 认识一个接口

`handlers/example/create.ts` + `export function create` 对应接口名 `example.create`。文件路径和命名导出就是接口名，不需要在清单里逐个登记。

模板已经包含创建和查询。先不要改代码，直接验证：

- `example.create` 接收 `record_key` 和 `title`，用 `record_key` 做业务唯一键。
- `example.list` 查询当前进程内的记录。
- 数据表由 `schema.sql` 定义，`store` 只有在 `allowlist` 申报 `data:read` / `data:write` 后才存在。

## 3. 启动本地后端模拟器

在工作区根执行：

```bash
pnpm exec fh2-plugin dev --root exp_hello/backend/exp_hello_backend
```

`fh2-plugin dev` 会先构建当前后端，再启动本地 Mock Gateway，不需要上传或安装到司空。它只验证 Handler 调用和 `store` 读写；记录保存在进程内存中，重启即清空，不会执行 `schema.sql`，也不会创建真实数据库表。

终端会打印本次的 Gateway URL 和本地调用凭据。保持命令运行，另开终端设置变量：

```bash
FH2_DEV_URL='<本次打印的 Gateway URL>'
FH2_PLUGIN_TOKEN='<本次打印的本地调用凭据>'
```

创建一条记录：

```bash
curl -sS -X POST "$FH2_DEV_URL/plugin-api/plugin/invoke" \
  -H "Origin: $FH2_DEV_URL" \
  -H "x-plugin-token: $FH2_PLUGIN_TOKEN" \
  -H 'content-type: application/json' \
  -H 'idempotency-key: demo-001' \
  --data '{"pluginId":"exp_hello_backend","handler":"example.create","input":{"record_key":"demo-1","title":"第一条记录"}}'
```

预期 `data.created` 为 `true`。再查列表：

```bash
curl -sS -X POST "$FH2_DEV_URL/plugin-api/plugin/invoke" \
  -H "Origin: $FH2_DEV_URL" \
  -H "x-plugin-token: $FH2_PLUGIN_TOKEN" \
  -H 'content-type: application/json' \
  --data '{"pluginId":"exp_hello_backend","handler":"example.list","input":{}}'
```

预期列表里有一条记录。

## 4. 看一次幂等和预期失败

用同一个 `record_key`、换一个 `idempotency-key` 再创建一次：

```bash
# 只改 idempotency-key 和 title，record_key 保持 demo-1
```

预期 `created` 为 `false`，列表仍然只有一条。业务唯一键负责去重，请求幂等键负责重试缓存，两者不是一回事。

再故意不传 `record_key`：

```bash
curl -sS -X POST "$FH2_DEV_URL/plugin-api/plugin/invoke" \
  -H "Origin: $FH2_DEV_URL" \
  -H "x-plugin-token: $FH2_PLUGIN_TOKEN" \
  -H 'content-type: application/json' \
  -H 'idempotency-key: demo-invalid' \
  --data '{"pluginId":"exp_hello_backend","handler":"example.create","input":{"title":"缺少业务键"}}'
```

预期返回非零错误码，文案包含 `record_key`。不要把失败吞成成功。

## 5. 打包

停掉本地模拟器，在外层工作区根执行：

```bash
pnpm run generate
pnpm run validate
pnpm run test
pnpm -r --if-present run tsc
pnpm -r --if-present run lint
pnpm run build
pnpm run pack
```

终端最后打印 `UPLOAD_READY` 和 ZIP 路径，这就是可以上传的安装包。包结构见[行业包构建与打包](../30.detailed-guide/60.delivery-and-security/20.industry-package.md)，上传、安装和回滚见[安装、升级与回滚](../30.detailed-guide/60.delivery-and-security/50.installation-and-upgrade.md)。

## 6. 自查

- [ ] `pnpm run validate` 通过。
- [ ] `example.create` 创建成功，`example.list` 能读回。
- [ ] 同 `record_key` 再创建，`created: false`，没有第二条记录。
- [ ] 缺 `record_key` 时返回明确错误。
- [ ] `pnpm run pack` 产出 ZIP，终端有 `UPLOAD_READY`。
- [ ] 知道本地模拟器不是真实网关，也不执行 Workflow/队列。
