# 快速开始总览

先选一条路线，完成一个能运行、能验证的最小闭环。三条路线共用同一套开发者工具和工程结构，收尾都是同一套「校验 → 构建 → 打包」；做完一条后，其他路线可以直接复用工程。

| 路线 | 适合谁 | 时间 | 你会得到 |
| --- | --- | --- | --- |
| [前端插件](./10.first-plugin.md) | 主要做页面和交互 | 15-20 分钟 | 在本地驾驶舱打开面板，改标题，校验并打包 |
| [后端插件](./20.backend-plugin.md) | 主要写接口、事件或数据 | 20-30 分钟 | 一个可调用的 HTTP 接口，创建和查询都能看到结果，最后打包 |
| [全栈闭环](./30.fullstack-plugin.md) | 要把前后端接起来 | 45-60 分钟 | 表单 → 接口 → 存储 → 刷新读回的完整链路，最后打包 |

打包出来的是安装包，上传、安装和回滚统一在[安装、升级与回滚](../30.detailed-guide/60.delivery-and-security/50.installation-and-upgrade.md)里讲，不在每条路线里重复。

需要多步执行、等待外部信号或下发任务时，再往后走一步：[流程编排练习（DAG）](../30.detailed-guide/20.development/20.backend/65.workflow-hands-on.md)。

## 共同前提

源码：<https://github.com/dji-sdk/FlightHub-2-Plugin>（`Download ZIP` 或 `git clone`）。

- 开发工具源码；SDK 位于 `packages/fh2-plugin-sdk/`，Toolchain 和 Skill 也随完整源码提供。本机有 Node.js **20.19 或更高**和浏览器。
- 第一次使用先完成[环境准备](../30.detailed-guide/20.development/40.hands-on/10.environment-preparation.md)。
- 前端路线使用端口 `5176`；全栈路线使用端口 `5175`。端口被占用时先释放，不要同时启动多个 dev 进程。

当前发行版与已知限制见[发版说明](../99.release-notes.md)。

## 先跑模板，再改代码

三条路线都建议先运行生成的模板，确认工程、ID 和调用链正确，再做修改。不要在模板还没跑通时同时改清单、前端和后端，否则很难判断失败发生在哪一层。

需要更完整的代码讲解时：

- 前端完整练习：[第一个前端插件](../30.detailed-guide/20.development/40.hands-on/20.first-frontend-plugin.md)
- 后端完整练习：[第一个后端插件](../30.detailed-guide/20.development/40.hands-on/30.first-backend-plugin.md)
- 全栈完整练习：[第一个全栈插件](../30.detailed-guide/20.development/40.hands-on/40.first-fullstack-plugin.md)

## 本地验证的边界

本地调试页面和 HTTP 模拟器用于快速反馈：

- 前端：验证扩展点、界面装载、入口与界面的通信。
- 后端：验证 HTTP 接口、事件脚本和进程内存储。
- 不执行真实 Workflow、队列和真实网关；`preview` 只替换前端资源。

真实宿主、真实后端、流程执行和设备行为必须在目标环境确认。本地通过不等于生产可用。
