# 全栈闭环

目标是跑通一次真实的最小业务：面板提交 → 调后端接口 → 写进本地后端存储 → 刷新后还能读回来。

模板自带的 hello 和现场问题面板只把状态放在内存里，刷新就回到初始值。这条路线换成有后端的工程：按[最小全栈示例](../30.detailed-guide/50.examples/30.minimal-fullstack-plugin.md)新建 `exp_issue_demo`，四个后端接口、`schema.sql` 和前端入口都由那一页给出，这里不重复代码。

## 1. 建工程，接上后端

在确认为空的目标目录执行 `fh2-plugin create`，选「0=完整能力工作区」，工作区目录填 `exp_issue_demo`，包管理器选 pnpm 并立即安装。

再按最小全栈示例的「工程结构」一节替换后端 `handlers/issue/*.ts` 和 `schema.sql`，以及前端清单与入口。换完执行：

```bash
pnpm run generate
pnpm run validate
```

两条都通过，说明清单、接口和界面代码对得上。前端调用时 `pluginId` 写 `exp_issue_demo_backend`——写前端自己的 ID 会得到 `PLUGIN_NOT_FOUND`。

## 2. 跑起来，提交一条

```bash
pnpm run dev
```

打开终端打印的地址进入驾驶舱，找到「现场问题」面板，新建一条问题（标题必填，描述可选），列表里应出现它，状态为待处理。

## 3. 刷新，确认读回

刷新浏览器页面再打开面板，刚才那条还在。停掉 `pnpm run dev` 再启动，记录回到初始数据——本地后端是进程内存储，这一步证明的是"数据不在浏览器内存里"，不是生产持久化。

## 4. 验两件事

- 标题留空时提交：面板给出错误提示或不允许提交，但不会出现空标题记录。
- 用同一业务键再提交一次：列表里不出现第二条，写法见[端到端幂等](../30.detailed-guide/20.development/30.fullstack/20.idempotency.md)。

## 5. 打包

停掉 `dev` 进程，在工作区根执行：

```bash
pnpm run generate
pnpm run validate
pnpm run test
pnpm -r --if-present run tsc
pnpm -r --if-present run lint
pnpm run build
pnpm run pack
```

终端最后打印 `UPLOAD_READY` 和 ZIP 路径，这就是可以上传的安装包。包结构见[行业包构建与打包](../30.detailed-guide/60.delivery-and-security/20.industry-package.md)，上传、安装和回滚见[安装、升级与回滚](../30.detailed-guide/60.delivery-and-security/50.installation-and-upgrade.md)。

## 6. 自查

- [ ] 前端清单声明了 `platform:http`。
- [ ] `pluginId` 使用后端插件 ID。
- [ ] 只有入口代码调用 `ctx.apiCall`，界面通过契约方法取数据。
- [ ] 创建、列表、缺字段失败、重复提交都验证过。
- [ ] `pnpm run pack` 产出 ZIP，终端有 `UPLOAD_READY`。
- [ ] 知道本地进程内存不等于生产持久化；真实存储和目标网关需在目标环境验证。
