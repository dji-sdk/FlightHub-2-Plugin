# 调试与交付

按顺序验证：源码检查 → 本地页面 → 目标环境 → 打包。

## 1. 先跑源码检查

```text
帮我验一下这次改动：先说清楚影响哪些成员、实际要跑哪些脚本，再依次跑生成、校验、相关单测、类型检查和构建。
每条命令都把命令和结果贴出来。
```

顺序：`generate` → `validate` → 聚焦单测 → `tsc` → `build`。后端测试单独运行，不能用根目录的前端测试代替。

| 结果 | 能说明什么 |
| --- | --- |
| `validate` 通过 | 清单声明符合当前检查 |
| 单测和类型检查通过 | 已覆盖的逻辑正确 |
| `build` 成功 | 产物能构建 |
| 本地页面已观察 | 当前 Mock 数据下面板工作 |

以上都不代表真实环境可用。

## 2. 失败时先定位

```text
构建挂了，先诊断，别重建工程。
保留原命令和错误信息，定位到文件后改一处，再用最小的命令复验一遍。
```

三个常见问题：

- 页面没有按钮：查路由、Host 挂载和成员是否启用，不要先重装依赖。
- 弹窗无样式：查组件库版本，样式是否挂到 `ctx.styleTarget`，浮层是否挂到 `ctx.overlayElement`。
- 显示成功但刷新无记录：分别查接口返回、列表和存储范围。

## 3. 本地调试

```text
可以起本地 dev 了，只用 Mock 数据。
验证成员加载、目标页面和主操作，把实际地址记下来。
做完把服务停掉。
```

工具栏有四个面板：

| 面板 | 用途 |
| --- | --- |
| 插件 | 成员、版本和启用状态 |
| Host | 页面需要的宿主与实际挂载 |
| 场景 | 模拟输入和事件 |
| 诊断 | 构建、激活和运行记录 |

## 4. 目标环境预览（可选）

```text
先给我 preview 的预检，别启动。
确认一下目标环境是不是 HTTP、登录权限够不够、本地后端是什么版本。
把代理、调试面板和怎么恢复说清楚，等我确认再动。
```

确认后按 CLI 输出的地址操作，结束后停止服务并恢复代理。本地能跑不代表宿主能加载。

## 5. 打包与报告

```text
核对一下 pack 的范围和产物位置，我确认后你再执行。
不要上传、不要发布、也不要部署。
```

在行业工作区根或 Capability 根打包，不在单个成员目录打包。

交付报告应包含：

- 改动文件和版本
- 生成的产物位置
- 每项检查的命令和结果
- 页面由谁验证
- 未执行的项：上传、部署、真机验证

## 可选：MCP 与 Web IDE

MCP 让客户端直接调用本地 Toolchain；Web IDE 用 `serve` 打开，可以修改本地工程。

- 启动前确认地址和写入范围，用完停止。
- `build` / `pack` 是异步任务：轮询到 `succeeded`、`failed` 或 `cancelled` 才算结束，任务受理不等于完成。
- Web IDE 保存看逐文件回执，区分 `saved`、`failed`、`conflicted`、`pending`。
- DAG 校验通过只代表编辑期检查通过，不代表可以部署或执行。
