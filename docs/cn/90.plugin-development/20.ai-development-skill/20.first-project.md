# 第一个工程

用一个完整工作区跑通“描述 → 澄清 → 确认 → 执行 → 验证”。

完整 Capability 模板包含两个前端成员和一个后端成员：`hello` 是按钮加计数面板的最小示例，`issue` 是列表加弹窗的示例。先跑通模板，再改一处行为。

## 1. 创建工程

```text
用 fh2-plugin-dev 帮我建一个完整的 Capability 工作区，目录放在 <我的目录>。
先看一眼环境，缺什么就问我，把方案讲清楚；我确认之前别创建、也别装依赖。
```

AI 通常会问：工程放在哪、用哪个包管理器、第一版是否需要后端。回答后它会给出方案：目录、成员、要执行的命令和影响范围。

确认时可以直接说：

```text
方案可以，就按这个来：在空目录里创建、装依赖，然后跑生成、校验、测试和构建。
模板成员先别动，业务代码也先别改。
```

## 2. 确认模板可运行

AI 依次执行：

| 步骤 | 目的 |
| --- | --- |
| `create` | 生成工作区 |
| 安装依赖 | 拉取模板依赖 |
| `generate` | 生成插件类型 |
| `validate` | 校验清单 |
| `test` / `build` | 跑模板测试和构建 |

这一步只看模板是否正常。有报错先修模板，不要靠改业务代码绕过。

工作区大致结构：

```text
<工作区>/
|-- packages.json          # 上传清单
`-- <Capability ID>/
    |-- capabilities.json  # 能力元数据
    |-- frontend/          # hello、issue 成员
    `-- backend/           # 后端成员
```

## 3. 改一处行为

```text
把 hello 面板改成一个“巡检计数”：显示当前次数，加一个重置按钮，数到 5 的时候给个提示。
次数先放在面板内存里，不接后端。
先告诉我你打算改哪几个文件，我确认了你再动手。
```

AI 应说明改哪些文件、怎么接状态、补哪些测试。实现后重新运行生成、校验、测试和构建。

## 4. 本地看效果（可选）

```text
可以起本地 dev 了，帮我验证打开面板、计数和重置这三件事，做完把服务停掉。
```

在驾驶舱里打开 hello 面板确认交互。看不到面板时，先检查入口和成员是否启用。

## 完成标准

- 创建和修改的文件清单
- 生成、校验、测试、构建的实际结果
- 页面行为是谁验证的（AI 或你）
- 未做的部分：后端持久化、真实设备、部署
