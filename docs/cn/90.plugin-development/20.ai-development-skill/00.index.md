# AI 开发 Skill

安装 `fh2-plugin-dev` 后，可以直接用自然语言描述想做的插件。AI 先澄清需求、查当前可用接口，给出方案；你确认后，它再创建或修改工程、执行校验和测试，并报告实际结果。

不需要先背扩展点和命令。说清要解决什么问题、在哪个页面用、数据从哪来，就足够开始。

## 一次对话怎么走

1. **说目标**：例如“在驾驶舱加一个现场问题登记面板，数据保存到后端”。
2. **回答关键问题**：谁在哪个页面用、数据从哪来、是否需要保存。
3. **确认方案**：范围、要改的文件、要执行的命令。确认前不要创建或安装。
4. **AI 执行**：改代码、补测试、跑校验；遇到错误基于证据修复，缺接口就说明缺口。
5. **核对结果**：区分“已执行并通过”和“未验证”。

提示词不用写长。推荐三段式：

```text
目标：在驾驶舱加一个现场问题面板，能上报和查看列表。
约束：数据保存到后端，复用现有 issue 接口，不改其他页面。
验收：创建后刷新能读回；缺标题时显示错误；重复提交不产生两条。
```

## 疑问、报错和代码检查

开发过程中，Skill 可以引导 AI 查证可用接口、解释报错，并检查清单、权限、界面副作用和生命周期等约束。已有工程可按[改造已有工程](./40.existing-project.md)先识别结构，再执行确认过的修改和检查；排错过程见[调试与交付](./50.debug-and-deliver.md)。

只问概念时，直接让 AI 解释并指出手册或 API 依据即可，不必启动插件开发流程。当前 Skill 中的代码检查是开发与交付自查，没有独立的代码审核模式；检查清单和测试结果也不能代替人工评审。

## 边界

- AI 不能代替业务验收；模拟事件、Mock 数据和构建成功都不等于真实环境可用。
- 只有在能力目录中声明的接口才能调用，提示词不会让未声明的能力出现。
- 安装、启动常驻服务、访问真实环境和打包，需要分别确认。
- AI 报告“已通过”时，要求它列出实际运行的命令、退出码和未验证项。
