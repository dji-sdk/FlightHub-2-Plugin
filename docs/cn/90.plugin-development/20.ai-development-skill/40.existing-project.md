# 改造已有工程

已有插件不用重建。先让 AI 识别工程结构，再做最小改动。

## 1. 先只读识别

```text
这是我现有的 FH2 插件工作区，用 fh2-plugin-dev 帮我看一下。
先只读检查 AGENTS.md、package.json、锁文件、packages.json 和成员清单，把工程根确认清楚。
这一步别改文件、别装依赖、也别构建。
```

AI 应报告：工程根、Capability 和成员、包管理器、命令执行位置、本地工具来源。

## 2. 修改现有成员

```text
帮我给 issue 面板加个搜索，只搜标题和描述，别动后端接口，现有的组件和状态管理也别换。
先读一遍现在的实现，把要改的文件和要补的测试列给我，我确认了你再改。
```

验收：搜索命中标题和描述；空搜索恢复全部；与现有筛选组合正常。

## 3. 增加成员或 Capability

加成员（前端或后端）：

```text
在现有 Capability 里加一个 Project 前端成员，先展示一个静态列表就行。
先确认目录、ID 和路由会不会冲突、有没有依赖问题，把方案给我。
```

`create` 不会向已有工作区追加成员，按现有目录结构手工新增，然后重新运行 `validate`。

加 Capability：

```text
在现有工作区加一个“设备巡检”的 Capability，跟现有的 Capability 一起交付。
先看看 packages.json、workspace 配置和根脚本，再给方案。
```

新 Capability 需要同步 `packages.json.capabilityIds`、`pnpm-workspace.yaml` 和根脚本，否则不会进入 `dev`、`test`、`pack`。

## 4. 补后端

```text
现场问题列表现在只存在内存里，我要把它存到后端。
先看看现有后端成员和共享契约；排序、分页、唯一键、权限这几件事你拿不准就问我，然后给方案。
```

前端调用使用**后端成员**的清单 ID；共享的输入输出只定义一次。后端测试单独运行。

## 5. 提交前检查

- 工程根和包管理器没变
- 只改了本次涉及的文件
- 新成员能被 `validate` 识别
- 生成物来自源声明，不手改
- 原有测试通过，新增逻辑有测试
- 未执行的服务、打包、部署单独说明

详细写法查[清单参考](../30.detailed-guide/70.api-reference/10.frontend/10.manifest-schema.md)和[扩展点参考](../30.detailed-guide/70.api-reference/10.frontend/30.extension-point-catalog.md)。
