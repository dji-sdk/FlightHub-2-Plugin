# 真实需求示例：现场问题上报

这一页用一个真实的前后端需求说明怎么和 AI 协作：驾驶舱面板上报现场问题，后端保存，刷新后能读回。示例使用工程自带的现场问题能力；如果你的模板还没有该成员，先按[全栈闭环](../10.quick-start/30.fullstack-plugin.md)创建工程。

## 第一句话

```text
我在驾驶舱左侧加一个现场问题面板：能填标题、选严重程度，提交后在面板里看到列表，刷新页面记录还在。
后端就用现有的 issue 接口存，别动其他页面，也别加新的真机调用。
做完帮我验三件事：刷新能读回、不填标题要报错、同一条重复提交不能变成两条。
```

AI 应先确认：

- 面板放在驾驶舱左侧面板还是工具栏？
- 严重程度是固定三档还是可配置？
- 列表是全部问题，还是只看当前项目/当前用户？
- 失败时保留表单还是清空？

## 方案确认

确认范围时，要求 AI 列出：

- 要改的前端文件：清单、入口、契约、挂载、界面。
- 要改的后端文件：`schema.sql`、handler，必要时 `shared/`。
- 要跑的命令：`generate`、`validate`、相关测试、`build`。
- 哪些必须在目标环境验证：真实存储、权限、设备行为。

确认前不要让它直接创建或覆盖文件。

## 实施要求

```text
就按刚才确认的范围改。前端只走 ctx.apiCall 调后端，pluginId 用后端插件的 ID。
后端把必填字段校验住，用业务唯一键去重；失败就返回明确错误，别吞成成功。
补三个测试：成功一个、缺字段一个、重复提交一个。
先在本地跑源码检查和单测，要起 dev 先问我。
最后告诉我改了哪些文件、跑了哪些命令、还有哪些没验。
```

## 验收

| 操作 | 预期 |
| --- | --- |
| 填标题和严重程度，点上报 | 列表出现新记录，状态为待处理 |
| 刷新页面，重新打开面板 | 同一 dev 进程未重置时，记录仍在 |
| 清空标题后上报 | 显示错误提示，不白屏、不显示成功 |
| 用同一业务键重复提交 | 列表不出现第二条 |
| 重启 dev 后刷新 | 回到初始模拟数据；这是本地内存限制 |

## 另外两个短场景

**计划表单增加字段**：

```text
新建和复制计划的时候，加两个字段：“值班人员”和“航线已复核”，缺了就不让提交。
先查一下 plan.form-extensions 在新建、复制、编辑三种模式下分别怎么走，再动手。
做完我要看到：缺项被拦住、填全能保存、不覆盖别的插件字段。
```

**消息中心插入告警卡片**：

```text
在消息中心插一张告警卡片，显示标题、时间和一个“确认处理”按钮。
第一版只做界面，点确认就把卡片关掉；回执要不要接后端，先给我方案，别直接实现。
做完看三件事：卡片能出现、点确认会消失、同一条消息不会开出多张卡。
```

每个需求单独确认、单独验收。不要一次让 AI 把所有场景都加进工程。
